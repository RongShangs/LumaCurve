曲线可调，习惯可记

直接拖动节点或输入数值，保存自己的预设。系统手动锚点记住对应照度的偏好，记忆强度可调、可关闭。

02

双参考，场景化控制

主光感、辅助光感和场景判断继续由 HyperOS 4 处理。APP 将观测、确认照度、曲线与屏幕亮度串起来。

03

接入系统，按事件工作

没有独立的亮度输出 daemon 或 Java broker。保留系统动画，前台按需读取，后台关闭界面连接和动画。

图上编辑 · 命名预设 · 手动记忆

从系统曲线出发。

读取本机四个基础锚点，前三点可编辑，最高照度端保持系统上限。柔和、系统默认、稍亮预设之外，也可保存自己的命名预设。

名义强度范围为系统基准的 10%～200%。可调范围还受本机上下限与相邻节点约束，曲线随照度增加不会下降。

手动调节会在对应照度附近形成记忆锚点。默认沿用系统速度，也可降低强度，让每次记忆的改变量更小。

关闭记忆保留已有锚点。清除、重设基础曲线或系统重置可能重建记忆；不承诺全部记忆跨重启永久保留。

曲线示意

仅演示曲线编辑，不是所有设备的默认值。纵轴为归一化逻辑曲线强度，不代表实际背光比例或肉眼亮度；手机上的坐标和范围以系统读取为准。

双参考：系统决定采用哪一路

沿用 HyperOS 4 的双传感器策略。单侧遮挡、两侧变化与屏幕启停参与系统判断，不固定优先某一侧，也不自行将两个数值平均。

观测值和确认照度可能不同。没有跨过系统门限时，确认值可以继续保持。被遮挡的一侧为 0 lux 可以是有效读数；空白 / -1 才表示没有有效滤波数值。

偏好记忆：保留系统锚点机制

手动亮度操作在当时照度附近形成锚点，可调整 1%～100% 的记忆强度，也可关闭。低强度时连续拖动共享起点，避免同一手势重复累积。

合并间隔可设为 0.5～3 秒，照度分组范围为 ±10%～50%。默认 100% 沿用系统行为；这与旧模块的 14 点渐进学习实现不同。

过渡与暗光稳定

接受新目标后由系统推进亮度过渡。普通亮暗与微小变亮确认时间默认沿用系统，可按需调整接受变化前的等待。

「暗光稳定」默认关闭。适用照度可设 5～100 lux，最短亮暗确认各可设 1～4 秒；默认仍为 50 lux / 3 秒 / 4 秒，保留更长的系统等待。采样窗口不足时沿用原值，不伪造照度、不修改动画；手动、HDR、闲置与驾驶模式保持系统处理。

温控：按需放宽显示层上限

减少温控降亮默认关闭。开启后只作用于已核对的显示层入口；温度未知、电池达到设定阈值或系统严重过热时，继续保留保护。

不改温度数据、Thermal HAL、内核或驱动。硬件、低电量及其他显示策略仍可能限制亮度，不保证永不降亮。

系统更新：重新核对接口

读取固件指纹、主屏和曲线字段。系统更新后旧配置不直接套用，恢复系统基准并提示重新核对。接口不兼容时保留系统亮度控制。

仅介绍 HyperOS 4 适配，不按单个机型锁定；不同固件仍需实际检测。缺少 Root 或 LSPosed 连接时有弹窗提示。

亮度分支：看清是哪一步在变化

状态和日志页均可进入「亮度分支」，查看实际执行的曲线、双侧参考、场景修正、手动保持、记忆模型、夜间唤醒、HDR、阳光增强与输出策略。未观察到的阶段显示「未取得」。

分析包新增最近 24 次曲线计算和 16 次不同输出记录及字段说明，与状态、配置、显示、温控和电池资料一并导出。带进度、保存到手机存储根目录，不自动上传；各资料顺序采集。

轻量架构

复用系统链路，减少独立进程。

Hook 在系统显示线程中按事件工作。APP 前台读取复用 Root 连接，后台关闭连接与动画，无额外常驻亮度输出进程。

没有独立输出 daemon

复用系统显示线程，不运行旧 C 核心与 Java broker。分支追踪只保留有界内存记录，不持续写文件、不增加光感订阅。

界面按需运行

状态刷新可设为 1～5 秒。流动虚线只在状态页面可见时运行，后台关闭刷新连接。

数字以实测为准

当前 APP 的独立内存与 CPU 增量尚待实测；不把整个 system_server 算作应用占用，也不沿用旧模块数字。

安装与兼容

HyperOS 4 · Root · LSPosed

安装 APK

最低 Android 14（API 34）。安装 APP 后，在 LSPosed 启用并勾选系统框架，首次启用或更新 Hook 后重启一次。

移除旧模块

APP 会提示已知旧亮度模块，请在 Root 管理器卸载并重启；旧测试 APP 也应取消 LSPosed 启用。

在设置中应用

允许 Root 后检查连接，修改曲线和参数并保存应用。后续调整无需重启。进入 APP 和关于页自动检查正式 APK 更新。
