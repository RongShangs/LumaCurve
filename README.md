# LumaCurve · 流光亮度

适配 HyperOS 4 的亮度引擎。包含自学习可编辑的亮度曲线，场景感知，平滑调节与手动偏好保持。

**正式版 1.0.0 / 10000** · 模块 ID `luma_curve` · 作者 **酷安@戎Shangs** · 完全开源免费，采用 **GPL-3.0**。

## 它如何调节亮度

LumaCurve 使用原生 C 核心判断环境和计算目标，系统框架代理负责通过 HyperOS 4 显示接口输出亮度。光感输入、算法目标、框架请求和面板反馈分开记录，避免把“请求成功”误当成屏幕已经达到目标。

- **自学习可编辑曲线**：14 个照度锚点，支持长期学习、手动编辑和预设。建议先正常使用，让重复的手动选择逐渐修正曲线；需要精调时，在设置页展开编辑器。
- **双参考场景控制**：正面光感优先，背面提供场景参考。同向变化、单侧变化、遮挡和低照度突亮采用不同确认策略；只有一个光感时退化为单侧处理。
- **平滑调节**：框架代理按时间推进亮度请求，变亮与变暗速度分别可调。滤波和目标确认减少短暂变化引发的来回调节；面板亮度受系统映射与保护限制，不能承诺物理亮度在所有设备上严格线性。
- **手动偏好保持**：自动亮度下移动系统亮度条，会保持用户选择，直到确认明显场景变化或锁屏。在同一照度区间多次同方向调整，才积累附近锚点的学习证据。
- **强光与温控**：持续强光可提高算法目标，硬温控限制优先于手动保持。温度来源区分可信、辅助和不可读；不可读不表示设备温度正常。框架版本不直接写硬件 HBM 节点，最终范围由系统决定。

### 曲线与学习

学习默认开启，也可以关闭。确认的手动操作只缓慢修改附近锚点，不把系统自行调光当成偏好。一次学习有确认时间、最小间隔、单次幅度与累计幅度限制，并保持曲线单调。手动编辑提供更大的自由度，支持保存、切换和删除预设。

手动保持采用相对照度与绝对照度差的联合门槛，并要求变化持续确认；小波动不会立刻撤销用户选择。详见[偏好学习与可编辑曲线](docs/偏好学习与可编辑曲线实施.md)。

## 安装与兼容

需要 **ARM64、Root、HyperOS 4**，以及 KernelSU 兼容的模块安装与 WebUI 桥。KernelSU 分支管理器能否使用，取决于安装环境、WebUI 桥和设备显示接口，不通过管理器名称单独判断。

安装会检查冲突模块，备份设置、学习和预设，识别主屏、亮度范围与框架接口，最后保存兼容报告。检测到冲突模块时，按提示使用音量键选择继续处理或取消。同模块升级先停止旧输出链路并确认释放，失败时恢复数据与原运行状态。

适配不再只根据整份 `framework.jar` 的哈希拒绝不同固件，而是检查接口能力、主屏配置和坐标一致性。**这不代表所有 HyperOS 4 固件已经实测**：系统更新仍可能改变隐藏接口或亮度映射。接口不成立、坐标不可信或持续无法收敛时，模块应交还控制权，而不是继续争抢亮度。安装预检主要只读，不能替代真实亮屏、锁屏和手动调节验收。

首次安装或常规升级后重启；运行中可在设置页暂停、恢复或重启引擎。更新保留配置与学习数据。已经安装同为 `1.0.0 / 10000` 的测试包时，请手动安装本次正式包；相同版本代码不会触发“新版本”提示。

## 界面与排查

**状态页**展示前后光感、已确认输入、平滑照度、曲线、保护状态与当前/目标背光。安卓变化上报型光感可能长期没有新事件，这本身不表示读数失效。“变化确认”表示是否允许接受目标变化，不表示面板已达到目标。

**设置页**顶部是引擎控制和保存操作。曲线始终可见，详细编辑向下展开；建议优先通过日常使用学习。保存操作等待核心确认加载，避免界面显示保存成功却仍运行旧配置。

**日志页**顶部用简明状态块展示引擎、显示控制、光感与兼容情况。最近日志只显示本次开机，默认保留历史日志 3 天。

- **导出日志**：本次开机日志与完整设备状态合并为 `.log`。
- **导出分析包**：包含日志、设备状态、系统版本、显示与光感快照、主屏配置、相关系统框架和资源文件；与设备采集脚本使用同一采集流程。
- 两种导出均保存到**手机共享存储根目录 `/sdcard/`**，附带 SHA-256 校验文件。界面显示读取、采集、压缩和校验进度。分析包可能较大，采集期间不修改亮度，也不自动上传；请仅交给信任的维护者。

运行数据位于 `/data/local/tmp/luma_curve*`，持久备份位于 `/data/adb/luma_curve`。日志和设备状态中的版本、核心构建号、输出后端、请求与实际反馈有助于区分版本混用、未取得控制权和输出失败。

## 资源占用

原生 C 核心负责计算，WebUI 仅打开时运行；框架代理是常驻进程。有限窗口、有界缓冲、传感器批量读取及设置缓存用于降低重复工作。

一组亮屏实测中，C 核心约 **9.4 MiB PSS**，整个模块进程合计约 **65–71 MiB PSS**；60 秒窗口合计 CPU 约 **1.26% 单核**。数据来自一台设备，随状态和固件变化，不代表全天耗电。不能把早期纯 C 版本的“30 MB / 0.02%”套用于当前完整模块，也不能直接相加 RSS 作为总占用。后续优化以保持亮度控制可靠为前提。

## 源码与构建

正式包包含对应核心源码，Release 同时提供完整源码包。构建无需原程序 ELF，需要 Python、Node.js、JDK、Android SDK 的 D8 与 Android NDK；本项目脚本中的工具位置可按环境调整。

```powershell
python tests/verify_project.py
python tools/build_framework_module.py --release
python tools/package_source.py
python tools/sync_website.py
```

统一验证会构建 Java 代理、运行 C/Java 回归和语义负向测试，检查配置与安装回滚、采集导出、WebUI 交互，最后构建当前生产后端。输出：

- `dist/luma_curve-1.0.0.zip`：正式安装包。
- `dist/LumaCurve-1.0.0-source.zip`：完整源码。
- `website/` 及工作目录的 `web/`：可直接部署的静态官网，包含两个下载包、校验和与更新信息。

| 目录 | 用途 |
| --- | --- |
| `csrc/` | 传感器、曲线、滤波、学习、保护与主循环 |
| `experimental/framework_output/` | 当前生产框架输出代理与协议；目录名是开发历史，不表示正式包缺少此后端 |
| `module/` | 安装、服务、升级、导出与 WebUI |
| `tools/` | 构建、验证、打包、采集及官网同步 |
| `tests/` | 主机回归、负向与浏览器测试 |
| `docs/` | 开发说明、审查记录与验证范围 |
| `website/` | 独立静态官网 |

参考原生后端需显式选择，不与当前正式框架后端混用。详细说明见[开发说明](docs/开发说明.md)及[本轮审查与修复记录](docs/审查修复与本地测试包-2026-09-30.md)。本地主机测试不能证明所有固件的硬件行为；系统更新后仍需实机复核。
