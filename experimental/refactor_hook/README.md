# HyperLux 3.1.0 正式版

2026-10-16 · 版本代码 31000 · 构建 release-3.1.0 。

1. 各项亮度功能在引擎启动及打开 APP 时独立检查实际设备接口，区分可用、等待就绪和不支持；系统版本仅保留为诊断信息。启动就绪检查有限复查，不增加光感采样频率。
2. 系统更新后实际曲线基准、控制路径与用户未改变时继续使用原设置，修复界面仍丢弃同基准配置、显示错误默认值的问题。可选功能不兼容时局部暂停，保留原配置。
3. 跨重启保留与亮屏恢复手动记忆默认关闭，旧配置缺少字段时不再自动开启。已明确保存为开启的配置仍保留，需要关闭并保存一次；不自动清除现有手动点或存档。
4. 暗光锁定改为“手动调整后退出锁定”，默认关闭。默认手动调整后以新亮度继续锁定，满足退出条件后恢复自动亮度；打开开关才退出并维持手动模式。
5. “节点高亮兼容（Beta）”更名为“强制达到节点上限”，新增独立的“增强目标节点”滑动杆。读取唯一主屏节点的实际 max_brightness，默认最高；未读到真实上限时禁用，不使用机型或 nit 映射猜测节点范围。
6. 节点目标按原始节点值设置，与常规户外增强强度独立。移除原先单独的 30 秒时限，完全跟随户外增强会话剩余时间和冷却设置。旧 Beta 配置缺少目标值时默认当前设备上限。

节点增强默认关闭，需要开启户外增强、高亮范围与画面限亮放宽，并取消 nit 上限。仅在全强度照度、普通自动亮度输出到顶、当前设备和保护条件都满足时提高节点；目标低于系统当前值时沿用系统输出。照度跌破全强度阈值、屏幕或保护条件变化时退出，系统重新下调节点后退让。

增强节点值不是 nit，不承诺特定面板亮度；当前 APP 仍显示系统换算亮度。启用该选项时运行可选 Root 守护，关闭后停止。短期授权只处理失联退出，不是额外的增强时间限制。

沿用原包名及签名，可覆盖此前正式版和 Beta；安装后重启一次。原正式版及两个 Beta 文件保留。本版同步发布至 GitHub、LSPosed 模块仓库与官网。

已完成完整主机回归、固件静态检查、编译、原签名与源码/恢复归档核验；数量见 build-info.json。本版尚未进行真机亮度、驱动保护行为或功耗实测。

# HyperLux 2.3.1 · 正式版

适配 HyperOS 4 的 Root + LSPosed 自动亮度工具。构建 release-2.3.1，版本代码 23106；沿用包名、图标与签名。安装后重启一次，启用 LSPosed 系统框架作用域，再保存并应用。

自动曲线、双参考、场景和过渡复用 system_server。「强光优先」将全强度自动目标提高至本机映射上限、开放已验证的 HBM / 峰值 / 动态范围；支持时提前触发 HBM，保留原时间预算。支持时可选放宽强光 SDR 的画面灰阶限亮，继续执行温控、省电、HDR 与驱动限制，不保证达到手动节点直写的实际亮度。进入、退出及超时即时请求系统重算，不等待新光感事件。

主屏磁贴打开独立弹窗，自动识别明确的主屏节点并直接调节，完整使用本机 max_brightness；按相对距离拖动，也可输入整数或选节点最大值。仅打开不接管，实际操作后关闭自动亮度，关闭弹窗继续保持。锁屏 / AOD 暂停释放，正常解锁恢复；开启自动、切换用户、故障或停用取消目标。系统进程重启不恢复高亮。

手动保持期间才运行小型 ARM64 C 守护，以单调时钟每 2 秒发布健康记录，超过 5 秒未更新时系统停止隔离输出并退让；先开句柄再锁权限、复用句柄、仅被覆盖时补写。匹配已确认接管的主屏正值输出才隔离，零值、息屏 / AOD 和唤醒首帧交给系统。全流程排除副屏节点、不改屏幕超时 / 唤醒设置，不使用唤醒锁。节点值不是 nit，不写超范围值。

弹窗信息卡、滑条和操作栏统一对齐，深浅色独立配色；背景模糊与渐显按系统能力运行，大字体或横屏时内部可滚动。磁贴显示真实接管与解锁恢复状态，关闭面板停止界面 Root 查询。

暗光定时锁定的新配置默认开启：主辅照度不超过 10 lux 持续 1 分钟后关闭本次自动亮度、保持当前值，系统进程继续低频监听；任一侧达到 50 lux 持续 1 秒后恢复自动。锁屏退出，不打开用户主动关闭的自动亮度。已有设置保留，可点击“睡前保持”应用新默认值。该功能不需要 C 守护。

保存确认不会覆盖等待期间的新草稿；暗光锁定转手动失败或接管确认丢失时，按原自动亮度所有权与当前会话回滚。

详见 [正式更新](../../docs/releases/2.3.1.md)和 [审阅记录](../../docs/review-2.3.1.md)。主机与固件检查不等于本版 Android 全设备实测。异常先在面板恢复自动，或 APP 停用并恢复；完整包解压后 Root 终端执行：

    sh ./restore_refactor_hook_android.sh

恢复工具先停止守护并恢复节点权限，再停用 Hook。APK、源码、恢复合集在 dist/，静态官网在 website/，部署副本在 D:/IOS/web。

构建：python tools/build_refactor_hook_test.py；没有私有固件资料时加 --skip-device-fixtures。需要 JDK 17、SDK 37、NDK 28.2.13676358 和 Xposed API 82。源码不包含签名私钥或采集固件。主屏界面参考本地 bright 项目的相对滑动、弹窗和磁贴行为；节点保持采用自己的事务和租约实现。
