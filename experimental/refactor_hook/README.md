# HyperLux 2.0.2 · 正式版

正式版，构建 `release-2.0.2-r1`，版本代码 `20002`。可覆盖此前的同签名版本，旧版会提示 2.0.2 更新。同包名、同签名覆盖安装后，在 LSPosed 保持「系统框架」作用域并重启一次。APK 为 `HyperLux-2.0.2.apk`，对应源码与恢复合集沿用 `LumaCurve-` 命名。

## 更新内容

- **感谢名单在线同步**：APP 关于页与官网使用同一份名单，进入关于页自动刷新；断网时显示已保存的名单。新增 *意、*弎、Albert_L。打赏提示改为尽快更新到名单，微信与支付宝二维码下方均提醒备注「昵称：想说的话」。
- **日志自动滚动**：刷新左侧新增小开关，默认开启，持续跟随最新记录；关闭后保留阅读位置，选项保存在本机。
- **完整分析包**：按需采集运行状态、配置、日志、曲线与输出追踪、显示/光感/唤醒/温控/电池、资源覆盖、显示配置与相关系统/小米框架文件。显示八步进度，保存到手机内部存储根目录。附命令结果、缺失项、超时及文件校验清单；完成 ZIP 校验后才提示成功，不自动上传。
- **状态入口归位**：曲线、输出与 HDR 分支摘要移入当前曲线卡片，预留独立区域，使用浅蓝背景；融合区域只展示融合照度，亮暗阈值继续紧贴虚线左右两侧。
- **暗光稳定参数**：新增适用照度 5～100 lux、最短变亮/变暗确认时间各 1～4 秒。默认仍关闭，开启后的默认值保持 50 lux / 3 秒 / 4 秒；保留更长系统等待，并继续核对采样窗口。参数对主、辅助光感均生效。
- **官网与发行资料**：更新首页版本与更新日志、APK、对应源码、恢复工具和在线更新信息。

## 基础功能

适配 HyperOS 4 的自动亮度工具。以系统双侧感光与场景判定为基础，提供可编辑曲线、预设与手动偏好记忆；保留系统平滑过渡，并可按需调整温控和变化确认时间。正式版本号 `2.0.2`，版本代码 `20002`；显示名称改为 HyperLux，包名 `top.rongshangs.lumacurve`、图标、官网和仓库保持原有约定，APK 文件名更新为 `HyperLux-2.0.2.apk`。本次构建标识 `release-2.0.2-r1`。

这是一款 Root + LSPosed 应用。曲线接入原有 system_server 显示线程，继续使用系统传感器处理、场景判定与过渡动画，没有独立亮度输出 daemon 或 Java broker。不再使用旧 KSU 模块的背光输出路径。

## 安装与升级

1. 安装 `HyperLux-2.0.2.apk`。与 APP test03 包名、签名相同，可直接覆盖安装，保留已保存的设置与本地预设。桌面图标为原来的蓝色曲线图标，应用名称为 HyperLux。
2. LSPosed 启用 HyperLux，作用域只选择「系统框架 / Android 系统」，**更新 APK 后重启一次**，使 system_server 加载新版 Hook。
3. 如仍安装旧包名 `top.rongshangs.lumacurve.refactor.test` 的测试 APP，先关闭它的 LSPosed 开关，避免同时接入。首次 Root 读取尝试迁移旧应用的命名预设。
4. 进入应用并授予 Root。权限不足、系统仍运行旧 Hook、接口尚未兼容，均有对应提示。进入设置页自动读取当前配置；修改后点击「保存并应用」。之后调曲线与参数不用重启。

第一次应用会尝试恢复此前的标准曲线测试，并暂停由本应用识别的旧 KSU 亮度引擎；停用时只解除由本应用创建的暂停。不要同时运行两个亮度控制实现。

APP 运行时读取 `/data/adb/modules` 与 `/data/adb/modules_update`，检测 `luma_curve`、`luma_curve_official_test`、`ios_auto_brightness`，提示到 Root 管理器卸载旧模块并重启。已停用与待更新的模块也会提示，同一组旧模块在本次 APP 运行中不会反复弹窗；已标记卸载的目录跳过。检测不删除或修改文件，不泛查其他亮度模块。

## 页面与交互

- **状态**：一张固定流程板，主光感与辅助光感 → 融合滤波与场景判定 → 当前曲线 → 温控 → 当前屏幕亮度。两路虚线各自从传感器流向中心，再向下连接。变暗与变亮阈值分别紧贴中间连线左右两侧。曲线只显示蓝色实际曲线，包括系统现有的手动记忆锚点；无曲线标题、图例或多段解释。温控左右分栏显示当前策略、电池温度和系统热状态。详细读数移到日志页。缺失传感器读数显示「—」，不会补成零。
- **设置**：保存与停用放在顶部。曲线节点可直接拖动，也可点击输入数字；保留柔和、系统默认、稍亮与自定义命名预设。最高照度端沿用系统上限，前三点名义强度范围 10%～200%，实际范围受本机上下限及相邻节点约束；不允许亮度随照度增加而降低。
- **日志**：页面外层固定，兼容概览、详细读数及导出操作始终可见，只有记录窗口内部滚动。本次系统进程最近 160 条记录带时间戳。刷新左侧的自动滚动默认开启，关闭后保留阅读位置。导出分析包有进度提示，保存到 `/sdcard/` 根目录，包含日志、配置、曲线、设备、显示链路、温控及固件信息。
- **关于**：无顶栏，左侧圆角原图标、HyperLux 名称、2.0.2 与简介；官网/仓库/协议下方是交流群，随后为打赏、感谢名单，作者信息位于最底部。进入页面自动检查更新，无需检查按钮。群号与暗号位于同一容器，复制仅含 `314981836`；暗号 `1691` 不写入剪贴板。作者头像带圆角。感谢名单从官网读取并保留离线缓存。详见根目录 README 的名单维护说明。

底栏四项图标与文字均居中，无页面返回历史。按钮无阴影，水波限制在圆角范围内。所有弹窗居中、带圆角，打开时仅渐显，不缩放或移动；关闭系统动画时也关闭渐显。界面跟随系统语言，中文系统显示中文，其他语言显示英文；用户留言与原始诊断字段保持原文。

## 可调参数

| 参数 | 范围与默认行为 |
| --- | --- |
| 基础亮度曲线 | 三个可调节点 + 系统最高照度端，图上编辑与命名预设 |
| 手动偏好记忆 | 可关闭；记忆强度 1%～100%，默认 100% 沿用系统速度 |
| 连续调节合并间隔 | 0.5～3 秒，默认 1.5 秒；同一手势的回调共享起点，避免重复累积 |
| 记忆照度范围 | ±10%～50%，默认 ±30%；暗处至少 5 lux 容差 |
| 减少温控降亮 | 默认关闭；电池阈值 38～45℃，默认 43℃ |
| 温控冷却幅度 | 1～3℃，默认 1℃；冷却到阈值减去该幅度再恢复减少降亮 |
| 变化确认时间 | 默认关闭，沿用系统；变亮 0.5～10 秒，变暗 1～15 秒 |
| 微小变亮确认时间 | 独立开关，默认关闭；0.5～15 秒，调节系统的小幅变亮等待时间 |
| 暗光稳定 | 默认关闭；适用照度 5～100 lux，最短亮暗确认各 1～4 秒；默认 50 lux / 3 秒 / 4 秒，保留系统更长等待 |
| 状态刷新 | 1～5 秒，默认 2 秒；只影响前台显示 |

手动偏好通过小米 Refactor 锚点机制实现，在当前照度附近记住手动亮度。低强度以手势起点插值，一次滑动的回调不会反复累积成全量调整；合并间隔与照度范围控制哪些操作属于同一次调整。关闭后不再添加新锚点，已有记忆保留。更换基础曲线、显式清除或停用会重建锚点，系统也可能自行重置；不承诺跨重启长期保存全部学习数据。

变化确认时间只调整系统变亮/变暗候选持续时间，保留其采样时间、滤波、变化阈值及额外分段延迟。微小变亮使用独立开关与等待时间，未开启时保持系统小幅变化策略；闲置与驾驶模式保持系统策略。不兼容的固件禁用相应选项；接口异常时返回原系统结果。详细读数的 `response_adjustments` 和 `small_response_adjustments` 记录实际调整次数，用于确认固件是否执行了这些 Hook。已核对提供的固件方法体，新增暗光稳定选项与分支界面尚待更多实机验证，暗光稳定默认关闭。

温控选项仅作用于已验证的显示层入口，在原调用期间暂时移除显示温控上限，结束即恢复字段。严重过热、温度未知或电池达到阈值时保留系统策略；不修改 Thermal HAL、内核、驱动或温度数据。硬件、低电量及其他显示限制仍可能降亮。

## 系统更新与应用更新

继续检测固件 fingerprint。系统更新后不继续使用旧曲线配置，恢复系统基准并提示重新核对兼容性、保存应用；不依赖某一机型的固件文件哈希。实际适配仍取决于显示接口是否兼容，仅支持主用户与主屏。

进入 APP 和每次进入关于页，自动检查原仓库 `RongShangs/LumaCurve` 的最新正式 Release，发现更高版本弹窗。只接受该 Release 的 `HyperLux-版本.apk`（兼容旧 `LumaCurve-版本.apk` 命名），忽略预发布和旧 KSU ZIP，不把模块升级包当成 APP。网络失败不影响亮度控制。后续在原仓库上传 `v2.x.x` 对应 APK 即可延续更新；本地构建不会自动发布远端 Release。

## 恢复

设置 →「停用并恢复」会等待系统确认。Root 或系统连接丢失时保存关闭请求，重启后再确认恢复。也可在 LSPosed 取消勾选并重启，移除内存 Hook。若有由本应用暂停的旧 KSU 引擎，须另外确认解除该暂停。

完整包包含恢复脚本与辅助 jar。解压到同一目录，在该目录执行：

```sh
su
sh ./restore_refactor_hook_android.sh
```

`LumaCurve-2.0.2.zip` 是 APK、源码和恢复工具的合集，**不是 KSU 刷入模块**。无需替换 framework/services.jar。

## 本地验证与构建

用户已确认此前 APP 的曲线接入效果有效。本版保留相同的核心插值、字段适配与回滚实现；新增参数有独立边界、手势分组、温控滞回、确认时间和更新匹配测试。625 项主机逻辑检查及 23 项名单/采集检查通过，包括旧模块检测的 UTF-8 名称、重复目录、停用、待更新、卸载标记与只读行为；核对提供的固件消费链、传感器字段、温控、手动锚点及确认时间方法体。APK 编译、签名、对齐与归档均检查。当前没有连接手机或模拟器，新布局与新增参数尚待实机确认，不把本地检查称为实机验证。

构建：`python tools/build_refactor_hook_test.py`，JDK 17 / Android SDK 37 / Xposed API 82，minSdk 34。没有私有固件反汇编时可加 `--skip-device-fixtures`，仍保留运行时接口检查。源码包附 GPL-3.0，不包含固件、采集包、编译依赖或签名私钥。本版沿用此前 APK 的签名以支持覆盖升级；自行重建会生成另一份本地签名。

关于性能：Hook 在系统显示线程按事件运行，前台读取状态复用 Root 连接，后台关闭连接；流动虚线仅在状态页可见且自动亮度启用时刷新。新增实际内存与 CPU 增量尚待本版实测。
