# HyperLux 2.4.0 · LSP 分支

适配 HyperOS 4 的 Root + LSPosed 自动亮度工具。构建 `release-2.4.0-lsp.2`，版本代码 24000；沿用包名与图标。安装后重启一次，启用 LSPosed 系统框架作用域，再保存并应用。

本分支还提供系统深浅模式跟随、可选背景图片和左右滑动切页。底部 Dock 按 KernelSU 发货版逆向参数重做为 64dp 高、4dp 圆角宽条，左右留白 28dp，底部间距按手势导航 inset 计算；4dp 模糊、24dp 面板折射、40dp 采样外扩、按压指示器透镜与双向流动高光均集中在 `GlassDockView`。页面卡片和输入控件使用普通主题色填充，液态玻璃只用于 Dock。API 33+ 使用缓存的 AGSL 镜头，API 31–32 使用系统模糊与饱和度，API 31 以下为高对比纯色回退；本 APK 的 minSdk 为 34，因此低版本分支仅作源码兼容，未包含在当前可安装范围。实际渲染、功耗和流畅度仍需在目标设备上验证。

自动曲线、双参考、场景和过渡复用 system_server。「强光优先」将全强度自动目标提高至本机映射上限、开放已验证的 HBM / 峰值 / 动态范围；支持时提前触发 HBM，保留原时间预算。支持时可选放宽强光 SDR 的画面灰阶限亮，继续执行温控、省电、HDR 与驱动限制，不保证达到手动节点直写的实际亮度。进入、退出及超时即时请求系统重算，不等待新光感事件。

主屏磁贴打开独立弹窗，自动识别明确的主屏节点并直接调节，完整使用本机 max_brightness；按相对距离拖动，也可输入整数或选节点最大值。仅打开不接管，实际操作后关闭自动亮度，关闭弹窗继续保持。锁屏 / AOD 暂停释放，正常解锁恢复；开启自动、切换用户、故障或停用取消目标。系统进程重启不恢复高亮。

手动保持期间才运行小型 ARM64 C 守护，以单调时钟每 2 秒发布健康记录，超过 5 秒未更新时系统停止隔离输出并退让；先开句柄再锁权限、复用句柄、仅被覆盖时补写。匹配已确认接管的主屏正值输出才隔离，零值、息屏 / AOD 和唤醒首帧交给系统。全流程排除副屏节点、不改屏幕超时 / 唤醒设置，不使用唤醒锁。节点值不是 nit，不写超范围值。

弹窗信息卡、滑条和操作栏统一对齐，深浅色独立配色；背景模糊与渐显按系统能力运行，大字体或横屏时内部可滚动。磁贴显示真实接管与解锁恢复状态，关闭面板停止界面 Root 查询。

暗光定时锁定的新配置默认开启：主辅照度不超过 10 lux 持续 1 分钟后关闭本次自动亮度、保持当前值，系统进程继续低频监听；任一侧达到 50 lux 持续 1 秒后恢复自动。锁屏退出，不打开用户主动关闭的自动亮度。已有设置保留，可点击“睡前保持”应用新默认值。该功能不需要 C 守护。

保存确认不会覆盖等待期间的新草稿；暗光锁定转手动失败或接管确认丢失时，按原自动亮度所有权与当前会话回滚。

详见 [2.4.0 正式更新](../../docs/releases/2.4.0.md)。主机与固件检查不等于本版 Android 全设备实测。异常先在面板恢复自动，或 APP 停用并恢复；完整包解压后 Root 终端执行：

    sh ./restore_refactor_hook_android.sh

恢复工具先停止守护并恢复节点权限，再停用 Hook。APK、源码、恢复合集在 dist/，静态官网在 website/，部署副本在 D:/IOS/web。

构建：python tools/build_refactor_hook_test.py；没有私有固件资料时加 --skip-device-fixtures。需要 JDK 17、SDK 37、NDK 28.2.13676358 和 Xposed API 82。源码不包含签名私钥或采集固件。主屏界面参考本地 bright 项目的相对滑动、弹窗和磁贴行为；节点保持采用自己的事务和租约实现。
