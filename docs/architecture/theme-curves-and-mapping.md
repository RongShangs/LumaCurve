# 深色曲线、系统默认恢复与控制中心映射

当前主题记忆规则已由 [主题记忆与屏幕读回](theme-memory-and-readback.md) 更新：4.3.0 Beta 01 提供清除、共用和独立记忆，以下固定清除规则仅记录原实现。

2026-10-27，4.2.0 Beta 01之后的源码变更；本轮未要求新包，不改变既有发行标识或交付文件。

## 深浅色曲线

- 普通`factors`、`curve_floor_nit`、`saved_base_curve`保持原语义。新增可选`dark_mode_curve`对象，内部独立`enabled`、`factors`、`curve_floor_nit`及`保存曲线`；缺键默认关闭。第一次启用从当前普通基础草稿起步，分别编辑；关闭后保留深色草稿。
- 两条曲线均沿用当前设备选出的Refactor/传统后端及其完整节点、SavedCurve约束，不新增按型号或OS版本选路的分支；同设备导入导出保留双曲线，异设备导入保留当前本机双曲线。
- 亮度引擎读取系统Configuration.uiMode；复用现有显示Handler广播与配置刷新，不运行周期主题探测、不增加进程。只在启用后根据实际系统主题选择曲线；APP显示主题不作为引擎依据。
- 主题实际切换时，先验证目标曲线，再取消待保存/恢复并清除当前和归档手动记忆，之后应用目标曲线、更新保持选项，并再次取消本次配置建立的旧恢复任务。数值相同也清除；永久保持不例外。
- 归档作用域增加已启用的light/dark后缀；未启用沿用原作用域，旧安装不变。首次启动可以恢复同一主题的存档，不把另一主题的存档带入。
- 状态曲线下方明确显示“深色模式基础曲线”，可直接跳到对应编辑区域。深色状态下保存绿色曲线只更新深色基础，普通基础不变；保存过程中主题变化则拒绝旧图转存。

## 恢复系统默认

- 原停止命令仍保留以兼容旧调用；设置按钮改为新的`restore-defaults`，执行前显示范围确认。
- 取消本模块的原生临时接管和控制中心映射，提交disabled配置及唯一reset_anchors，等待当前引擎确认已恢复官方曲线/保护且清除手动记忆。
- 只有成功后才重置APP亮度草稿，移除旧draft缓存；保留自定义预设、语言/刷新偏好、图标状态和教程记录。离线或未确认不假报成功，不提前清理本地草稿。
- 不恢复此前暂停的过时第三方亮度模块，以免“系统默认”又落到另一套控制器上；不修改用户主动关闭自动亮度的选择，仅按现有所有权标记释放本模块的接管。

## 控制中心映射

- 恢复主屏手动亮度页与搜索入口，保留原key和0关闭/1仅手动/2手动及自动三种取值，默认0。
- 原coordinate_v2及普通gamma、OEM V1转换路径保留；严格单调反解失败仅暂停映射，不造假采样、不旁路系统开放范围。
- 输入与回显仅转换UI坐标，自动模式不会被主动关闭。暗光锁定/名单暂停/主屏面板仍由原控制器管理；锁定中拖动按manual_exit设置继续锁定新值或退出，不为映射另设所有者或输出线程。
- 转换表补充enabled/revision/user_serial，Root与SystemUI均检查；停用、用户变化和故障异步撤销表，过期代次不继续映射。进程/boot、节点身份、主屏与UI ABI校验继续存在。
- 能力消失只暂停运行副本；用户保存其他设置时允许原样保留暂不可用的映射选择及节点身份，不能借此新增未经验证的启用。

## 验证边界

对应主机回归执行生产配置类型、实际主题交接代码段、默认恢复命令、记忆持久化、绿色转存事务及控制中心Hook；完整生产Java编译和主线verify-only另行记录。主机模型和静态固件核对不代表Android真机或功耗实测。本轮未安装设备、未发布。
