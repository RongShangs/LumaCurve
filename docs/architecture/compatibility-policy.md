# 兼容开发规范

适用于所有后续功能、兼容修复、重构、打包和发布；根 [PROJECT.md](../../PROJECT.md) 的需求与最高要求优先。本规范是必须遵守的维护契约，不是临时建议。

## 一、不可破坏的要求

1. **新增兼容保留旧路径；覆盖更新保留已保存设置。** 不删除旧路线来适配新机型，不因能力缺失、重新自检或启动失败回写默认。能力恢复后应能重新使用原偏好。
2. 按实际类、加载器、对象、签名、字段类型、配置形状及运行条件判定；不以系统版本、设备型号或指纹字符串直接放行 / 禁用功能。指纹和基准用于配置安全隔离，不是兼容白名单。
3. 区分互斥路径和组合组件。Refactor / 两类传统映射、两类 SDR / 目标入口互斥；HBM 控制器与时间策略是两个维度；动态范围是可选补充。
4. 只有**确实不存在**优先接口且旧 ABI 完整时才能选择备用结构。接口存在但类型错、部分移植、访问或调用失败，不得降级绕开原生保护。
5. 保留主屏、用户、HDR、手动接管、系统场景、严重温控、电量及实际 HBM 允许条件。不能在通用工具函数中偷偷放宽所有功能的条件。

## 二、放代码的位置

| 变更 | 应放位置 | 不允许的捷径 |
| --- | --- | --- |
| 新字段 / 签名 / 旧结构兼容 | 对应功能适配器，复杂新结构可拆独立 Access / Profile | 在页面、Root 命令及回调里各写一遍猜测 |
| 路线名称、稳定 ID、简要条件 | CompatibilityCatalog | 在多个界面维护不同的路线列表 |
| 选择、清理、证据与测试责任 | compatibility-manifest.json | 只改代码不登记，或写“兼容所有机型”代替条件 |
| 触发、持续与退出 | 现有控制器 | 为一个新机型复制整套状态机 |
| 数值计算和约束 | Policy / Options | 将默认值或魔法数散在各回调 |
| UI 展示 | 页面和 FeatureCompatibility | 为了展示“可用”而主动试写节点或切换路线 |

常量可以表达已验证 ABI 和安全界限，例如数组形状、确认窗口、协议范围；不能用未知固定上限代替读取设备真实上限。未知布局只暂停对应功能。

## 三、适配记录必须包含什么

每项兼容至少登记：稳定功能 ID 与路线 ID、父功能 / 内部 ABI 变体、负责类、完整探测条件、拒绝条件、优先顺序、是否可与其他组件并用、调用线程、对象与用户归属、配置和坐标单位、状态证据、停止及异常回滚、旧 / 新 / 负向验证。

使用 [记录模板](compatibility-change-template.md) 说明新旧差别。型号和系统版本只作为复现样本背景，不能直接成为选择器。涉及私有固件的原文件和分析包留在忽略目录，只在公开记录里写必要的接口事实。

## 四、安装事务与运行回滚

- 安装前尽量完成必需反射校验；多 Hook 单元使用 `try (HookTransaction tx = new HookTransaction())`，安装句柄加入事务，成功后才发布能力并 `commit()`。
- 子事务需要纳入上层回滚时用 `commitTo(parentHandles)`；不能在 catch 后保留已经安装一半的回调。
- 回滚逆序执行，一个 unhook 异常不阻止其他句柄撤销；失败必须记日志，不能报告成功清理。
- 可选观测失败只失去该观测，不能顺带删除目标增强、曲线等已提交核心。支持缓存 / profile 不得在失败后假装可用。
- 临时字段和 ThreadLocal 按调用成对恢复，含原生异常；持续修改记录原对象和本次应用值。只有当前仍是本次值时才恢复，系统或其他所有者已替换则不覆盖。
- 同一功能 / 同一实际类和加载器避免重复安装。缓存以实际 Class 或实例为键，不能只按字符串类名把不同加载器的对象混在一起。

现存已有安装器可逐组迁移到统一事务，但必须保留对应失败回滚测试，不能为“统一”一次性改动所有成熟 Hook。此次 Refactor 与户外核心已先落地该方式。

## 五、状态报告不能混淆的四层含义

1. **接口支持**：必需接口与实际对象通过检查。
2. **路线采用**：已取得本次实际 profile / 绑定等证据；未上报不能推测。
3. **用户启用**：保存的功能偏好，独立于当前设备是否支持。
4. **当前生效**：当前场景满足、控制权允许，且存在对应运行结果。

`available` 不等于功能已经开启或效果已验证。`pending` 表示未就绪；`inactive` 表示 OEM 未启用；`unsupported` 表示已确认接口不完整；路线 `unconfirmed` 表示报告证据不足。低光真实 0 lux 不是缺采样；记录缺字段不等于开关为 false。

自检只消费已安装能力和真实对象，不在查看页面时重复安装 Hook、试写、切模式或周期巡检。APP、Root、引擎记录各自固定完成时间与请求来源；打开 / 展开页面只读。待就绪有限补检，明确主动重检保留。

## 六、配置与升级

用户原始配置、APP 草稿 / 本地偏好、运行裁剪副本分开。保持原包名、签名、schema 的可读性及原键含义；新键默认不擅自激活。改键需要明确迁移及旧值优先顺序，不得“迁移”成重置。

配置的基准、用户、物理背光 / nit / 逻辑 nit 坐标必须核验；不能跨机型直接复用曲线。临时不支持可以将本次副本禁用，但持久化的列表、保持范围、增强参数和用户曲线仍留着。预设也不得覆写用户未要求改变的独立上限。

## 七、最小验证矩阵

| 情况 | 必须确认 |
| --- | --- |
| 原设备 / 原 ABI | 原路线仍可选择，原输出和保护保持 |
| 新 ABI | 新路线按实际条件单独工作 |
| 同时存在新旧接口 | 优先顺序确定，不能双重增强 |
| 新式接口缺部分 / 返回类型或静态性错误 | 拒绝残缺结构，不盲目回退 |
| 原方法抛错 / 数据暂缺 | 对应功能停止或等待，不绕开保护 |
| 安装到一半失败 | 必需组回滚、无残留半套 Hook、支持状态不造假 |
| 可选观测安装失败 | 核心仍正常，独立功能失败不互相拖累 |
| 两个实例 / 同名不同加载器 | 状态和缓存隔离，不串控制权 |
| 熄屏、解锁、用户 / 对象变化、停用 | 清理及时，只恢复自己所有的值 |
| 覆盖更新 / 能力消失后恢复 | 保存的设置、名单、曲线、保持范围完整 |

分别记录主机模型、实际固件静态核对、Android 真机、长测和功耗。静态接口匹配或主机回归不能写成所有机型已测；本轮不新增功耗改善宣传。

## 八、变更交付门槛

补齐登记 → 生成索引 → 维护契约检查 → 对应旧 / 新 / 负向回归 → 完整只验证构建 → 记录风险及验证级别。主线构建已接入这套检查；CI 检查注册与文档不漂移。自动检查不能证明语义正确，审阅仍须检查真实消费者和保护顺序。

仅修改文档无需重打 APK。用户要求打包时才生成新的可区分交付；不能悄悄替换以前交付的相同文件。发布需要用户授权，并同步官网下载、源码 / 完整包、SHA-256、更新 JSON / JS 及 GitHub / LSPosed。私有分析包、固件、签名和服务器认证不得进入任何公开产物。

## 九、Root权限与接口适配分离

Root管理器名称 / 模式不代表全权限；LSPosed注入、设置桥、诊断、操作目录和原生节点各自按实际访问结果判断。设置桥保留原Provider优先，读取探测失败可用系统命令的同权限入口，仍经同一系统服务鉴权；禁止写失败后多路重放、绕开SELinux / 内核限制或跳过进程身份检查。只读可用不等于写入确认。可选Root工具失败不回滚已ACK的核心曲线；不能假报已恢复原生守护。自检不试写，权限缺失不覆盖任何用户配置，APP不完整诊断须明确不是实时系统日志。

## 十、共享清理机制

新临时字段优先使用FieldOverride，恢复前比较本次应用值，系统或其他所有者改写后不覆盖；多字段逆序清理。Hook失败撤销统一使用HookTransaction.rollbackAll或事务close，单项错误和日志错误不阻断其余清理；真实撤销失败的句柄必须保留再次尝试能力，不先标记为已完成。迁移既有安装器时保留其ABI检查、优先顺序、能力发布时间及失败回归，不为统一而重写所有成熟控制逻辑。
