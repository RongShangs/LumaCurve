# 主题记忆与屏幕读回

2026-10-29，4.3.0 Beta 01。补充并更新 theme-curves-and-mapping.md 中原来固定清除主题记忆的约定。

## 配置与默认值

`memory_hold_theme` 为独立保持范围，缺键 false。`dark_mode_curve.memory_mode` 为 0 清除、1 共用、2 独立，缺键 0；原独立基础开关和所有曲线键保留。独立基础开启时运行副本由 memory_mode 决定是否需要主题交接，持久化的 memory_hold_theme 不回写。

实际主题来自系统 Configuration.uiMode，与 APP 界面语言/本地主题无关。由现有广播和配置刷新驱动，不增加定时主题探测。目标曲线验证成功后才交接记忆，显示 Handler 串行执行；新手势始终优先，重建模型的回调不在自身读取栈内重放。

## 交接与隔离

MemoryPersistence 负责原生模型快照、排队/取消、恢复及存档；ThemeMemoryStore 仅管理有界的会话银行、键与显式共用转接。共同沿用原 Refactor/传统映射后端和本机模型容量，不另建虚拟插值引擎。

独立记忆使用 `:independent-light` / `:independent-dark` 的曲线身份，存档键为原 PersistentMemory.KEY 加 `_light` / `_dark`。设备、用户、基础曲线共同构成身份，原有非独立存档键和清除模式的旧作用域保持。新基础曲线使当前旧银行失效；另一主题不受影响。

仅开启重启保持才读取/写入磁盘，不能因为发现旧文件而恢复。普通主题保持仅使用当前运行缓存；锁屏、模式保持仍由各自开关决定。清除当前记忆只清当前银行；恢复系统默认清全部银行。模型在切换完成后才重放，短窗口内接收 OEM 的晚到重置；不会永久阻止系统重判。

UI 仅展示当前主题的实时曲线/节点。转存基础沿用既有 promote-memory 事务并校验捕获主题；清除命令也带捕获主题，晚到请求不清另一份记忆。

## 屏幕读数

ScreenBrightnessReading 集中处理只读标定与读回。实际主屏发现继续由 ActivePanelNode / PanelNodeDiscovery 负责。直接控制时，读取失败首先撤下框架旧 nit；可读实际节点则按本机标定换算，无法验证则显示节点。请求目标与守护目标都不是读回值。

标定由现有 ControlCenterEngine 校准线程采样原生 getNitsFromBacklight，验证浮点轴、数值单调、同一配置对象和前后物理身份；不探写、不外推。APP 状态刷新才在现有 Root 辅助链读取节点，不增加进程、采样或后台刷新频率。Root 读数失败和 LSP 核心控制解耦。

新增观测只组合既有兼容路线；具体 ABI 分支记录在 compatibility-manifest.json 的 screen_brightness_readback，源码归属见 source-map.json。保留正式版所有路线及缺省配置行为。

## 最高照度点

从固定 100% 放宽到可下调；上界仍是编辑基准自身 100%，下界不低于相邻点且不低于原因子范围。Refactor 和传统后端同步验证，传统与已保存基础保留全部节点，不能以四点直线替换本机密集曲线。

旧式 Refactor 系数路线使用实际验证的 calculateBrt 方法和三组原生系数数组；仅显式下调最高点后，将这些实际数组的计算域止于设备原最高照度点，形成下降后的终端平台。其他数组、原始100%配置、线程或用户不匹配均不改写输入。此处只限制曲线计算域，不篡改光感值或最终输出保护。该路线相邻点必须严格递增，编辑器随实际后端收窄边界，避免零斜率拟合。

## Beta 03：矛盾的驱动零值

亮屏、同设备寄存器为正、未报告背光关闭，并且独立框架实际输出为正时，actual_brightness的0作为矛盾信息保留但不采用。常规输出优先原框架值；直接节点保持原读回换算路线。真实关闭、无矛盾证明的0和有效正驱动值保留。状态带驱动值、寄存器值、框架原nit及回退原因，不存在按机型硬编码或从目标亮度推断实际亮度。
