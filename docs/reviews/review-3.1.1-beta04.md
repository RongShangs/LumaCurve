# 3.1.1 Beta 04 复审

## 需求与范围

将跨自动亮度开关、锁屏、重启的保留策略统一到“保持记忆”，独立选择，并提供永久保持。继续包含 Beta 03 的曲线与辅助光感修订；不发布、不安装其他手机，不扩大手动点容量或接管系统输出。

## 配置与迁移

MemoryOptions 增加 memory_hold_schema=1、memory_hold_switch、memory_hold_forever。memory_persist 现在明确代表重启保持，memory_restore_unlock 代表锁屏保持；enabled() 决定是否需要运行期保存。永久保持启用三种范围、忽略年龄和照度约束，默认关闭。

旧格式的亮屏恢复仍以旧总开关有效为前提；新格式允许独立亮屏保持。这样不会把已被旧总开关关闭的遗留字段重新激活。配置导入、运行适配、Root 验证和能力探测同步支持新选项。缺少模式交接能力时，只停用相应范围，保留独立的锁屏与重启设置。

## 运行路径

MemoryLifecycle 独立核验原生 owner.setAutoBrightnessState(boolean) 与当前显示对象，关闭自动状态前只捕获有界的手动节点及匹配模型，排队保存；不在 OEM 回调内执行存档写入或递归恢复。

实际恢复使用 BrightnessControl 已注册的模式设置通知，临时所有权操作期间也通知记忆策略，再由原控制器继续处理原有逻辑。初始模式只记为基准；重复通知不会重复恢复。熄屏导致的原生自动处理暂停没有设置变更通知，因此不冒充用户开关，避免“只开跨开关保持却跨锁屏恢复”。

只有选择重启保持才写 Settings.Global。其余范围保存在本次进程缓存，冷启动不会加载旧磁盘记录。手动保存合并，熄屏和模式交接只捕获本次状态，写入及恢复排队执行。恢复仍核对用户、基础曲线、固件身份、当前主映射、屏幕和 HDR 状态；不主动开启自动亮度。新手动调整优先并取消待恢复任务，主动清除同时清理缓存和存档。

永久保持不使用 Long.MAX_VALUE 等可能溢出的超时。对已核验、当前主模型的有效性到期标记作局部保持，并停止该用户选择下的锁屏环境重判；其他模型、用户、HDR、空闲映射、停用状态继续沿用原行为。确需系统重建时，操作结束后恢复已保存偏好；重播期间不再次捕获、排队或重复保存。没有新增轮询、采样或运行进程。

## 界面

三种范围、永久开关、预设和详细参数统一在“保持记忆”容器；绿色曲线概览及清除操作保留。详细参数默认折叠，永久保持时不生效的时间、照度和重判项停用，原参数保留。说明区分运行期记忆与重启存档，避免把“永久”误认为冻结学习或无法主动清除。

## 验证与限制

实际生产类回归覆盖：独立范围、RAM 与磁盘隔离、旧配置迁移、过期存档、永久恢复、相近照度条件、延迟采样、HDR 等待、新输入优先、主动清除和基准变化；实际生命周期 Hook 回归覆盖原生失效标记、无溢出的原有计时、模式前捕获与延后恢复；控制器测试验证忙碌时模式通知仍到达保持策略；配置导入验证能力降级和字段保留。

最终测试数量、签名、源码与交付物一致性见 build/beta-3.1.1-beta04/final-audit.json。没有目标手机加载本包的实测，不宣称新的保持策略、移植适配或功耗已经完成硬件验证。正式版和 Beta 01—03 文件必须保持原哈希。

最终全量构建通过，85 条 PASS 汇总；记忆策略 217 项、实际生命周期 Hook 49 项、亮度控制 387 项、独立自检 249 项、配置迁移 2625 项。永久保持核验当前模型 Hook 和模式能力，且只保持与当前手动节点对应的有效模型；清除后的残留模型不会被继续保持。模式初始化读取异常只等待本功能就绪，不向外中断基础曲线。117 份 Java 源码与最终 APK 构建摘要核对，沿用原签名。
