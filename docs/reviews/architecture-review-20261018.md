# 全项目架构与兼容维护审阅

日期：2026-10-18。基线为刚交付的本地 4.0.0 / 40000；原始快照 `build/architecture-review-20261018/before-review.zip`，原 245 个 APK / ZIP 摘要另存 `prior-artifacts.json`。本轮只修改代码、维护文档及验证工具，不重写已交付包，不更改版本、不发布、不安装手机。

## 审阅范围与方法

- 对全部生产 Java 做文件职责登记、依赖边界与功能 / 路线覆盖检查，重构后共 121 份；48 项功能、20 组适配和 18 类 ABI 内部分支纳入维护清单。6 份原生 C / 头文件及 5 类原生协议 / 运行分支也单独登记。
- 人工核对曲线选择与两类适配器、Hook 安装 / 失败清理、主辅输入与移植补位、主辅确认 / 阈值 / 动画、场景、HBM / 目标 / SDR / 范围 / nit、前台任务、暗光 / 手动接管、节点发现与租约、配置持久化、状态传输、自检、APP 欢迎 / 导航 / 更新及构建 / 发布入口。
- 原生程序与策略头的主屏身份、路径 / inode、IPC 调用者、短租约、系统改写退让和息屏保护做重点复核，并运行既有原生回归；本轮原生业务源码没有修改。
- 使用实际生产类的主机测试、既有多 ABI / 多加载器场景、私有固件静态检查及新增失败注入验证。不是逐台设备的实际运行验证，也没有性能 / 功耗测量。

针对户外安装问题，另将审阅前的真实 OutdoorTuning 源码放回相同故障注入夹具：可选温控跟踪安装失败后，旧代码仍登记支持但目标 Hook 已不存在，确实触发断言失败；新代码在相同夹具通过。结果保存在 build/architecture-review-20261018/counterfactual/result.json，不是仅靠代码阅读推测。

这些修复针对具体安装和维护缺陷；不把它们写成某机型历史卡死的已证实根因。本轮不调整亮度算法、预设、增强强度、采样率或配置默认值。

## 新的长期规范

[架构入口](../architecture/README.md) 连接架构、强制规范、完整自动索引、适配记录模板和根 AGENTS.md。规范要求新增适配同时具备完整探测、旧路径保留、部分接口拒绝回退、互斥 / 组合关系、线程 / 对象 / 用户归属、证据、停止恢复和验证。

代码声明与维护 manifest 各有明确职责，不建立第二个运行时路线选择器。生成索引不手改；新源文件漏归属、功能自检漏目录、删旧路线、缺测试 / 退出说明、HBM 双维度混用、运行层引用页面或按版本判断等会使维护检查失败。静态守卫仅覆盖明确可检查的边界，不能证明真实接口语义正确，仍需审阅消费者与回归。
