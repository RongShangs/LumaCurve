# 2.4.0 r9 场景与状态页整理

历史记录：当前交付已修订为 r10，见 [排版修订](2.4.0-status-spacing-20261010.md)。

构建 `release-2.4.0-r9`，版本代码 `24009`。本轮以 r8 为基础调整交互、文案及场景配置；沿用原正式签名，保留现有曲线、记忆、输出守护与默认参数。

## 界面行为

1. 状态页使用“光感输入与场景”。点击打开场景目录，每项只显示名称、简短状态和一句效果。生效项排在前面；布局完成后定位到第一个生效项。无生效项、状态未知或过期时从顶部显示，不猜测模式。
2. 弹窗只保留一个底部“场景设置”入口。17 类目录保留；完整触发条件在现有系统场景的编辑界面中查看，诊断读数仍在日志页“亮度分支”。背面距离没有可靠框架状态时明确未知，不由辅助光感零值推断。
3. 场景设置按亮度目标、遮挡与降亮保护、运动与游戏分组。每项按钮统一“编辑”，策略另行显示。只有选择“满足条件才允许”时展开条件；时间段、照度分别按需展开，减少默认阅读长度。
4. 手动阳光屏参与方式和原进入/退出等待设置合并为户外页中的同一卡片；不改系统阳光屏开关，也不强制触发。
5. 下部改为“输出范围与保护”，固定横排暗光稳定、户外高亮、温控三栏。每栏有状态、简短说明和箭头，可进入对应设置；未读取或过期也不留空白。曲线蓝块保持单行当前曲线说明。
6. 默认操作按钮至少 48 dp；并排操作使用一致高度和边距，关闭基线对齐。条件编辑弹窗的取消/保留按钮使用同一布局规则。

## 删除自定义场景

已删除命名规则的编辑、执行、计时状态和运行时输出。旧配置中的 `scene_options.rules` 数组只为升级兼容而接受，内容忽略，重新保存/导出不再包含此字段。导入有旧规则时提示移除；`policies` 中九类现有系统场景的配置保留。

现有场景仍支持系统、不参与、附加条件三种策略。附加条件只能限制系统准入，不创造场景；跨午夜、照度、遮挡、多条件同时匹配、进入/退出持续确认和未知输入回退均保留。

- 完整生产 Java 与 ARM64 原生构建通过，沿用原证书；APK 与源码哈希记录在 `build-info.json`。
- 场景 schema/状态机/目录/输出说明 414 项；场景消费者与恢复 66 项；两套固件静态核对 144 项；配置迁移 2350 项；富文本/当前三栏渲染逻辑 636 项；固定布局 2617 项；导航 70 项。其他原有构建回归也全部执行。
- 定位回归覆盖真实弹窗滚动区域的选择、布局完成后滚动、一次性移除监听、关闭弹窗/隐藏目标时不滚动，以及空目标/缺失窗口的安全返回。界面逻辑采用实际生产方法配必要替身；不等于 Android 实际显示验证。
- 当前 ADB 未检测到手机，r9 未覆盖安装、重启或真机截图验证。r8 的真机记录仅对应其原 APK 哈希，不继承到 r9；本轮 `device_verified=false`，不附加旧的设备报告。
- 仅生成本地交付；没有推送、公开 Release 或网站部署。私钥、服务器认证资料、私有固件和完整设备 dump 不进入归档。
