# 本次亮屏应用亮度共享与手动记忆交互复审

## 用户要求

新增应用亮度隔离的子开关，让同一次亮屏内的被隔离应用共享一个普通亮度值。用户明确选择桌面仍使用系统亮度，返回另一应用时再恢复共享值，锁屏清除；付款码等极端提亮不进入记忆。

同轮移除“记住手动偏好”卡片的完整记忆、渐进记忆、不记忆三个预设。红字提醒最终按用户最新要求：本次进入页面后用户调整过记忆开关，或详细参数处于展开状态时显示；初次进入且折叠、未操作时隐藏。开关调整后再调回原值仍算已操作；重新进入页面重新计算，已保存的详细参数展开选择继续保留。

仅本地修改、验证和生成4.4.5-beta03，不含网站发布、设备安装或重启授权。旧折叠适配及所有历史交付保留。

## 实现和兼容边界

- 新配置键`app_brightness_isolation_share`默认false；旧配置缺字段也为false。父开关关闭时子选择仍可保存，运行时不共享。缺少新能力只裁剪运行副本，不回写保存值。
- 新能力`app_brightness_share_supported`独立自检；SCOPED隔离路线保留原来5个Hook，复用原生窗口来源、亮度原因与同步边界。原生无同步路线仍为0个隔离Hook，不伪装支持共享。
- AppBrightnessShareAccess核验原生非二维码组件集合、相机标记、主屏物理ID、HBM及DisplayDeviceConfig类型和范围方法；任何缺失、类型/静态性错误或未就绪均不降低标准，也不拖停已有隔离。
- 只有同用户、同物理屏、同窗口代次、原生明确认为普通非二维码调光，且本次同步确实被隔离、原生返回未裁剪原请求时，才能记忆或应用共享。二维码原生限亮分支、未分类窗口、超出普通范围的请求、0/1端点、HDR、相机、其他控制者和控制中心本次主动调节均不参与。
- 不仅凭应用名字或数值大小认定付款码；不维护支付/视频包名白名单。原生无法证明普通调光的应用沿用系统，等待可靠证据，不承诺任意ROM或任意窗口都可共享。
- 单个RAM状态通过弱引用绑定范围/标定对象，保存框架亮度比例；只有请求不超出本机普通上限才参与，越界请求不覆盖已有普通偏好；保留值仍受当前普通上限约束，原生后续温控、功耗、灰阶等限制继续处理。来源切换时旧应用原始偏好不能覆盖共享值；同窗口后续原始调节可更新。
- 返回桌面撤回窗口限定但保留RAM值，不写系统亮度、自动模式或应用偏好。灭屏/锁屏许可立即撤回并清空；关闭功能、停止引擎、切用户/物理屏或范围/标定对象改变清空。进程重启自然不恢复。
- 锁屏状态只在现有窗口变更事件中检查，放在会话锁外，不在每个输出帧重复查询；现有屏幕退出路径同步撤销许可，再执行既有清理。无新Hook、服务、计时器或光感采样。

## 验证

针对性测试直接编译生产策略、适配器和Hook，覆盖A调高→桌面原亮度→B共享→B调节→返回A、重复帧不回灌旧值、付款码分支及端点、相机/HDR、控制中心优先、锁屏/灭屏、迟到帧、同帧换屏/换标定、用户及范围变化、异常退出和新ABI残缺时旧隔离保留。重复100帧不会增加锁屏服务查询。

手动记忆交互测试使用生产开关回调、详细参数回调和提醒刷新方法，验证初始/展开/收起/开关往返/程序加载及无关设置展开，不改原强度和持久配置。旧隔离、亮度控制、自检、配置导航及私有原生消费者也纳入完整构建。

私有固件仅保留接口及消费者核对结论：原生两处应用同步均在明确的非二维码分支，二维码限制在另一返回路径；相机/HDR判断、原生普通范围委托及物理屏字段匹配。原文不进入公开源码或交付。

完整构建、APK原签名、同源源码/完整包、最新感谢名单及历史文件保留以本地回执为准。主机及静态验证不等于Android真机、观感、长测或功耗验证；新功能尚待用户设备回访。
