# 3.0.2 Beta 01 自检与兼容复审

## 检查范围与边界

引擎逐项检查基础曲线、主辅光感、手动记忆、曲线保存、记忆持久化与重置/超时、暗光锁定、手动输出钩子、应用名单、温控、变化确认、暗光稳定及闸门、五组高级设置、九个现有场景、户外增强、HBM 预算、高亮范围、画面限亮、nit 上限及节点输出接口。

Root 启动检查独立覆盖配置读取、备份/分析包目录、主屏唯一节点与打开权限、节点增强条件及 APK 内控制程序。打开 APP 检查桌面入口、本地偏好与文件目录。联网服务在真实请求中检查，不把离线误判成设备不兼容。

接口缺失与未就绪分别记录。每个探针独立捕获失败，后续探针继续执行；结果包括时间、请求标识、条目状态及有长度上限的原因。状态显示使用自检能力结果。用户配置保留原样，运行副本按能力暂停不兼容选项，依赖选项同步回退。

引擎启动与 APP 恢复到前台均触发检查。结果未变化时不重新应用配置。暂未就绪只安排 1、5、15 秒三次检查；关闭引擎后失效。不调整 ALS 监听频率，不增加常驻采样。检查是接口与就绪性验证，不是对硬件效果的全自动实测。

## 固件与亮度证据

- 新 OTA 案例中设备基准、曲线路径与用户身份保持一致，仅固件标识变化。取消由该字符串差异造成的整体拒绝；真实基准变化继续要求重新应用，避免使用失配坐标。
- fuxi 分析包中框架坐标 1.0 的物理映射为 1200 nit，用户确认主屏手动节点仍可明显更亮。该证据支持研究节点余量，但不能据此推算新增亮度的实际 nit。
- 其他分析包的 Refactor 逻辑 nit、物理 nit 与节点值属于不同坐标。不能将逻辑上限或单条导出数值当作面板硬件极限；SurfaceControl 输出路径本身也不能证明缺少高亮能力。

## 节点兼容路径

默认关闭，实际接口分类，与常规画面限亮路径协同；不使用机型、系统主版本或固件哈希白名单。Root 层再次核验唯一主屏节点和打开权限，未知/有歧义时不启动。保持已有主屏手动面板优先。

框架输出回调仅缓存状态并投递任务，文件 I/O 移出显示线程。授权有效期 1.5 秒，仅满足自动亮度、持续强光、输出到顶、温度、电量、SDR、未接管等条件时续期。节点值稳定后才提高，连续最多 30 秒。系统写入其他值后停止重申目标，释放时仅还原自己仍持有的值。写入/启动失败保留原因，同一配置不重复拉起失败守护。

该功能需要额外 Root 进程。重启后需打开 APP 重新协调启动；未开启时没有额外节点守护。不能将策略测试理解为已证实所有设备驱动温控、HAL 并发行为或耗电水平。

## 验证

- 新独立自检回归：236 项，包含生产探针、异常隔离、等待后恢复、相同结果不重配、关闭后取消、运行副本局部回退与原配置保留。
- 新节点策略与 Java 桥接回归：7252 项，含手动优先、过期授权、系统覆盖让出、30 秒退出、动态节点上限与 I/O 失败。
- OTA 基准重验：10 项；完整回归数量见包内 build-info.json。
- ARM64 原生程序与 Android APK 编译、原签名、源码摘要及归档一致性均需随最终包核验。
- 未做本版真机效果、解锁复现或电池功耗测量；原始设备分析包、固件及认证资料不纳入源码分发。
