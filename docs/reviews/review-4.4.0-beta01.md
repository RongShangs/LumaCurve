# 4.4.0 Beta 01 复审

用户报告重启后映射需开关一次，随后本人设备也发现需打开APP。所附分析包当前快照的系统框架和SystemUI均已加载，映射标定已就绪；Root为uid0、设置读写已确认，不能仅凭KSU二改就认定权限原因。代码显示曲线随Hook启动，而Root端PROFILE/闲置节点监听的reconcile此前仅从APP inspect/apply触发。跨开机PROFILE按PID、启动标识、boot_count验证失效是正确防护，但缺少自动重新连接。

本轮在原兼容适配器上补充系统一次性任务恢复，未新增机型或Root管理器分支。Job只为主用户已保存开启的映射调度，默认关闭不请求Root；可读全局配置提示支持已有用户升级，无权限读取时保持原本地记录。最多四次就绪等待，每次连接8秒；拒绝、超时、明确身份或节点失败终止。重复广播按构建/开机代次去重。Job停止通过ID/attempt匹配，取消连接；旧线程不得记录或结束新任务。没有永久APP服务、启动脚本、网络、旧亮度回放或自动增强。

Root复用既有reconcile与原生监听：原配置不重写，真实TABLES和PROFILE仍绑定当前系统进程、用户及物理节点；其他手动面板保持不被抢占。raw10资产及所有旧路线保留。SystemUI增加boot_count事件观察，未增加轮询。

作用域核对从无关apply中移除，重复选中不触发；仅相关草稿改变按需引导，同一草稿去重。数据库未知且注入已核验时不弹缺失提示。明确缺失仍提示，不写作用域，不自动重启系统界面或设备。

独立功能自检记录与分析包导出增加启动证据。新增两份Java登记源码分层、路线目录与清理规范；171份Java、57项功能、24组兼容。Beta以公开4.4.0为累计基线，保护441份已有APK/ZIP，官网保持44000。未提交用户分析包、固件或无关研究改动。

验证见 `build/beta-4.4.0-beta01/build.log`、`verification.json`、`local-audit.json`：执行生产调度/异步任务与Root恢复状态负向回归、作用域与设置交互、完整旧路线回归、签名/源包/旧产物一致性。无本轮设备重启、Android像素或功耗实测；平台自启动/强行停止和Root本身不可用仍可能影响恢复，报告中保留具体原因，不宣称全部二改环境已实测解决。
