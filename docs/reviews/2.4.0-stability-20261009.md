## 已修复问题

| 范围 | 触发与影响 | 修复与验证 |
| --- | --- | --- |
| 延迟记忆保存 | 手动节点排队保存后切换曲线或用户，刷新存档时可能把新身份的短期模型附加到旧身份节点中；若照度恰好相同，不能靠照度匹配发现混用 | 附加模型前比较完整 scope；旧节点仍按原 scope 保存。测试覆盖换曲线、换用户、停用前的待保存记录 |
| 合法零亮度平台 | 传统曲线的工厂节点与基础节点同时为零，重建倍率得到 0/0，曲线对比可能不可用 | 零除零的恒等倍率取 1，其他非法输入继续拒绝；基础与草稿曲线均回归 |
| 实时限亮证据 | 仅修改温控等设置、户外选项未变时，旧限亮观测残留至到期；相同户外目标的请求时间没有刷新 | 每次配置更新都清理实时证据；当前目标每次计算都刷新时间，增强计数仍只在实际提高时增加 |
| 监听器生命周期 | 注册到一半失败会留下部分监听器；关闭时一次注销异常会跳过后续注销；重复关闭或旧回调可能影响新实例 | 部分注册失败时逐项清理，关闭时各服务、各观察器独立注销；控制器重新尝试注册，运行时关闭幂等，已关闭实例忽略回调。实际方法加服务故障替身验证 |
| 建议跳转 | 展开参数后用普通 post 滚动，可能在新布局完成之前读取坐标 | 改为一次性预绘制监听；页面离开、销毁或目标不可见时不滚动，不改参数或草稿 |
| 正式版签名 | 原构建在密钥缺失时可以生成新密钥，导致同包名正式 APK 无法覆盖旧版本 | 正式构建在任何 SDK/依赖和产物操作之前要求原密钥与指定证书；丢失、不同证书或 keytool 失败均停止。测试版逻辑保留 |
| 网站交付 | 同步脚本写入部分新下载后才检查版本；打包脚本只检查文件存在，可能打出混合版本 | 输入与页面版本预检通过后才写入；打包前核对元数据、脚本、链接、三份下载与构建文件、SHA256。失败保留原包；测试完全在临时目录运行 |

源码归档同时补齐 `docs/reviews/` 和本轮新增测试，避免交接文档引用的审阅依据未进入源码包。

## 回归与边界

正式构建命令为 `python tools/build_refactor_hook_test.py`，不使用 `--skip-device-fixtures`。构建包含完整 Java 编译、ARM64 严格警告编译、既有固件静态核对、主机模型与实际方法回归、原生资产一致性、APK 对齐及签名验证。

定向结果：亮度控制 205、恢复方法 100、记忆存档 154、曲线对比 64、户外链路 235、状态建议 94、导航与配置帧 47、发布保护 41、beta01 节点权限 130 项。完整计数和源码/原生/APK 校验值以合集内 `build-info.json` 为准；本机完整日志为 `build/release-2.4.0-stability-build.log`。新增用例在修复前复现了记忆混用、零平台异常、旧限亮证据及监听器清理问题。

继续保留系统的传感器、过渡动画、严重过热、HDR、省电和驱动保护；不加入额外自动亮度输出守护或唤醒锁。状态建议只读，图表含义、九个二级保存入口、贡献名单和独立感谢 JSON 遵循原要求。

本机没有 Android 真机或可用虚拟设备，不能把主机模型及静态资料核对写成实机通过。发布前仍需在目标设备验证覆盖安装后重启、提示跳转、大字体/横屏、锁屏/AOD/解锁、主动开关自动亮度、长时间运行及真实节点权限。此报告不作“所有设备无故障”的保证。

本轮交付本地 APK、源码和恢复合集，未执行推送、发布或部署；不包含服务器凭据、签名私钥或私有固件。
