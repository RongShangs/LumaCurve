# 3.1.0 节点目标与统一增强时长复审

## 目标与范围

用户要求将节点兼容选项更名、去掉单独 30 秒时限，跟随户外增强时长；随后明确节点不再按增强强度计算，并新增独立滑动杆，真实设备上限、默认最高。本版保持已有触发与退让条件，集中修改目标和时长。

Root 层使用 PanelNodeDiscovery 找到唯一主屏候选，实际打开权限探测通过后向 APP 提供 max_brightness。滑动杆以该值建范围，未取得时禁用。配置值 0 表示动态跟随本机最大节点，界面显示实际数字；显式目标必须为有效整数，最低延续主屏节点控制的 10。导入、提交与原生执行均按当前设备上限校验或收敛，避免跨设备设置越界。

Java 桥接使用 v2 原始目标授权，不再读取增强强度作为节点倍率。原生层保留 v1 协议兼容，v2 的 0 直接取实时核验的最大节点；显式值不超过本机最大值。目标低于系统基准时不主动压低 OEM 输出；若模块仍持有旧高目标，调整到低目标会先归还自己的增强。

## 触发与退出

- 户外增强、高亮范围、画面限亮放宽和节点选项开启，nit 上限为 0；实际接口、主屏节点与写入权限核验通过。
- 户外增强先完成进入照度与确认等待；节点增强还要求照度达到全强度阈值。默认分别为 10000 lux / 3 秒和 30000 lux，均以当前配置为准。
- 主用户、亮屏且解锁、SDR 普通自动亮度，框架输出已到最大，没有手动面板、暗光锁定、应用亮度覆盖或 HDR/防窥拦截。
- 当前桥接仍要求电量至少 30%、非省电、热状态无热限制、电池温度不高于 43℃与用户阈值的较低值，同时满足户外增强原有温度和场景判断。
- 节点读数稳定后提高到目标；如果实际已经不低于目标则不增加。系统主动覆盖后停止争抢，释放时只回退自己仍持有的值。
- 移除原生 held 状态的 30 秒分支及 poll 中对应期限，不保留另一份增强计时。Java 的实际 OutdoorPolicy 管理会话，过期或进入冷却时节点授权撤销。晚于户外增强开始才触发节点时，不重新获得完整时长。
- 授权 1.5 秒、符合条件时续期，属于进程失联的回收机制。普通有效会话超过 30 秒仍可增强；不因短期授权而固定停在 1.5 秒。
- 全强度阈值以下、锁屏、手动调整或保护变化时仍退让；户外增强整体可以尚未退出，节点增强先退出。

## 验证

- 原生策略与实际 Java 桥接测试覆盖 v1/v2、动态最大节点、显式原始节点、目标更新、系统覆盖、手动优先、失联释放，以及最长 10 分钟的授权续期。
- 桥接与生产 OutdoorPolicy 联合测试 30 秒、1 分钟、3 分钟、10 分钟会话，确认到统一时限撤销，而没有额外 30 秒截止。测试不同增强强度时原始节点目标一致。
- 生产滑动杆绘制及设备上限字段传播回归覆盖未知上限、4095 / 8191 / 16383 / 65535 等范围、默认最高、显式目标、支持状态变化与导出往返。
- 配置迁移额外检查节点值类型、越界以及跨设备收敛。完整已有测试、ARM64 编译、原签名与归档一致性一并执行。
- 测试使用主机服务模拟和私有固件静态证据，不代表本版实际设备上的亮度、解锁或功耗实测。未推送或部署。
