# HyperLux 当前主线完整复审 · 2026-10-26

## 结论与交付边界

审阅基线为已交付的 **4.1.1 Beta 04 / 41104**，范围是当前正式 APP / LSPosed / Root / 原生工具主线 `experimental/refactor_hook/`、21组兼容登记、构建与交付检查。独立API 102、旧KSU/C模块、固件研究和未合入工具不自动成为当前运行路径。

**整体仍遵循实际接口检测、兼容独立选择、保留旧路径和保留用户设置的设计；不是所有文件都已经彻底模块化。** 已确认的临时字段恢复、Hook失败清理、OTA旧提示和Root错误展示问题已修复。重复清理机制已收敛，仍有大型协调类与部分旧式安装器需要分阶段整理，见下文。

本轮只修改源码、文档和验证，不变更版本标识，不安装手机，不重新打包，不发布。已交付Beta 04不包含本轮源码修复。下一次打包必须使用可区分的新Beta或修订，不能覆盖旧包。公开正式版仍4.1.1 / 41100。

## 审阅范围和方法

- 所有生产Java均纳入源码分层登记和完整编译，共137份；其中新增的FieldOverride是共享的临时字段机制，不是新设备路线。
- 52项功能、21组兼容家族、59个稳定路线ID、27个内部ABI变体、6组原生变体与旧基线核对。
- 人工重点检查初始化与回滚、反射入口、曲线与记忆的坐标/归属、显示用户与物理屏身份、屏幕/温控/应用场景状态机、Root权限隔离、APP异步操作和更新、导出及构建产物边界。未把“137份文件纳入检查”表述成每行都已在真机执行。
- 自动层面执行完整维护契约、生产Java编译、现有各路线回归、私有固件静态核验，以及新加故障注入。私有输入仍留在忽略目录。

### 哪些看起来像“特判”，但不是临时脚手架

- `zte.sensor.light_second`、小米已选用的私有ALS/FOV及物理地址类型是已核验接口身份，不是按设备昵称放行；仍有唯一性、来源、单位、权限、线程和实际主屏校验。
- Refactor的逻辑锚点与分段系数是互斥ABI，传统小米/AOSP mapper各自负责坐标换算；不能为了代码短就把不同坐标强行合并。
- 节点65535等数值用于16位输入安全验证，不用来替代实际节点上限。写入前仍读取真实max_brightness并核验身份。
- Root的su位置候选只是定位可执行入口，不代表根据Magisk/KSU品牌开放某项功能；已拒绝授权不多路重试。

### 本轮确实收敛了哪些重复机制

- 原来三套临时字段恢复实现 → FieldOverride统一归属与嵌套语义。
- 多处手写撤销循环 → HookTransaction.rollbackAll统一逆序及异常隔离；不改各安装器原探测和优先顺序，不复制成熟状态机。
- Root目录失败原因 → 适配层统一记录，页面读取证据；没有在页面再创建目录或猜权限。
- OTA提示 → 使用已确认运行状态；删除UI中沿用旧强制重应用策略的误导文案。

## 仍需逐步整理的技术债

1. **MainActivity与RootControl仍偏大。** 前者混合页面组合、草稿、提示和操作协调，后者保留协议分派、配置事务及导出。它们不是每个机型一套脚手架，但维护面过宽。后续按页面/事务逐组拆分，沿现有设置与回归契约迁移，不在本轮无依据重写整个控制链。
2. **不是所有安装器都已改为完整安装事务对象。** 本轮统一失败清理；成熟安装器仍有本地句柄列表。其成功发布能力、失败清理与旧测试仍保留。以后触及相应功能时逐组迁移，而不是为了统一同时重写全部Hook。
3. **部分绘制方法仍包含选项依赖归一。** 例如户外节点的前置选项联动；这是UI草稿层的规则，不是重新检测机型或直接写系统。应逐步迁到显式编辑动作与共享Options中，同时保留已有联动行为。
4. **历史目录命名与总文档历史记录较多。** experimental/refactor_hook和build_refactor_hook_test.py已经是正式主线，名称带历史痕迹；研究目录仍隔离。当前状态与历史状态必须明确区分，本轮补充当前复审入口。
5. **有些控制事务仍同步调用系统设置。** 大体积状态已交给DeferredStateWriter；暗光/手动模式切换和持久记忆等要在保证控制权、确认与时序的前提下继续评估，不能以异步化名义改变原子性。此次没有证据证明它们造成当前卡死，也未做功耗测量。

以上为维护债务，不把它们包装成已经完成的“大重构”。
