# 3.1.1 Beta 02 复审

## 任务与边界

用户提供努比亚移植 HyperOS 系统分析包，明确症状为辅助光感没有读数，并要求新的 Beta 发包继续递增编号。本轮仅本地适配、验证与打包，不发布，不操作其他手机。原有机型的适配路径优先保留。

## 原因证据

原始包已按实际注入构建 `beta-3.1.1-beta01-coordinate` 私有归档至工作区 diagnostics/packages/3.1.1-beta01/，固件与反汇编仅在忽略的 build/port-compat/nubia-20261017-83931a/ 内使用，不分发。

主引擎状态 active，曲线路径 refactor，主光感有效。SensorService 清单包含 Sensortek 第二光感 `zte.sensor.light_second` / 33172007；没有原小米辅助类型 33171055。DualSensorPolicy 构造函数仍按后者查找，原始 setSensorEnabled 会在注册返回前标记已启用，所以采样状态 true 不能证明已有监听。辅助值为重置状态、有效标志 false。

实际 OEM 回调读取 SensorEvent.values[0]，没有按原私有数字类型过滤；后续仍经过原有夜间驾驶、手电筒、背屏、预热与滤波策略。因此可在严格条件下补齐缺失的传感器对象，无需自建融合或高频监听。

## 实现

AuxiliarySensorIdentity 只接受已核对的标量第二光感语义身份，非唤醒、on-change、无额外权限且量程与分辨率有效；不选择 flicker、SAR 或复合 dual_light。兼容别名从实际列表读取数字类型，不硬编码机型或系统版本。

AssistSensorCompat 仅在当前用户已应用配置、主屏、原辅助对象为空、原系统允许辅助策略且辅助倍率为 1 时接入。继续调用 OEM 原有启停方法，由它管理现有监听。未应用配置、原生对象存在或任一身份 / 线程 / 单位检查失败时不修改传感器。

接入、撤销和回退记录所有权，使用原启用状态完成事务；注册抛异常时尝试恢复，策略对象消失 / 重建、用户变化、倍率变化时撤销旧绑定。其他组件已经替换对象时不覆盖。没有额外传感器监听、轮询、Root 守护或进程。

RuntimeFeatureChecks 与 BrightnessControl 复用同一光感身份规则，避免状态页支持但暗光锁定不接受的路径分裂。现有启动就绪检查在探测前补齐延迟创建的辅助策略；原有独立自检本身仍只读。跨线程撤销交回原显示线程处理。状态报告包含接入信息，读数有效性仍取原系统标志，不伪造 lux 或替换为主光感。

## 验证

专项主机测试覆盖原生选择不变、缺失补位、其他显示 / 用户 / 单位 / 权限 / 数据流形态、多个候选、初次未启用、失败回退、停用恢复、策略替换、对象被其他组件替换以及暗光锁定采样。用户固件检查验证原始类型缺失、第二光感存在、注册清理与原消费者标量语义。以最终构建回执记录各测试数量和签名 / 打包核验。

尚未得到该设备加载 Beta 02 后的传感器事件，传感器单位、实际采样和场景效果仍需真实运行确认，不据静态核对宣称修复已实测。

完整构建回归通过，日志含 84 条 PASS 汇总。辅助光感兼容 57 项、用户固件静态核对 18 项、独立功能自检 242 项；亮度控制含新光感采样共 386 项。原发布证书核验通过，交付源码与 APK 构建身份一致。无本轮硬件执行结果。
