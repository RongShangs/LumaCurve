# 4.1.1 Beta 04 · 受限 Root 独立能力复审

日期：2026-10-25。基线：公开4.1.1 / 41100；累计Beta 01—04，仅本地交付。用户说明常见环境为KSU“越狱模式”，未提供确切版本、权限配置或目标设备分析包。

## 问题和边界

原Root入口将UID0、固定操作目录和外部Settings Provider作为全局前提。某一项失败会阻断整个诊断，APP又容易将Root通信失败混成LSPosed未连接。成功注入的系统进程逻辑不依赖APP持续su；APP设置桥和原生工具仍需实际访问权。不能把“临时 / 越狱”名称等同于权限不足。

参考：[KernelSU应用权限配置](https://kernelsu.org/guide/app-profile.html)、[官方late-load实现](https://github.com/tiann/KernelSU/blob/main/userspace/ksud/src/late_load.rs)。前者明确UID、组、Capabilities和SELinux配置可独立限制su；后者说明晚加载流程与冷启动不同。本文不据此推断任一用户实际权限。

## 兼容责任

| 层 | 选择和失败处理 | 不变的保护 |
|---|---|---|
| RootLaunch | APP和面板共用su入口；仅找不到可执行文件时尝试其他位置 | 已启动或明确拒绝授权不循环弹授权；APK路径单引号转义 |
| RootSettings | 原Provider → cmd settings → settings；启动只读选择 | 同一系统服务鉴权；原PUT可返回null，读回确认；写入失败不换路重放 |
| RootWorkspace | 原目录优先；身份、父目录及0700检查通过后可选独立目录 | 非共享tmp；不接受符号链接或其他所有者；原生固定旧目录 |
| RootCommand | 无文件时有界输出 / 超时 | 8MiB上限；旧脚本保留文件输出，支持继承输出的后台子进程 |
| RootControl | 保留当前进程核验；核心ACK后可选工具分别记录错误 | 不跳过PID、启动标识、构建、指纹和用户；提交失败仍回滚 |
| 原偏好 | 不可用且未改动的既有节点偏好只裁剪验证副本 | 持久配置不删除，不授权新增未核验节点控制 |
| Root自检 | 各项独立；所选入口、失败入口及未尝试入口分别显示 | 不改亮度、不安装或启动原生程序；目录初始化在辅助进程启动阶段 |
| APP诊断回退 | 完整导出失败后Downloads保存明确标记的不完整报告 | 最近状态不是实时，失败删除半成品，无额外存储权限 |

说明：原生停止流程的恢复顺序未放宽；无法确认守护和权限恢复时仍报告失败，不能以“解耦”为由假报已恢复。新增功能没有改Hook / 原生C算法和采样率。备用CLI存在前台命令开销，没有新增后台周期服务。
