# 独立亮度原生交接与迁移按钮复审

目标：本地4.4.5-beta11 /44511，构建beta-4.4.5-11。保留原配置、原签名与全部旧交付，不含发布或设备操作。

## 回访事实

用户报告Beta10独立亮度失效，并提供2026-11-10 13:10分析包及迁移确认框截图。设备仍按pandora／25098PN5AC、HyperOS 4.0.6.0.XBLCNXM记录，不猜测商品名。

包内运行构建为Beta10，接口自检可用、配置已应用，三款视频应用归属同一组，组记忆值为0.16379364。导出时前台是HyperLux，因此独立租约非活动符合预期，不能据此认定前台识别失效。显示事件多次出现进入时关闭自动亮度，却仍沿用进入前的系统值；13:10:38进入时仍为0.022329245，没有恢复已保存组值。手动调节及退出日志存在，不能判为整条接口不可用。

私有同版本原生消费者显示，关闭自动亮度时Refactor会在原生模式切换回调内再次调用DisplayManager.setBrightness。配置模式先写入不代表该异步交接已完成，模块首次写入会被覆盖。此前主机模型只检查即时模式/亮度，没有模拟这次延后覆盖；Beta10阻止误学习后，该缺口影响恢复。不能通过重新允许曲线误学习让独立值看似生效。

## 改动

- 独立会话从自动模式进入时，等待已核验DBC设置消费事件及实际手动模式。消费Hook仅投递通知，离开原生策略调用栈后才读取模式和亮度、单次补交付当前租约目标，避免在原生锁内调用服务。
- 没有定时轮询、持续重写、额外常驻任务或开机Hook。模式确认后标记完成，不将补交付当新用户记忆。前台查询完成的既有事件可接续待确认任务。
- 用户待处理拖动优先；非模块基线或目标的后来写入不覆盖。配置/物理屏/焦点/代次不匹配、退出、锁屏、换组撤销旧回调。保留Beta10退出消费、短期模型与曲线学习隔离，以及用户主动开启自动亮度的规则。
- 迁移弹窗继续用24dp外圆角和自适应正文；两操作采用项目已有的等权等宽48dp布局，10dp水平文字留白、14dp正文间隔，统一文字居中和字体内边距。确认才移动、取消不变。

## 核验

控制器新增可复现的原生延后覆盖、重新进入同组、实际模式未确认、单次执行、快速退出/锁屏、外部前后写入、待处理拖动和原手动模式检查；同时检查原生通知不直接进行服务读取。负向副本故意移除原生交接通知后，新回归失败。适配器检查设置消费通知只发给当前主屏/显示线程，错对象和错线程不发通知。名单页测试执行生产按钮布局方法，核对多密度下等宽、同高、留白及正文间隔；不是Android像素渲染。

完整检查继续覆盖旧暂停名单、配置迁移、分组、窗口隔离、曲线、HDR/温控及节点映射开机/解锁/折叠恢复。签名、编译源码指纹、随包源码、感谢名单和旧交付字节核对见本地build/independent-active-20261110回执。

输入包、固件、反汇编与设备原始日志均私有归档，不进入源码/安装包。新包尚未在用户设备执行；实际效果需回访。此前SystemUI启动延迟没有新的有效故障主线程栈，不宣称根因已确定。
