# 节点写入失败恢复 · 2026-10-23

公开版本4.1.1 / 41100。本轮仅本地源码实现与验证，不重新打包、发布或安装手机；原交付物保留，新增兼容保留旧路径，覆盖更新保留全部用户设置。

## 依据

用户2211133C / fuxi、release-4.0.0分析包：节点增强开启、目标0（实际上限4095），普通阳光增强曾在约11万lux下到达系统换算1200 nit，但节点守护write_failed退出。旧failure_revision阻止恢复，即使用户重新保存也继续沿用旧失败；4.1.1仍存在。原记录无完整errno，不能断言首次失败是硬件拒绝还是系统竞争。

## 修复与边界

- 保留v1/v2/v3及原折叠绑定，集中在现有原生节点适配器处理，分开成功、比较竞争、系统有效改写与真正I/O错误。
- 对EAGAIN/EINTR/EBUSY/ETIMEDOUT/EIO最多3次总尝试，初次后等待80、160毫秒。等待时释放手动锁，不新增常驻轮询或传感器采样；恢复原亮度仍只比较写入一次，包括停止退出。
- 每次绑定最初计算目标时的租约，重读许可、PID、目标、物理身份、同一节点及上限。续租可更新期限，但改变请求、熄屏、手动占用、系统保护收回许可即停止。不同的系统有效节点值进入原场景抑制，不连续抢写。
- 只有上一写入已接受且读回稍有延迟，才确认后续目标匹配；未接受的写入后出现系统同值，不能冒认控制权。不得延迟恢复而覆盖其他所有者。
- 耗尽重试仍停用，普通查询不反复拉起。用户主动保存并应用且新配置获确认后，经过全部原有支持、归属、节点及屏幕校验可重新启动；失败保留错误并走既有配置回滚，不清空设置。
- 健康记录增加write_attempts、write_errno、write_stage；退出清理保留失败证据，不被恢复尝试覆盖。

## 验证

专项测试直接提取生产C函数并控制I/O，覆盖两次失败后成功、三次耗尽、延迟读回、权限拒绝、系统改写、手动抢占、目标/PID/物理身份变化、节点上限变化、失去许可与停止恢复；同时编译实际OutdoorNodeRoot验证自动锁存和主动恢复必须完整校验。100项专项主机检查，不是目标机实测。
