# 独立亮度退出恢复与应用管理复审

交付目标：4.4.5-beta10 /44510，构建beta-4.4.5-10；仅本地，不包含发布、安装或设备操作。

## 问题与证据

用户反馈Beta08退出独立亮度组后亮度未完全恢复，曲线也发生变化。本次没有新的设备分析包，不能认定该机每一次曲线变化的唯一原因。

源码存在可复现的时序缺口：恢复基线的框架写入并不等于原生待处理设置、临时拖动值和用户更新标记已消费；旧版紧接着恢复自动模式，会把未消费的变化作为用户调节交给自动学习。原测试仅模拟即时亮度写入，没有覆盖这条队列。独立会话首次接管也需在写入前建立学习隔离，避免模式状态尚未更新时误学习。

私有固件仅用于核对真实方法签名和消费者：DBC的handleSettingsChange读取当前设置，updateUserSetScreenBrightness消费待处理值并更新用户变化标记，第二次无待处理时清除标记；setTemporaryBrightness(Float)清理临时策略。ABC用户学习入口同时写入映射点和短期模型，不能只在图表层隐藏变化。固件与反汇编不进入交付。

## 最终改动

- 在实际独立接管前建立学习隔离；精确匹配当前显示对象及显示线程的ABC用户学习入口，阻止独立会话改变短期模型；Refactor与传统映射的手动学习入口同样隔离。普通全局调节保持原有学习行为。
- 退出仍拥有的独立亮度时恢复原基线，再通过原生消费者清理待处理设置、用户变化标记和临时策略，最后恢复原自动/手动模式。退出时先在同步边界撤销输入许可并快照最后手势，快速退出识别本会话尚未合并的普通输入；外部后来写入的值不覆盖。进程恢复使用相同清理。
- 不删除、重置或反向拟合用户已有曲线；没有当前原生ABI时仅独立亮度不可用，旧暂停名单及其他功能继续按实际能力工作。启动/自检仍不安装独立观察Hook。
- 暂停块删除旧版兼容提示，旧键、可见性、多窗口和升级保留行为不变。自检删除退役共享条目，旧存储字段继续读取；维护文档保留退役配置记录。
- 视频分类结合系统category与明确包名，补充常用国内视频应用及其部分版本，仅从本机候选中选择，不模糊匹配名称，不整份采用混合影像列表。视频/游戏批选继续共用迁移确认与名单上限。
- 迁移确认采用现有ResponsiveDialog、24dp圆角、固定标题/操作区与可滚动正文；确认才移动，取消不变。

## 验证边界

生产控制器配合异步设置/临时策略双件检查自动、手动、分组切换、快速退出、外部写入及进程恢复。私有负向副本故意移除退出消费，新增检查失败，证明能识别原缺口。原生输入适配器检查学习入口的对象/线程隔离、清理标记和缺接口拒绝；传统学习检查独立会话不新增点、原有调节继续有效。视频识别覆盖国内常用包名、系统分类及支付/相似包名负例。

完整构建继续覆盖节点映射开机恢复、SystemUI晚就绪、解锁、折叠屏重绑与旧租约，以及原有曲线、隔离、HDR、温控、用户与物理屏保护。实际计数、签名、随包名单和历史文件核对见本地build/independent-restore-20261110回执。

以上属于主机执行及私有固件静态证据，未在用户设备运行新包；设备实际观感、重启与长测需回访。此前SystemUI启动延迟根因仍未获得当时有效主线程栈，不因本次修复宣称已解决。
