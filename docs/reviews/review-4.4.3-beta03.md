# 4.4.3 Beta 03 · 节点程序私有锁及升级复审

## 用户证据及限制

Redmi K90 Pro Max/myron/25102RKBEC、HyperOS4.0.6.0、正式4.4.3分析包显示：曲线及Root设置读写正常、真实主屏节点可读且上限16383；磁贴和映射共用的原生程序两次在root_private_lock退出，errno均为0，socket未监听，无节点保持实例。已生效配置的映射模式为0，截图中的分区选择未成功提交。

旧检查将有效UID、目录类型/所有者/权限、锁文件元数据和flock合为一个分支，其中元数据拒绝没有设置errno。本包未提供锁元数据，因此不能断言是某个KSU版本、某一种权限或锁竞争。当前Root工作目录检查通过也不能证明此前启动瞬间或原生子进程命名空间相同。

## 实现和所有权

- 原生private_directory/private_open_lock共用于手动主屏、映射和户外节点锁。验证有效Root、可信父目录、真实路径、根目录身份及打开对象身份后，将可信Root自有目录规范到0700。拒绝错误UID、类型、别名和不可信父目录。
- 锁使用openat和O_NOFOLLOW，在同一目录描述符中打开；要求Root自有普通文件、单硬链接、非阻塞独占锁，并在拿锁后规范到0600。重新核验路径与FD的设备、inode、类型、UID、链接数及权限。不unlink、不替换锁、不强抢已持有的锁，不借新inode产生双写。
- 锁内容不被采信。权限恢复记录仍按原协议严格验证，不因本次修复而接受被共享或被替换的记录。原生恢复和真实节点边界保持不变。
- 区分锁正常占用与权限/身份失败；前者继续退让，后者记录明确阶段与errno，原生身份错误单独记录uid/euid。export新增只读native-storage.json，不增加常驻采集。
- 安装器将APK已核验的候选程序写到唯一私有临时文件，先用候选执行原生恢复；恢复成功才原子替换旧程序，失败保留旧文件并清理本次临时文件。相同载荷保持原快速路径。此举避免旧程序因同一权限检查阻止新版修复被安装。
- 原生版本raw11-slider；Java继续接受raw08/09/10及raw11的同节点就绪协议。曲线、模式、设置键、真实上限、租约、屏幕/用户边界和原有兼容路线不变。

## 验证

tests/refactor_native_storage.py提取生产C检查和Java安装方法，覆盖64组私有权限组合、相同inode修复、Root/父目录/所有者/别名/类型/硬链接、锁占用、路径更换、chmod失败及虚假成功、候选恢复失败回滚、候选清理及相同载荷快速路径。旧元数据检查的errno=0模式被复现；这不证明用户设备恰好使用该文件权限。

旧主屏写入、户外有界重试、节点权限、恢复和Root独立能力回归继续运行，ARM64实际生产编译通过。主机及静态结果不等于Android/SELinux、该K90设备或功耗验证；完整构建与分发审计保存在build/beta-4.4.3-beta03。仅本地交付，不发布或操作手机。
