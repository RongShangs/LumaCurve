# Beta 02：记忆开关与暗光手动调整复审

## 代码中确认的问题

- MemoryOptions 缺失字段的回退，以及 APP/引擎的初始选项，将跨重启保留与亮屏恢复设为开启。用户未明确设置时可能启用存档恢复。
- Beta 01 中 HookRuntime 接受基准与路径相同的 OTA 配置，但 MainActivity 仍按固件标识不同丢弃它，随后可能显示默认开启的恢复选项。界面与运行状态不一致，再保存时可能写入非用户选择的默认值。
- 用户设备本轮未连接 ADB，也没有本次启动的分析包，不能确定实际存档来源或认定其经历必然走了某条路径。修复以上已确认的代码问题，不自动删除任何现有存档。

## 修改

- 两个存档恢复选项需要明确为 true 才启用。初始对象、缺字段解析、配置导入保持一致；普通当前会话手动记忆继续工作。
- MainActivity 使用 ConfigurationCompatibility.canReuse，核对实际路径、基准、用户及 OTA 重新核验条件；读取失败时通过 MemoryOptions.forDisplay 展示实际生效选项。未保存草稿仍受 dirty 标记保护。
- 暗光手动调整改为正向退出开关，键 dark_lock_manual_exit，默认 false。生产控制器默认保留新亮度与锁定所有权，到达退出条件才恢复自动模式。明确打开退出开关才归还所有权并维持手动。
- 旧 dark_lock_manual_hold 仅用于校验合法旧配置，迁移到新的默认继续策略；规范导出只保留新键，避免同时存在相反语义的字段。
- 已存在的显式 true 无法判断是用户设置还是旧版写入，继续尊重配置，需要用户关闭并保存一次。该修复不擅自抹掉当前记忆或备份。

## 验证

- 记忆/主题回归 187 项：包含缺字段、显式关闭、显式开启、冷启动已有旧存档却不恢复、界面读取回退、关闭后不写存档及当前会话手动点保留。
- 配置迁移 2483 项：保留明确开启/关闭，旧字段迁移、规范导出与新退出选项往返。
- OTA 核验 18 项：同基准升级保留关闭值，不混用其他基准、后端或用户配置。
- 暗光/亮度控制 307 项：默认手动调整后保持新亮度、达到阈值恢复自动、明确退出策略、自动亮度主动切换优先及旧字段迁移。
- 其余完整回归与原签名/归档核验结果见交付包 build-info.json；本轮没有真机、实际开机存档溯源或功耗测量。
