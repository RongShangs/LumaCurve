# 4.0.2 Beta 04 本地交付复审

2026-10-22。用户要求修复 MIX Fold 3 的“强制达到节点上限”置灰，并打包 4.0.2 Beta 04。仅本地交付，不发布、不部署、不安装手机。正式版仍为 4.0.2 / 40200；日志从该正式版累计，分别保留 Beta 01—04 的变更。

## 接口与路线区分

样本的传统曲线引擎及手动面板均已连接，但户外节点功能一直等待原生输出策略。私有实际固件确认：此结构没有 `DisplayPowerController.getLastSelectedStrategy()`，使用独立 `AutomaticBrightnessStrategy2` 和 `BrightnessReason`；不能把缺少该方法等同于不存在自动亮度。

新增集中适配器 `OutdoorOutputAccess`，仅供户外输出确认使用，不更改全局策略识别及手动面板。原接口（含继承方法）优先；只有它确实不存在时，才核验独立自动对象、默认逻辑屏、同一 ABC 所有权、三个布尔状态接口、当前与待提交亮度原因及修饰位。存在但签名错误、调用异常或备用结构残缺均拒绝，不绕过原接口。原因常量取实际类，特殊亮度和未知修饰位继续退让。

接口支持与当前生效独立：关闭自动、锁屏或未开启增强不会被误报成 ABI 不支持，也不允许实际接管。新路线不能绕过原有户外条件、HDR、系统场景、隐私、温控、电量、HBM 预算与实际输出上限检查。

## 折叠节点绑定与清理

户外 Root 复用统一主屏节点发现；普通主屏保留旧节点和原启动协议。仅实际折叠布局通过时启用独立折叠协作，传入经核验的物理屏 ID 集合，读取当前实际节点上限。运行证据每次读取活跃 DPC 的物理身份，不使用开机自检中缓存的屏幕 ID。

新增带物理身份的 v3 租约，v1 / v2 保留。原生进程将租约身份与唯一点亮 DSI 端口共同核验；切屏时清除旧接管，只有端口与物理身份一致变化才能重新绑定。旧状态不跨屏恢复，节点解析失败回滚原绑定。切屏初期亮度暂为零时允许记录已经确认的绑定，但共享状态机仍等待正亮度及 500ms 稳定期，不会点亮熄灭节点，也不会因只更新一半身份而一直等待。

绑定前后重新检查真实节点、控制器、上限与所有权；写入前后复核点亮端口，切屏竞态退让，真正写失败沿原规则停止。退出时只在当前仍是本模块值且原屏仍有效时恢复。双屏同亮、全熄、证据不一致时不写入。节点增强的目标和时长沿原有设置，不另加会话限制，也不修改节点权限或屏蔽系统输出。

复用既有可选户外守护和显示线程外租约发送，不为兼容新增 APP 常驻进程、传感器监听或额外轮询；未开启户外增强时提前退出。守护在没有租约时等待文件事件，可在确认切屏后复用。此处仅为结构审阅，不能表述为已测得省电。
