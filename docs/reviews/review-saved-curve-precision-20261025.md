# 传统曲线记忆转基础的精度修复

日期：2026-10-25。仅源码修复和验证，不改版本、不打包、不发布、不安装设备。公开4.1.1与已交付4.1.1 Beta 01均不包含此次新增修复。此前节点写入恢复及其他既有未提交研究完整保留。

## 问题与依据

用户截图在“将当前绿色曲线保存为基础曲线”时提示“保存的基础曲线节点无效”。样本使用4.1.1的传统物理映射路线，当前有1个手动偏好点，实际导出的绿色曲线有257个采样点，设备换算范围为2—4000 nit。

绿色曲线高亮平台出现4000.00048828125、4000.000244140625及3999.999755859375等浮点值，相邻点发生极微小回落。最大偏差仅2个float ULP。原SavedCurve构造和范围校验严格拒绝下降/越界，因此UI预检在确认和Root提交前即报错；此分支未保存新基础，也未清除当前记忆。配置中尚无saved_base_curve，与此一致。

使用实际原始状态回放旧生产代码，重现相同错误；修复后同一257点样本通过捕获、JSON往返和中性基础曲线重建。仅3个采样值需要校正，最大改动0.00048828125 nit；全部257个lux坐标不变，其余亮度值逐位保留。

截图中绿色曲线高亮末段到达100%，与其原生学习曲线在本机4000 nit附近形成平台相符；蓝线保留原始自动曲线约1200 nit末端。曲线目标不等于受温控、内容、HBM等保护后的实际输出，不能据截图断言屏幕实测达4000 nit。

## 修改边界

- 只在SavedCurve.capture内、physical_mapping普通活动路线，对新鲜物理nit采样进行精度归一；不按型号、OS或固定nit阈值选择。
- 边界及平台下降容差最多4个float ULP，随数值量级变化；越界或下降超过此范围仍拒绝，累计小下降也不能规避整体单调检查。
- 原始状态数组不改写，全部照度坐标和节点数保留；不压成4点、不替换真实上限、不扩大输出能力。
- CurvePlan、SavedCurve构造与持久化parse的严格校验不放宽；Refactor锚点路线保持原样，分段系数路线仍不允许未验证的记忆转基础。
- 既有HDR、活动物理映射、刷新时效、revision、用户/基准绑定、配置确认及异常回滚继续生效。预检失败不调用apply，不清除原记忆，不重置其他设置。
- 没有新增Hook、监听、采样频率或定时任务；该处理仅在用户主动转存时执行。
