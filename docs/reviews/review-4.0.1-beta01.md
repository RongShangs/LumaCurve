# 4.0.1 Beta 01 复审

2026-10-20。本轮范围为实际单光感移植系统、传统自动亮度过渡及睡前预设说明。仅本地开发和打包，不发布、不操作手机。

## 机制与兼容边界

- 实际移植样本：37 个硬件清单项及系统虚拟传感器中仅一个标准 `android.sensor.light`；没有已验证的辅助照度候选。原生 ABC 的双光感能力为 false，主光感有连续真实事件，暗光锁定已有主光感监听。原生基础锚点读回与用户配置一致。因此不替换传感器、不伪造数据、不强开双光感；仅完善单光感状态和独立能力判定。公开清单不证明物理器件不存在。
- 单主光感路径复用原有 `BrightnessSensorAccess` 和 `DarkLockPolicy`；有真实辅助时依旧双侧确认。无辅助源时不等待不存在的事件；主光感有效性、退出亮度条件、用户控制权和失效退让仍保留。实际未接入与初始化未就绪 / 接口错误分开；未知字段仍作为未知处理。仅展示“未接入”，不展示 0 lux。
- 保存时另有独立验证副本：同一设备 / 用户 / 基准下，之前已开启且参数未改的辅助设置可原样保留，避免新增“不支持”判定挡住基础曲线等无关保存；新开启或修改不支持参数仍拒绝。验证副本不作为存储或运行配置，原能力依旧为不可用。
- `LowLightTuning` 在真实双策略对象缺失时，单独验证原生 ABC 主确认接口；已有双策略存在但残缺时不盲目套用。辅助确认和闸门的能力独立为 inactive，配置裁剪仅修改运行副本，原始 JSON、用户选择和记忆均保留。
- 传统过渡新增 `TraditionalAnimation`，以实际原生策略返回 false、两个 Refactor 时长对象为空、默认屏双 RampAnimator / 属性 / DisplayPowerState / RateController 归属和原生原因记录完整为条件。保留旧 `oem_animation` 路线，新旧互斥；不按机型或 OS 版本放行。
- 速率由原生计算后，在 `setAnimationTarget(float,float,boolean,float)` 调用入口按时长倍率反比调整；目标、色彩与帧调度不改，下游原生最大时长继续裁剪。只允许原生普通自动原因、慢速变化、无特殊速率 modifier，且通过现有用户、主屏、HDR、亮屏和近期手动保护。首次 / 零速率 / 无效坐标 / 其他原因均保留原样。
- 记录只有原生实际采用、未被时长限制另行裁剪的速率；停用或换配置时，只恢复仍等于本次值的字段。原生抛错或后来更新不覆盖；对象和多实例隔离。安装使用事务，查看自检不安装 Hook 或试调亮度。
- 睡前保持仅改说明，预设值和 schema 均不变。不新增定时、日落日出或默认启用功能。

## 证据与验证

私有固件、分析包与反汇编位于忽略的 build/beta-4.0.1-beta01/；分析包按实际运行版本存入工作区 diagnostics。包、签名、源码摘要与旧正式版保留结果在同目录 final-audit.json。维护路线清单、来源映射和生成索引同步更新。

测试入口：`tests/refactor_traditional_animation.py`、`tests/refactor_traditional_animation_firmware.py`、`tests/refactor_single_sensor_firmware.py`、既有高级 Hook、主屏控制、自检、配置、状态、OS3 / 移植 / 折叠回归及完整构建。具体通过数以构建日志及最终审计为准；不把主机或静态核验表述为目标设备实测。
