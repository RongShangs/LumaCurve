# 2.3.0 发布审阅

范围：2.2.0 以来的暗光定时锁定、主屏原生接管、控制中心磁贴与弹窗；此前曲线、记忆、配置迁移和诊断执行原有回归检查。

## 核对与处理

- `release-2.3.0 / 23004` 对照本次用户分析包：强光自动目标已为 1.0，OPR 降至 0.57015526，BrightnessEvent 记载 1060 nit、`automatic [ opr ]`；不能再用提高曲线或泛化范围解决这一限制。OPR 另有 1300 / 1500 nit 状态，因此不硬编码 1060。
- 新增可选 OPR after Hook，只在相同主屏显示线程、自动 SDR 调用栈、`mAutoBrightnessEnable`、非 HDR / 隐私增强且强光门控全部满足时放宽。原方法仍执行，恢复值不超过输入、HBM 可用值及映射值；仅清掉本次新加入的 OPR reason 位，保留原有 modifier。嵌套及异常调用清理线程上下文。不存在背光写入或自动模式切换。
- 配置默认关闭 OPR 放宽，要求高亮范围同时开启；旧配置不暗中升级限制策略，缺接口导入按能力关闭并提示。强光优先只在已验证 OPR 接口存在时启用该选项。温控、HBM 条件与会话超时仍阻止增强，后续电池和省电限制不被恢复覆盖。
- 编辑页灰色系统默认、蓝色可拖动基础；记忆页蓝色已应用基础、浅绿色系统当前曲线。状态只画当前曲线，生效记忆实际改变后浅绿，否则默认基础为灰、自定义为蓝；需要实时记忆证据和曲线差值，不把存档或 OEM 插值误报为记忆。全部曲线使用 2 dp 线宽并适配深浅色。未保存草稿不进入记忆与状态图，未恢复存档只显示空心浅绿点，当前手动记忆为实点。编辑页红字提示记忆影响，记忆页解释两线、点及最终限亮，状态页不增加图例。路径不匹配或缺失 / 异常节点时说明未读取，传统曲线保留全部基础节点。曲线、记忆分类与保存恢复开关没有合并或改变。真实 Android 视觉仍需实机检查。
- 通用弹窗按窗口可用尺寸限制内容区域，标题与动作先测量再分配剩余高度；扣除系统栏、刘海和 IME 并保留外边距，不沿用详情页固定高度。已有单层 ScrollView 展平，数字输入禁用横屏全屏编辑；旋转销毁时关闭旧窗口。主屏面板横屏扩宽并左右布局，短窗口和大字体仍可滚动。这些为布局实现与编译检查，没有 Android 设备进行横屏 / 键盘渲染验证。

- 自动高亮沿原目标、HBM 范围、峰值范围与照度动态范围入口工作，不以手动节点上限冒充自动上限。静态核对三份已有 HyperOS 4 固件：自动目标之后仍执行画面、峰值、温控与电池修正。强光优先预设强度 100%、范围开启、支持时触发倍率 0.5、预算倍率仍 1；不可兼容时拒绝该预设，普通曲线不受影响。
- 修复户外计时状态改变却不触发重算：无新采样时进入、超时与退出也请求 OEM 重算。回归覆盖自动目标为映射上限、HBM 不可用时回落、温控继续限亮、计时释放与预设跨版本校验。没有绕过最终保护或自动写 raw 节点。

- OS 版本检查不借助机型或 Android API 猜测。APP 工作线程在 Root 请求前只读版本属性，已知结果按进程缓存；Root 再核对。OS3 / OS5 / OS40 明确不支持；空值、冲突、格式或读取失败保持未知，不误报权限。恢复 helper 一并携带版本类。
- 温控校验、界面滑条及配置导入范围同步为 38～50℃，默认仍 43℃；回归 50℃ 到阈值退出、冷却迟滞、严重过热退出及旧 45℃ 配置保留。
- 主屏只使用明确的 panel0-backlight，最大值从本机读取；Root 请求和 C 租约均校验整数范围，不把节点单位混同 nit。加入最大节点请求的事务回归，超范围请求保留拒绝行为。
- 主屏正值输出隔离需要接口完整、实例匹配、显示线程、原生就绪、主用户、有效租约、手动模式、亮屏且解锁。无接管、自动、背屏、零 / 未设值和重新点亮第一帧不拦截。
- 打开句柄后才去掉写权限，保持复用；暂停、失联或退出时关闭句柄并恢复原权限。每次写入再次核对租约，不在零节点上强行点亮；系统进程无法续约时退出。
- 锁屏将租约改为暂停，C 释放节点；保留目标待正常解锁。开启自动、切换用户、停用功能或故障取消目标；系统进程重启不恢复高亮。
- 使用 uptime / CLOCK_MONOTONIC 租约，无唤醒锁；锁屏停止暗光传感器订阅，主屏守护暂停时等待事件。两个功能仅在本次使用所需范围内工作。
- 磁贴使用实际 Settings 自动模式和会话所有权，状态改变立即发布，避免内部自动模式字段与限频快照延迟；进入控制中心才注册界面监听。
- 弹窗 Root 通信放在工作线程，连续拖动合并请求；关闭弹窗释放界面查询连接。旧会话响应不覆盖新手势。初始化或接口失败时数值操作禁用；恢复自动保留可用入口。
- 弹窗采用统一行列边距与数字右对齐，独立深浅色配色。按钮反馈限制在圆角内，无阴影；数字输入跟随主题，空间不足允许卡片内滚动。真实 Android 排版、模糊支持与驱动行为仍需手机确认。
- 更新官网及 README 的资源说明，区分自动曲线复用系统与可选原生保持；不沿用旧架构的实测数字。感谢名单由网站 feed 维护，变更不写更新日志。

## 曲线与记忆关系核对

- Refactor `mAnchorLux / mAnchorNit` 是实际当前节点，`mAnchorIsUserDrag` 区分手动点；基础编辑字段与手动点没有混作同一组持久值。`RefactorAdapter.configure` 在改变基础时调用 `resetDefaultSpline`，失败会回滚节点和基础字段。
- 传统后端当前曲线通过实际 `mBrightnessSpline` 采样，包含手动模型与点间插值；不把四个编辑控制点当成完整实际曲线。比较图保留设备完整系统原始节点。
- `HookRuntime.reload` 仅在基础形状改变时重新配置曲线，仅保存户外、温控等其他设置时保留当前手动节点。既有持久化仍核对曲线、用户与固件，不把旧存档强加到新基础；本轮未修改任何保存恢复开关、记忆力度或锁屏策略。
- 曲线设置直接编辑基础，无查看 / 编辑切换按钮。只在用户保存时提交，失败保留草稿；导入、预设、页面切换和深浅色重建继续保留未保存设置。状态图与记忆图使用已应用基础数据和系统当前曲线，不使用编辑中的因素；记忆保存、锁屏恢复与跨重启逻辑未变。

## 保留的限制

没有连接的 Android 设备，未把主机模型或固件反编译核对称为实际执行验证。当前节点值写满与 nit / HBM 模式不是等价关系；没有证据支持修改面板命令或写入越界值。本版保留驱动、硬件与屏幕启停边界。
