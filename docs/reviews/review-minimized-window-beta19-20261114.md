# 最小/挂起窗口亮度与独立亮度重入复审

新增WindowBrightnessAccess和AppWindowBrightness。前者严格核验WM实现门禁、Task根ID、主用户/显示、应用窗口类型、实际小窗服务最小/贴边谓词及模式事件；后者只把原生已允许的候选改为拒绝，使用独立默认关闭的suspended_window_brightness。原AppBrightnessIsolation源码/旧路线保持原字节。开关位于原同步隔离页独立卡片，原生已隔离不会强制开启新功能。

门禁Hook先保留原生false/异常，候选来源和主屏用户核验在持有WM锁时完成。无焦点/尺寸推断，无LayoutParams/亮度/模式写入，无定时轮询。配置或小窗模式事件在WM handler合并一次原生遍历；退出/关闭移除所属规则，重新选择其他窗口或系统，不重放窗口值。必要两Hook事务安装，残缺ABI拒绝，调用损坏保留原生并报告，不降级绕过保护。

私有三份固件原生RootWindowContainer先验证屏上可见性，再调用shouldApplyOverrideBrightness，逐帧清空/重建候选表并发出克隆消息；原手动覆盖记录在原生实现保留。服务提供明确的isInMiniFreeFormMode/inPinMode，未将Android正常PiP当作最小化。83项静态证据只证明消费与ABI，不是真机小窗效果验证。

独立亮度问题由实际控制器回归复现：模块离开应用恢复自动亮度，provider回调延迟后busy已经释放，被误当用户操作而给仍可见的小窗添加豁免，最大化后仍无法接管。以有界自写通知队列识别模块回调，并保留不同最终模式和显式控制中心操作。覆盖先后两笔模块通知都延迟的合并读场景。任务onConfigurationChanged只在模式确实变化且有订阅者时排队现有前台查询，完整TaskInfo模式ABI提供全屏准入；缺整个可选ABI保留旧焦点路线，已匹配但读取失败不冒充全屏。

主机：窗口门禁47项、开关/升级27项、控制器679项（包含小窗最大化、延迟回调、用户自动优先及旧控制器回归）、独立亮度117项、原隔离79项、配置3175项、自检448项、页面/跳转与原高亮223/31/152项。三份负向副本分别取消最小窗口过滤、取消最大化事件、恢复误判自写通知，编译后均被实际运行断言拒绝。

完整构建、原签名、197份编译源码、随包最新感谢名单、源码/完整包和历史交付指纹核验见build/minimized-window-beta19-20261114。独立研究、普通/高亮曲线及学习、Root映射恢复保持原字节。仅本地，不发布或操作设备；实际小窗/贴边/恢复、显示观感和功耗待回访。
