# 默认行为排查 · 2026-10-19

范围：用户纠正暗光锁定应默认关闭，并要求默认尽量与原机一致。本次只修正源码与验证，不重新生成或替换已交付 Beta 01；源码预留 4.0.0-beta02 / 40002，后续打包继续递增 Beta 标识。

## 发现与修改

1. `BrightnessControlOptions.darkLock` 构造默认值为 true，APP 无有效启用配置时会使用这个构造器，第一次保存会一并启用锁定。改为 false，普通解析、缺省旧配置与新草稿一致。`bedtime()` 是用户主动选择的“睡前保持”，改为显式 true，避免改变构造默认值后使预设失效。
2. `LowLightThresholds()` 构造默认值为 true，但 JSON 缺字段解析为 false；它还受默认关闭的“暗光稳定”门控。统一构造值为 false，消除未加载配置时的隐式预选。现有显式启用的阈值和“暗光少动”等预设保持原样。
3. 构建报告 `dark_lock_default` 同步 false，防止实现和元数据冲突。原 Beta 01 的报告仍记录当时 true，不能将源码修订说成旧 APK 已变更。

## 其余功能的核对

已核对 APP 字段、缺省载入、Root 提交、运行期配置解析及各控制器进入门槛，完整矩阵见 [默认行为约定](../guides/default-behavior.md)。户外各开关、节点增强、温控调整、确认与过渡覆盖、场景自定义、额外记忆保持和应用暂停均默认关闭或跟随系统。预填数字不等于功能启用。

手动记忆默认 100%：Refactor 的 `HookEntry` 和传统 `TraditionalHooks` 都将原始 desired 参数原样传给原生方法，仅小于 100% 时调用额外分组 / 强度策略；0% 会拦截原生锚点更新。因此保留 100%，不能为“所有开关关闭”而禁止系统原有记忆。分组时间和照度半径在 100% 直通时不调整原生输入。

主屏手动亮度的可用开关仅允许用户打开工具、发起带会话标识的接管命令，不会因默认 true 自动写亮度或启动节点控制。默认空应用名单、关闭节点映射、未启用临时常亮也不会主动接管。恢复的同场景检查等安全条件仍保留。

没有修改配置 schema、默认曲线倍率、原生曲线坐标、旧路线选择及用户已保存的开关。无法区分旧版自动保存的 true 与用户主动开启的 true，因此不强制把已有配置改为 false；用户可主动关闭并保存。
