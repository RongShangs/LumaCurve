# 比例曲线首次提交顺序修复

日期：2026-11-03。基线为公开 4.4.2，累计 Beta 01—02；本轮只交付本地 4.4.2-beta02 /44202，不发布或操作手机。

## 实际反馈和复现

笙歌醉梦红尘制作的 Redmi K50 电竞版 4.0.5.0 移植包回传 Beta 01：引擎已 `attached/simple_mapping`，主辅光感等独立接口已报告，三次应用失败后回到未保存配置。141 个归档条目已按机型私有校验，55 份随包 JAR 与上一样本逐字节相同。

旧导出只有外层异常，缺少嵌套原因。源码显示 `reload()` 先验证配置 `user_serial`，调用 `kernel.configure`，之后才写 `boundUser`。比例曲线在同步重建回调内却要求 `appliesToUser()`；首次 boundUser=-1，因此跳过新基线并触发“系统未采用比例曲线”。原主机替身默认用户匹配，漏掉首次配置的未绑定状态。

以生产 `ForegroundUser.matches` 代替恒真用户替身，保留原提交顺序，Beta 01 代码可重复复现同一外层失败及底层验证错误。记录在私有 `build/beta-4.4.2-beta02/reproduced-beta01.log`；这证明实现存在此错误，不把缺少 cause 的用户日志表述成已排除其他全部异常。

## 修复与归属

`SimpleCurveAdapter` 内部建立同步事务用户作用域：公共管理已验证配置归属后，适配器捕获实际当前用户；仅该事务的显示线程/对象回调可使用新基线。当前用户再次核对，负数不执行，提交中切换则回滚；finally 撤回临时许可，事务外继续检查已绑定配置用户。公共管理不提前绑定，不改其他后端的权限判断。

保留原始数组身份和值、完整原生样条、学习、全节点转存与失败回滚。追加有界底层异常说明和 `simple_curve_last_error` 诊断字段；没有新增路线、模型/版本白名单、线程、进程或周期任务。旧兼容与保存偏好保持。

## 验证

- 旧代码失败对照，修复后首次非默认应用、首次保存的完整基础曲线提交通过。
- 事务期间无已绑定用户仍能按已验证当前用户执行；返回后临时许可消失，原生未调整查询重新遵守正常用户归属。
- 未知用户不写、不重建；提交中用户变化撤回，异常和恢复后作用域均清理；嵌套错误可导出。
- 全部原物理曲线及原生学习回归、108 节点私有样本、完整兼容契约和打包检查。精确产物、签名与旧文件核对保存在本轮 build 目录。
- 新设备只验证过 Beta 01 的接入及失败反馈。**Beta 02 未做目标设备 Android/ART 验证、长测或功耗测试。**
