# 放宽后高亮曲线研究与本地实现

用户要求基于手头分析包尝试实现，随后明确目标为“可调节开启强光下放宽画面限亮后的亮度曲线”。本轮只交付本地4.5.0-beta01 /45001，不发布、不安装或主动调整手机；独立研究和旧交付保留。

## 样本与结论边界

扫描本机私有归档中的39份outdoor-state，18份开启OPR，只有一份有实际放宽计数：用户确认RedmiK100 Pro Max的2026-10-22历史包记录opr_adjustments=62，保留轨迹中能看到原生1.0被OPR降至约0.5188/0.5493再由模块恢复的事件。其导出时已经回到低照度，不能当作新功能验证；该机也未被认定为Issue #5报告者的设备。

已核对os41、os28与k90pm私有原生SDR消费者。OPR是画面灰阶/照度条件下的限亮逻辑，其后还存在画面修正、阳光目标合并、峰值/温控/电量等处理；只在OPR内部调节一个值可能被后续目标合并覆盖。没有把灰阶—nit表说成原生照度—亮度曲线，也不因映射端点更高就宣称设备可持续达到该值。

因此第一版增加明确的“高亮上限包络”，不重写未知原生高亮曲线。它在整个原生SDR调用结束后，只对已经执行过本实例OPR消费者的自动SDR帧进一步限亮；原生动画仍接续正常返回值。普通段保持，其他保护的较低结果保持。

## 实现及保护

- 默认关闭、节点为空，旧配置不开启。物理nit节点按递增整数lux、非递减正nit严格校验，2—16个节点启用；照度间线性插值，端点外用端点值。图只表示用户的上限包络，不假画原生曲线。
- 复用当前主屏原生convertBrightnessToNit及既有受校验反解器，区分普通边界与全映射范围，不混用逻辑nit、物理nit和背光比例。低于普通上限的目标只约束到普通边界；原生结果更低时不抬升。
- 复用既有两/三参OPR与四/五参SDR事务Hook，不新增输出循环、线程、计时或节点程序。调用帧核验owner、自动状态、显示线程、隐私/HDR、户外准入、真实OPR调用、配置对象及HBM对象；异常和嵌套调用恢复ThreadLocal，无OPR消费者的帧不应用。
- 强制节点输出会绕过框架目标，与曲线互斥：先确认再切换，取消不改变旧选择；确认前重新核对能力与条件。既有静态nit上限仍可进一步限亮，关闭曲线恢复原画面放宽路径。
- 原配置、节点和启用意图可保存为休眠设置。能力丢失或前置条件不足只在运行副本关闭；导入、预设、系统默认等不清空节点。Root工具包含OutdoorOptions内嵌曲线类型，避免工具侧缺类。
- 新自检opr_curve与旧OPR/nit上限独立显示，需有真实高亮区间及可靠物理nit映射；状态记录节点、限亮计数、最近目标与失败原因。型号不参与放行。

## 验证

运行模型706项保留原662项，新增原生目标在36klux已固定2000nit而曲线设60klux到2000的场景：36klux结果约1644.8nit，60klux才达到2000；OPR后重新合并更高目标仍被最终包络限制。覆盖较低温控/电量/省电结果、普通/DIM输出、HDR/隐私/手动及直接OPR调用、无OPR消费者、换配置、失效映射、缓存和关闭恢复。它是确定性服务模型，不是真机nit读数。

修改前实际OPR Hook替回同一夹具可正常编译，原662项保留后在新增回归case685失败；证明新检查能识别原路径缺少该约束。旧ABI兼容1292项继续通过。UI18项执行实际编辑/开关/弹窗方法，覆盖添加、编辑、删除、少于两点自动停用、旧视图回调、互斥确认/取消和能力变化；不是Android像素测试。配置3083项验证导入、无能力保留与预设不丢节点。
