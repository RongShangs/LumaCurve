# 3.1.0 Beta 01：应用名单与多窗口

## 问题与处理

旧实现使用 ActivityTaskManagerService.mLastResumedActivity，浮窗获得焦点就误认为离开名单应用。现在由焦点和 ActivityRecord.setVisibleRequested 的实际变化触发刷新，读取主屏可见任务；优先使用 isVisibleRequested，缺少时使用 isVisible。仅匹配主用户、主屏和可见任务的顶层应用，不把后台进程或隐藏的最近任务算作正在使用。

不持有 WM 锁调用服务、设置或亮度接口。窗口回调只传身份或失效通知；显示线程合并事件并异步提交查询。一个按需工作线程，队列最多 8、单次最多 128 任务，空闲 10 秒退出；不添加轮询。3 秒查询期限释放应用接管，过时响应不覆盖新事件、不取消新查询的期限，息屏或停用使迟到结果失效。

当前应用接管在等待合并刷新期间保持，屏幕、用户、主屏及解锁资格仍即时检查；最终可见名单为空才恢复。主动开启自动亮度的豁免保持到相应名单应用不可见。多窗口 ABI 不完整时退回原焦点功能并在设置中提示，未强行适配或按机型判断。

## 验证

- 控制器实际代码与 Android 服务替身回归：340 项，新增小窗、分屏、多名单应用、焦点不变的显隐、隐藏任务、用户/显示隔离、主动自动亮度、查询竞态、异步超时及晚到结果。
- 两份用户提供的系统框架与一份框架 TaskInfo 元数据：29 项静态核对。记录只保留于忽略 build，不分发固件或反汇编。
