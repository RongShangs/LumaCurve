# Beta07/08：名单页闪退、启动初始化与说明复审

## 输入和确认事实

用户提供pandora／25098PN5AC、OS4.0.6.0.XBLCNXM的Beta06分析包。输入、固件和完整日志留在按设备分类的私有诊断目录，不进入公开源码或产物。

- 三个应用管理入口共同进入ApplicationListActivity；崩溃堆栈明确为PhoneWindow内部DecorView为空，发生在系统栏控制器读取。Beta06在setContentView前访问该接口。
- SystemUI多次因发布内容Provider超时被结束，目标进程已经退出，未取得其主线程栈；system_server显示线程转储处于消息等待，未见HyperLux阻塞调用帧。包中独立亮度及暂停名单为空、无亮度接管。不能从同时发生推定新增独立亮度导致SystemUI超时。
- 源码仍存在SystemUI启动线程同步注册观察器/广播的等待风险，移入原有有界后台线程。此为模块侧阻塞风险修正，不等于已确认该机根因或锁屏加载问题已消失。不禁用锁屏、不伪造解锁状态、不新增系统亮度接管。

## 修复与保护

1. 名单页先安装窗口内容，再取系统栏控制器；控制器为空时保持默认外观。搜索、图标、批选、迁移确认、已保存选择与组ID不变。
2. SystemUI绑定只发布上下文及排队。后台完成观察器和广播注册，失败移除部分观察器并最多尝试3次；就绪前映射不参与，系统原生和锁屏行为保留。
3. 简介以阻止应用窗口调整同步到系统亮度偏好开头，保留非控制中心操作、视频与付款码例子，明确控制中心主动调整仍按原设置处理。

4. 独立亮度输入观察按需延迟到实际接管；引擎启动、自检和旧租约恢复只探测ABI。用户确认启动延迟仅在升级Beta06后出现，继续作为本版回归处理，不归因于其他模块。

## 验证边界

控制中心回归用阻塞的Provider注册替身确认启动调用立即返回且注册不在启动线程；另检查失败清理、三次上限及未就绪的原生回退，保留旧ABI和手势回归。完整构建、签名、名单、源码及历史交付核对见build/boot-picker-fix-20261110。尚无Beta08同机重启、锁屏或界面真机回访，不宣称完成这部分设备验证。
