# K90 Pro Max 内部排查包说明

当前提供 **2.4.0 内部测试版 r18 / 24018**，沿用原签名，未公开发布。最新反馈确认 r15 仍可能在点亮、解锁时卡住并触发系统框架自动重启。**根因尚未确认，r16 增强诊断，r17 进一步移出显示线程中的状态写入等待；r18 将记忆恢复排到当前曲线计算返回之后，并补收小米专用故障记录。这些属于预防性修复，不能宣称卡死已修复。**

## 尽量减少用户操作

已有包由开发侧继续分析，不要求对方反复复现、切换功能、执行 ADB 命令或频繁更换测试包。无需为本轮排查立即升级或再提供一次包。

后续按正常更新安排采用 r18 时，可同签名覆盖安装、保留配置，并在方便时重启加载；关于页构建为 `internal-2.4.0-r18`。正常使用即可，不安排故障复现任务。

如果日后自然发生故障、用户愿意提供记录，恢复正常操作后一次导出分析包即可；方便的话附上大致时间和是自行恢复还是手动重启，不必再填写机型、系统与构建号，这些会随包采集。若故障仍未恢复，不要求现场抓包。

## 同一次导出包含什么

- 崩溃、系统故障、进程事件和五类系统保留的 DropBox 条目，修复过去漏查当天记录的问题。
- 小米 Watchdog 文本和 Binder 调用链文件，同次导出，不收堆转储。
- 最近 72 小时的原始 ANR / DropBox 文件，优先最新，最多分别 6 份、10 份，单文件上限 8 MiB；不可读、缺失和超限有明确记录。
- 原有的运行状态、配置、模块日志与显示固件；采集有总时限与体积预算，仅在导出时执行，不新增常驻监听或改变亮度。

已导出的 ZIP 保留在磁盘。系统恢复后保存的故障记录可能仍在，logcat 和内存历史可能已丢失；系统未保存或已清除的内容无法补回。一次导出会尽量收全，仍不能保证拿到故障时的线程栈。
