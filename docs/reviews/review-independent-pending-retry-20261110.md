# 独立亮度待处理输入与记忆读取复审

目标为本地4.4.5-beta14 /44514，构建beta-4.4.5-14。用户仅授权修复此前评估的前两项；本轮不调整配置导入、能力校验或审阅报告提出的其他问题。不发布、安装或操作设备，全部历史交付与保存配置保留。

## 已复现的问题

1. 原控制器延迟180毫秒合并真实手动调节。快速返回桌面或换到另一独立记忆键时，取消任务但没有把最后一次有效输入存回原键；前台查询超过等待期也会漏记。跨锁屏开启时，屏幕事件先推进代次，同样丢失末次候选。单次输入已正常合并的普通路径不受此缺口影响。
2. 存档读取提交被执行器拒绝时，原代码直接标记loaded=true，之后不会再读取；正常执行器恢复也需要再次改配置才能触发读取。该故障通过注入拒绝实际复现，不代表已经证实用户设备发生过线程池拥塞。

两个修改前负向副本均使用Beta13实际控制器：原有599项通过后，新增的快速退出与拒绝加载断言分别失败，编译正常。记录保存在私有build/independent-pending-retry-20261110，不随源码交付。

## 修复与边界

- 将待处理输入绑定到原记忆键、来源应用、模式租约、配置签名、物理绑定及时间。换键或退出前只补存有效输入，不能落到新应用/组，不向离开的应用补写屏幕值。同组连续快速切换仍归原组。前台查询尚未完成时保留候选，原生单次模式交接也让真实候选优先。
- 锁屏立即冻结输入并取消调节任务；原生屏幕Hook只操作内存和投递任务。跨锁屏开启后在原生锁栈外复核用户、租约、物理屏、普通范围、HDR/温控及输入时效，再补存；重复通知和直接屏幕接收路径不会丢候选。默认清空不变。仍属于本租约的最后输入可用于识别恢复责任，恢复基线并清理原生待处理设置后才交回原自动模式。
- 拒绝提交不标记已加载，同一绑定最多尝试3次，后续间隔250/1000毫秒。等待期间不会随控制tick重复提交；耗尽后保留原生控制及明确状态，不永久轮询。锁屏取消计时，离页/用户/配置/停用和旧代次不能提交或接管；新合法场景可使用剩余次数。
- 尚未读出的持久记忆不会被空快照覆盖。成功读取后解除等待状态，配置和物理绑定仍按既有协议核验；显式关闭保留的清理语义不变。新增加载状态仅用于诊断，不增加页面功能。
- 保留全部既有ABI、付款码和窗口排除、HDR/严重温控、外部后写优先、原生学习保护、节点映射和原生raw12载荷；生产运行修改局限于AppIndependentControl，另有版本标识递增。
