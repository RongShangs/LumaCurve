# 3.0.1 Beta 01：户外 SDR 接口兼容审阅

## 证据与范围

两份用户包的 device 均为 myron / 25102RKBEC。支持包的系统版本为 OS4.0.0.33.XPMCNXM、模块 3.0.0 / 30002；不支持包为官改系统，显示 OS4.0.0.25.XPMCNXM、模块 3.0.1 / 30005。3.0.0 与 3.0.1 的 OutdoorOpr 相同；根因为固件接口布局差异，不能归因于版本号或机型本身。

支持包字节码有 shouldUsePrivacyOprBrightness；不支持包没有任何 privacy 符号，但有完整旧 OPR 灰阶表、HDR 检查和 nit 换算。旧包日志中目标 1.0 被普通 OPR 限制到约 0.501；温控和电池在该次链路没有继续降亮。归一化坐标不等于 nit 百分比。

## 互斥选择与保护

新增 OutdoorSdrScope，按实际 Class 对象缓存不可变路径（包含类加载器身份），同时供 OutdoorOpr 与 nit 上限使用。

- privacy_aware：存在完整 boolean 无参防窥接口时优先选择；每次使用仍检查防窥和 HDR，异常不切换路径。
- legacy_opr：只有完整旧 OPR 方法、实例字段和显示配置类型符合时接入；继承层级中出现 privacy / uhbm / boost multiplier 等不完整新实现线索时拒绝回退。
- unsupported：类型不匹配、保护接口不完整、未知布局等保持系统控制，不安装放宽/上限 Hook。

旧路径运行时还检查 OPR 可用状态、显示配置、合法灰阶、照度阈值与最大 nit 参数，以及严格递增的 N 个灰阶分界和 N+1 个非递增正 nit 值。这个 N+1 结构来自真实系统的最后一档灰阶处理，避免将有效设备错误拒绝。

继续使用原有主屏/线程/用户/自动 SDR/强光策略/输出归属约束。OPR 仅恢复该次画面限亮所降低的部分，受实际 HBM 允许范围约束；后续温控、电池等不变。独立 nit 上限在前后阶段只降不升。现有 ThreadLocal 帧恢复和亮度原因位保留逻辑保持。

Hook 安装同步去重，OPR 部分失败撤销本次安装；同一类的两功能共享同一个 scope 实例，没有按固件字符串选择或运行中降级。诊断增加 sdr_compatibility_profile / sdr_compatibility_detail。

## 验证

- refactor_outdoor.py：现有生产 Hook 模型 512 项。
- refactor_outdoor_compatibility.py：8 种 ABI 模型、新旧共存、类加载器隔离、多线程路径解析、不同控制器实例、重复安装、异常保护和原生下游限制共 1272 项。
- refactor_outdoor_compatibility_firmware.py：两份用户实际字节码与真实灰阶表 43 项。
- 完整构建继续执行既有配置、记忆、线程调度、状态、恢复、界面与签名检查，以 build-info.json 为准。

以上不是目标设备实测。本轮无 ADB 设备，没有操作手机或验证强光最终 nit。原正式 APK 与线上发布保持不变；新增私有固件、反汇编和用户包不分发。
