# 4.0.1 Beta 02 复审

2026-10-20。仅本地修改和打包，不发布、不操作手机。累计保留 [Beta 01 复审](review-4.0.1-beta01.md) 的单主光感与传统过渡实现，本次新增可选夜间暗光范围。

## 实现与归属

新增 `DarkLockSchedule` 集中适配实际 `LocalServices` / `TwilightManager`、`TwilightListener` 和 `TwilightState` 的返回类型与非静态方法签名。通过系统原生 `sunriseTimeMillis()` / `sunsetTimeMillis()` 获取时间戳，当前时刻必须在它们界定的日间或夜间窗口内。数据缺失、已过期或调用失败时等待；没有固定 18 点 / 6 点回退，不用深色模式充当日落，不按机型和系统版本选择。

日落只开放暗光条件的判定：复用原 `DarkLockPolicy` 的照度、持续确认、真实单 / 双主辅来源及手动调整方案。日出或时间失效时，只释放模块持有的 dark 会话；用户手动模式、应用暂停和节点手动面板均保留各自控制权。白天不注册暗光锁定光感监听。时间服务异常不将原暗光控制标记失败，也不删除保存的夜间偏好。

只在用户明确启用夜间范围、当前用户 / 主屏亮起时注册系统共享 twilight 通知；复用显示 Handler 与单个边界回调。系统时钟 / 时区事件重读原生时间；熄屏、停用清理监听与边界。系统服务未就绪最多三次一分钟补试，后续亮屏可重新检测，旧代际回调不能恢复监听或改变亮度。注册异常撤销本次 listener。系统 TwilightService 自身可能按其实现使用系统位置；模块不自行申请定位、不新增定位器、进程或唤醒锁。功能自检只检查接口，不注册 listener；状态读取只消费已有窗口，不重新计时。

新增键 `dark_lock_sunset_only` 默认 false，不从旧“睡前”名称推断 true；旧 dark_lock_enabled 和阈值原义不变。解析严格校验布尔类型，序列化、导入导出、同值比较均覆盖新字段。全天预设明确清除夜间范围，夜间预设明确启用；其他独立设置不受影响。暗光锁定本身依旧默认关闭。

路线登记于 CompatibilityCatalog 与 compatibility-manifest，新增生产文件登记 source-map，兼容索引重新生成；旧 compatibility-baseline 不修改。自检将接口支持、用户启用、有效时间与实际锁定分别报告。

## 验证

实际移植与 K90 固件样本 services.jar 共 12 项静态确认系统 TwilightManager 的三项方法及 TwilightState 的两个 long 时间戳 getter；反汇编仅保留于私有 build/beta-4.0.1-beta02/twilight-redmagic。

主机测试运行实际 adapter、controller 与 service doubles，覆盖全天 / 夜间、日落后暗光确认、日出释放、日出不恢复用户手动模式、空 / 过期时间、读取 / 注册失败撤销、有限补试、熄屏清理、旧 listener、只读状态、缺接口、错误服务对象，以及旧单 / 双 / 折叠 / FOV 来源与所有权回归。配置回归覆盖新键默认关闭、显式保存、导入导出、能力缺失后保留范围和非法类型。原有整套兼容与保护测试继续执行。

完整构建、原签名、版本、源码及旧产物保留结果以私有 build/beta-4.0.1-beta02/verification.json、build.log 与 final-audit.json 为准。尚无本轮真机日落日出、位置变化和功耗长测，不表述为全机型测试通过。

对应主机回归：亮度控制 513 项、配置 2719 项、自检 349 项、兼容展示 1133 项通过；完整只验证构建通过。最终完整打包会再次核验当前源码与原签名，不以静态接口匹配代替真机结论。
