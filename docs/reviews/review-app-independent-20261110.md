# 应用独立亮度与隔离还原复审

## 范围

按2026-11-10用户授权实现互斥三块名单、最多三个共享组、旧暂停配置接续、统一二级选择页及隔离页还原；本地递增Beta04后，按新增确认要求递增Beta05，再修正手动输入来源边界递增Beta06。此前未完成的窗口重放草稿已私有备份，不带入新包。无服务器发布、安装或设备操作。

## 关键边界

- 旧暂停名单不换键、不按可安装列表过滤；默认空的独立名单/分组及关闭的保留开关不会自动接管。保存配置与能力裁剪副本分开。
- 暂停名单按旧可见任务语义；独立名单仅当前同用户主屏焦点，避免PiP或桌面误套用。模式租约沿用BrightnessControl，用户手动开启自动亮度优先。
- 记忆来自原生手动输入，不从窗口覆盖、付款码、实际输出或HDR采样。原生窗口同步写回在独立租约内也被隔离，独立值仍受原生范围和温控限制。
- 只恢复模块仍拥有的系统首选值和模式；不同物理屏、后来的写入和过期手势不覆盖。系统进程重启时核对同设备、用户、物理屏及恢复意图。
- 跨重启记忆按设备基线/物理屏/用户校验；读写离开显示线程并按代次失效。不新增轮询、驻留服务或传感器采样。
- 原生已隔离显示开启，不伪装成模块Hook生效，不写回默认值；旧共享字段保留但不执行。
- 系统应用分类仅作附加选择线索，未分类应用可手选；存在但损坏的专用文件不换路径猜测，Android独立分类仍可用。全部名单合计64项，与旧上限及配置通道约束一致。

- 跨名单迁移先生成只读计划，确认后自动关闭旧选择，取消不改原状态；批量迁移一次确认。已确认后关闭新选择仍保留旧处移除，结果原子提交；过期计划拒绝，旋转保留已确认记录。

- Root工具归档须包含BrightnessControlOptions的分组内嵌类型；APK生成前仅使用实际Root工具类归档执行分组配置测试，完整APP类路径不得掩盖缺依赖。

- 手动输入以原生入口及调用帧作为来源证据，不把“窗口正在显示”等同于“输入由窗口发起”；普通控制中心调节在播放页也可记忆，窗口调用帧、HDR和极端输入不采集。

## 验证

生产控制器旧543项回归通过后新增独立接管/恢复、分组、记忆、屏幕、手动接管、持久化、重启恢复及另一写入者检查。独立配置/策略/分类/ABI检查涵盖迁移、互斥、最大组数、损坏结构及事务安装失败。隔离保持旧路线和原生无同步零Hook；新增独立观察是独立事务。
