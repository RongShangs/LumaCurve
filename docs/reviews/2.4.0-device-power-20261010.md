# 2.4.0 r13：真机功耗路径与持续观察

构建 `release-2.4.0-r13 / 24013`。本轮沿用既有需求、默认采样间隔、暗光进入/退出时间、场景条件与正式签名。

## 基线

2026-10-10，ADB 连接的 pandora / 25098PN5AC，Root 可用；安装和系统实际运行均为 r10。原配置关闭暗光锁定、关闭持久记忆，自动亮度开启，手动节点面板未接管，场景沿用系统。所有私有原始记录在忽略目录 `build/device-power-20261010/`，不随源码发布。

原配置下，模块光感监听为 false，主辅样本计数为 0，sensorservice 无模块活动订阅；不能将系统/其他应用的光感或整机 system_server CPU 全部归因于模块。系统存在 DaemonSensorPolicy、DualSensorPolicy、DozeAutoBrightnessController 等独立订阅，不改写它们的采样策略。

临时仅启用暗光锁定进行基线检查：模块主、辅订阅均请求 1,000,000 微秒；实际传感器为非唤醒、按变化上报。稳定光线窗口中，主辅只收到初始样本，不能把 1 Hz 请求解释成实际每秒固定回调。原配置随后已按原字符串值恢复，JSON 完全一致。

USB 连接、充电、系统 StayOn 和 ADB 本身会影响功耗。这里验证的是订阅、调用次数与退出清理，未得出续航提升百分比或整机省电量。

## 实现

- 暗光锁定关闭且未持有暗光所有权时，直接清理模块监听并返回，避免无意义的 PowerManager/Settings 检查。已有暗光所有权仍走原退出流程；手动节点模式先经过原安全检查。
- 户外增强关闭时，曲线目标直接使用系统值，不进入户外 binding/省电模式/场景检查。启停时的 HBM 归还仍由 configure/stop 完成，不将停用分支直接跳过清理。
- 主辅光感每次回调仍记录最新值、时间和样本数，稳定的同批事件合并为原显示线程下一轮的一次判定，不额外添加等待。新增诊断计数 `watch_evaluations`，与样本数区分；`watch_requested_period_us` 明确是请求值。
- 无效数据、暗光进入确认被高光中断、退出确认被暗光中断，仍立即判定，不能被合并吞掉。保留 1 秒采样请求、原确认期限、非唤醒监听、息屏注销及全部解锁保护。
- 状态页原先已有 1 秒说明缓存，保留现有实现。本轮不以动画帧数推断后台采样率。

## 持续采集

`tools/observe_device_runtime.py` 默认每 5 分钟记录一次，默认最多运行 7 天；只读取现有状态、system_server 计数和电源摘要，不主动刷新状态、不注册传感器、不唤醒屏幕、不安装或重启。原始状态过期不等同于卡死：稳定光线或息屏下可能没有新发布。

结果保存在忽略目录，最多保留 7 个每日 JSONL 文件；`latest.json` 保存最近结果。在输出目录创建 `STOP` 文件即可停止，最多约一轮 ADB 超时加一秒检查延迟。观察器不是自动代码修改器；当前会话未提供自动化唤起工具，不能承诺聊天结束后自动审查、改代码或发布。重连后的后续迭代应先读取这些证据。

本轮采用的传感器语义见 [Android SensorManager](https://developer.android.com/reference/android/hardware/SensorManager#registerListener(android.hardware.SensorEventListener,android.hardware.Sensor,int,android.os.Handler)) 和 [AOSP 上报模式](https://source.android.com/docs/core/interaction/sensors/report-modes)：请求速率是提示，按变化上报不等于固定周期轮询。

## 辅助光感显示 0 的补充调查

用户明确表示辅助读数长时间为 **0 lux**，与“等待采样”不同。r10 与 r13 的 sensorservice 订阅历史均显示 OEM DualSensorPolicy 请求 250000 微秒，额外暗光监听仍为 1000000 微秒；未降低采样频率。检查时 OEM 辅助读数有效，近期环形历史包含 3 → 0 → 12 → 124.5 → 192.7，零段约 218 毫秒。该短窗口不能重建用户所说的较长等待；不把硬件零值、滤波保持、状态刷新滞后混为缺少监听。当前辅助等待门控 holds 为 0，不能将本次零值归因于该门控。此门控只推迟满足条件的主光感增亮，并不改写辅助原始读数。
