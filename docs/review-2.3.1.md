## 本轮修复

1. **保存完成覆盖新草稿**：原完成回调无条件清除 dirty，随后读取已应用配置，导致用户在等待期间新改的选项被覆盖。现在按提交的选项与当前草稿逐键比较，仅一致时清除未保存状态；比较不依赖 JSON 键序及数值装箱类型。无效新草稿仍保留，不因比较失败清除。
2. **暗光锁定转手动失败后不恢复自动**：先 relinquish 再读取 auto，遗失了由本应用暂停自动的事实。新增回归在原代码上复现失败；现在先捕获暗光或原手动会话的自动模式所有权，失败 / 守护失联时恢复原模式，用户本就主动关闭自动时仍不开启。
3. **接管确认丢失未立即回滚**：system_server 已关闭自动但 Root 未收到 ACK 时，原调用在事务清理外抛出。新增回归模拟成功切换后丢失 ACK，原代码复现失败；现在对未确认事务发送当前会话 abort 和带 token 的 STOP，拒绝响应与其他会话保持原边界。
4. **旧健康记录长期有效**：旧记录仅包含 token / active / errno，守护被杀或停滞后可能长期被视为健康。新记录增加 CLOCK_MONOTONIC / uptime 时间，原生每 2 秒更新，Java 接受不超过 5 秒且非未来的记录；失败通过现有续约退让，过期租约仍阻止输出隔离。原生身份升级为 raw06-health，socket 名维持原有协议入口，Java / C 同步更新。无每帧文件查询、无唤醒锁，自动模式无新增进程。
