## 路线决定

停止重复同类升降探测，进入核心输出边界适配。
临时策略已有短时/一分钟实机输出和清除证据，尚未证明无需仲裁即可长期替代所有系统场景。
优先用框架请求输出，取消该后端的 sysfs 锁与逐帧开关；旧后端保留用于回退和其他设备。

第一版状态机位于 experimental/framework_output/LumaFrameworkOutputSession.java：
显式单位、有限值校验、序列、短租期、实时范围钳位、自动/手动/未知模式仲裁、
熄屏/窗口覆盖让权、过期/失败释放，以及未确认释放时禁止再接管。
算法目标、范围限制后的请求、基础/adjusted 字段和节点读数分别存储。
这只是输出边界模型，本地 12 项测试通过，尚未接入 C 主循环或正式模块。
租期需要宿主周期性 tick，并需要独立退出恢复进程；模型本身不解决 JVM 被杀后的恢复。

## 集成前必要读取

原维护核心 refresh_settings 仍调用 settings shell；旧 app_process Settings 入口因未注册
IApplicationThread 失败。可靠自动/手动退出与学习都需要有效 mode/auto_adj/slider，
不能把 null 或读取失败变成手动，也不能一直当自动并压过用户手动模式。

framework05 只读包尝试 ActivityManager.getContentProviderExternal + Binder token，
直接调用 SettingsProvider 的 GET_system，再移除外部引用；不使用失败的普通 Context 入口。
该新路径权限和返回值尚待本机验证。若失败，保留完整异常，输出适配不默认启用。

API 单位读取不是光学标定，只用于明确本机声明的单位，不能把它宣传为绝对测量。
