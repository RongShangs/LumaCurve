# 占用分析与实机复测（本地候选 lean01）

实机基线由用户的 Root Agent 于 2026-09-30 采集，属于单台 HyperOS 4 / 小米 17 Pro 的运行样本，不代表其他设备或 24 小时平均值。broker `dumpsys meminfo`：PSS 56,658 kB、Private Dirty 55,312 kB；其中 Dalvik Heap 13,560 kB、`.art mmap` 24,846 kB。C 核心 PSS 约 9.4 MiB。60 秒窗口的单核 CPU 占比：broker 0.862%、C 核心 0.133%、两个主要监管 shell 约 0.265%。RSS 跨进程相加会重复计算共享页，不用于总占用。

`.art mmap` 的私有脏页是独立 `app_process` 运行 ART 的重要成本，但不能仅凭映射名断定改成 zygote 子进程可完整节省 24 MiB。改用原生 Binder 也需要重做并实机验证 HyperOS 4 私有亮度接口、放权和失败恢复；不能把理论省内存当作已实现优化。

`lean01` 仅优化稳定状态的唤醒和重复请求：broker 的请求、目标、反馈相差不超过 `0.00012`（本机约两个背光码）时以 500 ms 检查并跳过重复 Binder 写入；差距更大时继续以 100 ms 检查。模块描述检查从 10 秒改为 20 秒，总服务巡检周期仍约 60 秒。框架监管仍每秒检查，保证暂停和进程退出后的亮度放权时延不额外增加。亮度曲线、传感器决策和渐变速度均未改。

复测应分别在亮屏稳定、持续渐变、控制中心手调、暂停/恢复、熄屏五种状态下记录 broker 与 C 核心的 PSS、Private Dirty、60 秒 CPU 时间和框架输出是否正常。与旧版比较时使用同一配置、相近亮度与环境，并记录 `core_build`。若稳定状态 CPU 未下降或出现目标跟随迟缓、亮度跳变、手调被吞、暂停放权变慢，应回退到 `fix06`。本候选尚未完成实机复测，不宣称降低内存或电量百分比。
