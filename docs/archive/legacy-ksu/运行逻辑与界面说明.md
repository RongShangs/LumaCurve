# 1.0.0 运行逻辑与界面检查

## 一次亮度决定如何产生

1. 前置光感优先给出屏幕前的照度，后置光感用于判断两侧是否同向变化。单侧突变需要确认；持续、可信的突暗有单独的响应路径。
2. 时域滤波把有效样本变成控制照度。光感按变化上报时，短期没有新事件不等于读数失效。
3. 用对数照度在 14 个锚点之间插值。用户可以直接编辑并保存预设；长期学习只缓慢调整当前照度附近的点，且可关闭。
4. 昼夜因子、强光增强、电量与温控约束给出可用目标，再经过目标确认与平滑过渡。前端区分原始读数、确认输入、平滑照度、目标背光和当前背光。
5. HyperOS 4 框架代理接收目标，并根据系统当前显示范围平滑输出。锁屏、手动亮度模式或接管条件不满足时交还系统；安装固件校验不匹配时拒绝接管。

自动模式下用户在系统控制中心拖动亮度条，代理先让系统完成此次操作，再保持用户选择。正常波动不会立即结束保持；照度相对锚点变化至少约 3 倍、绝对差至少 8 lux，连续至少 3 秒和 3 次确认后退出。锁屏会直接结束本次保持。同一照度区间反复同向操作，可在可信证据与冷却约束下缓慢学习曲线。

## 界面各页的职责

| 页面 | 最先回答的问题 | 需要进一步查看时 |
| --- | --- | --- |
| 状态 | 哪路光感在起作用、曲线当前要求多少背光、屏幕实际到哪里、是否正在保持或保护 | “详细读数”显示传感器年龄、框架接管、温控来源、写入阶段等诊断字段 |
| 设置 | 暂停/恢复引擎，保存配置，查看学习后的曲线 | 展开曲线锚点与预设；高级参数按用途分组 |
| 日志 | 本次开机发生了什么 | 复制或导出本次开机日志；归档默认 3 天 |
| 关于 | 模块适配、版本、更新入口、源码和支持方式 | 官网站点提供模块、对应 GPL-3.0 源码与校验值 |

状态页的曲线是“照度到目标背光”的关系图，并非屏幕实际发光亮度曲线。目标点与当前点分开显示；框架限幅时用可执行目标。温控没有可信来源时，应显示“暂无可信温度”，不能把缺读数解释成温度安全。页签只切换界面，不写入浏览器历史，系统返回键可回到模块管理器。

## 仍需实机确认

安装预检只能确认当前固件和主屏接口符合本包条件，不能验证所有唤醒、传感器静默、HBM 和用户滑块时序。保持阈值与默认曲线末段在主测试设备上有主观反馈，但本次调整仍需更多用户实机体验。源码、WebUI 与官网均按 GPL-3.0 发布；官网资源和更新元数据只有在站点实际部署后才会在线可用。
