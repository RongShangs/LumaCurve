# 验收范围与限制

## 源码范围

生产 source_lists.py(highlevel) 和 CMake 显式列出 35 个 C 文件。完整 main、23 个原业务函数、配置/学习/状态协议、传感器/设置/电源/电池/HBM/执行器/信号均恢复到普通 C。CPU、模拟栈、原地址 dispatch、低层 main .inc 和原 ELF 镜像不进入生产调用图。static audit 检查预处理后的实际生产文件和最终 ELF 符号；不把 dormant 参考源码的字符串搜索当作生产检查。

## 行为验收

- 主机 C：曲线 1407 例（本轮最大误差 0）、过渡 800 例、辅助业务 197 例。
- 传统主流程：134 个状态字段，以及 7 个双侧完整场景，SKIP=0。
- 扩展主流程：37 个场景，同一 fixture 运行原 ELF、主机 C、实际 ARM64 C ELF。每次等待边界比较 232 个纳入 oracle 的可变业务字段；结束时比较日志、文件、权限、命令、传感器操作、执行计数与退出值。
- 内容：sysfs 小数与明暗变化、温控进入/退出、阳光/HBM/冷却、NDK 前后 ALS/proximity、必需/可选符号缺失、manager 失败、有效后传感器回退、学习注入/累计/已有单元两次提交、重载/reset、手动/自动/屏幕边沿、外部亮度、所有权权限失败。
- 五类背光故障各有实际注入计数：open/write 失败、短写、invalid 回读、偏差回读，随后取消故障检查恢复。
- 组合：阳光→温控→恢复、学习 pending+灭屏/重置、NDK 无事件窗口+屏幕边沿。组合名称说明输入，不意味着其中每个业务分支都被触发；实际计数及状态记录可复核。
- 已注册信号回调：原 ELF 和 ARM64 模拟器执行注册的真实函数；主机执行真实 C 函数指针。重载/reset 和 TERM/INT 完整清理均比较。这里不模拟内核发送信号。
- 长循环：1000 次等待；原程序、新主机 C、新 ARM64 的全状态/IO 对照一致。
- 生产语义负向：分别破坏 debounce/thermal/sunlight/learning/ownership。每个 mutant 能编译运行，测试必须发现差异；还原版本重新匹配。历史实验 helper 的负向另行保留，不替代这五项生产验收。
- UBSan：ARM64 `-fsanitize=undefined -fsanitize-trap=undefined` 编译后对同一 37 个完整场景运行；触发陷阱会使测试非零退出。范围限于这些执行输入，不能宣称任意输入无 UB。

指针/NDK 句柄的地址与原程序不同，比较其操作及相关业务状态，不比较任意地址数值。学习在原版配置路径被强制关闭，学习测试在第一等待边界显式注入 enabled/单元状态，详见测试源注释。

## 测试可信度与静态边界

没有给出完整 CFG 的 100% 分支覆盖率或形式化等价证明。恢复主流程覆盖整个原 main，包括不常执行分支；未在场景中触发的参数组合不能标为已跑实测。较少见的 thermal 类别/归一化、NDK enable/queue 失败、文件/系统调用失败组合、畸形值等仍可通过 fixture 扩展验证。现有辅助测试和逐区恢复依据提供额外证据，但不能据此把所有组合标为 exact match。

静态恢复依据保留在 reference/decompiled、reference/lowlevel-c、原地址复核文档和浮点映射。编译器保存/恢复、栈布局和 CRT 初始化由新 C/NDK 生成，不属于缺失业务。

## 独立构建与交付

正常构建依赖 Python 3 + NDK；CMake + Ninja 为另一入口。源码 ZIP 排除 build/dist/缓存；在无 original、.pylibs、.tools 的新目录中清空分析环境变量后分别构建。验证 ARM64 PIE/API26 及 16KB LOAD 对齐。输入/模块资产/报告/源码包哈希绑定在 delivery-manifest.json 中。

Python 构建加入路径映射以减少绝对目录导致的调试信息差异，实际可重复性结果以 standalone-verification.json 为准。CMake 编译命令及 debug 工作目录不同，不承诺它与 Python 输出位级相同。模块经过 strip-debug，分别记录发布二进制与未 strip ELF 哈希。

## 待实机验证

没有 Android 实体设备。真实内核信号、机型 ALS/HBM/thermal/backlight 节点、SELinux、安装/重启、实际 CPU/RSS/资源泄漏与长期性能未验。脚本 tools/device_acceptance.sh 只采集只读现场信息；后续步骤见二开指南。

报告保存每个场景 Original/Native/Arm 墙钟耗时，它们属于模拟器/主机测试环境，不能推断新实现的 Android 性能优于原版。只确认长循环行为和资源调用顺序一致，不将 ELF 体积变化当作性能结论。

## 测试运行环境

本机 Python 3.13 + Unicorn 曾在长批次回调中发生 Executing a cache 的解释器崩溃，失败记录留在 build/history/test-runtime-failure-20260928。该退出未计通过。完整场景现按单场景子进程隔离，任何崩溃/缺报告/比较失败都会使总报告失败；正向/负向使用现有 MSYS2 Python 3.14.5；UBSan 场景使用独立 Python 3.12.10 运行时。3.14 的原生进程异常也保留为失败，不计通过。正常 NDK 源码构建不依赖这个测试专用解释器。

统一验证支持 --resume，但只允许恢复最后的负向/UBSan门槛；必须校验同一原ELF、解释器、37个正向结果、主机/ARM产物、静态审计及全部生产输入哈希仍一致。先前失败报告按SHA保存在 build/history/verification-resumes；该功能不把失败步骤改绿，仍真实执行剩余步骤。
