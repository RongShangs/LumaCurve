# 核心进一步评估与安装检测

上述四个优先项已在后续一轮处理，当前实现与验证范围见 [室内稳定与硬件可靠性优化](室内稳定与硬件可靠性优化.md)。下表保留评估时的发现。

## 评估时的核心优先级

| 优先级 | 源码发现 | 建议与验证要求 |
|---|---|---|
| 高 | read_lux_fallback.c 仅以 lux >= 0 判断成功，正无穷也可通过；clock_gettime 失败时使用未初始化 stamp | 有限值与范围校验、初始化时钟结果并检查失败；非法读数保留旧样本，不能标记新鲜。补异常浮点、超范围、时钟失败对照。 |
| 高 | business_sensor_init.c 不检查 enableSensor 返回值便设置 g_ndk_ok，set_light_sensors_enabled.c 也需要按实际返回确认 | 区分传感器存在、权限允许、成功启用和收到有效事件。失败允许 sysfs 降级；避免把有接口当成有数据。 |
| 高 | read_screen.c 两次读取失败后默认亮屏 | 使用可信显示/电源缓存并明确未知状态，验证锁屏、AOD、节点缺失与读取失败。直接改成默认息屏也会造成另一种误判。 |
| 中 | 背光、最大背光、息屏节点固定 panel0-backlight | 统一设备节点发现与配置，选定同一组 brightness/max_brightness/bl_power；安装检测必须与引擎使用路径一致。本轮先拒绝当前引擎不能支持的路径，不能检测其他路径通过后仍让引擎写固定路径。 |
| 中 | settings XML 监视固定 users/0，读取命令未显式约束同一用户；错误后带有效缓存仍可能等待 60 秒才重试 | 统一用户、区分成功缓存与失败重试，采用有上限的退避。避免故障时每两秒反复启动系统命令。 |
| 中 | 通用格式化仍用于日志与控制路径；辅助状态访问仍是逐字节读写 | 先记录调用量和耗时，再扩大类型化边界；保持整数符号、浮点精度、信号可见性和回放布局。 |
| 待实测 | 背光 FD、HBM 写入缓存，以及固定曲线锚点 log10 的缓存 | 前者需处理节点重建、外部修改与休眠恢复；后者收益小但需验证同目标浮点库的舍入。 |

本轮只分析以上策略，不修改亮度曲线、保护阈值或异常输入行为；避免将“优化”与新行为混为一次未经对照的变更。

## 已接入安装检测

现代管理器 customize.sh 与兼容 update-binary 共用 compatibility.sh；检测发生在最终模块切换和旧版卸载提交之前。安装失败走原有回滚入口。两个 update-binary 内容一致。

基础检查：root、明确的 ARM64 架构、API >= 26，以及 timeout/settings/base64/tr 工具。无法确认架构或系统版本时不再默认为支持。

新引擎入口 `--check-install` 在 ios_reset_data 和业务 main 之前返回：只检查，不启动正常守护进程。由 timeout 限制 12 秒。

- 实际执行本次 ARM64 ELF，从而发现动态链接器、依赖库、架构、执行权限等加载失败。
- 检查引擎真实使用的 panel0-backlight 节点、当前/最大背光范围，并以 O_WRONLY 打开背光节点后立即关闭，不写、不截断、不 chmod。
- 探测 libandroid.so、必需 NDK 符号、SensorManager 和前/后光感；或检查引擎支持的两类 sysfs 目录中的有效照度入口。两条路径都不可用则拒绝安装。
- 读取屏幕电源节点；查询亮度模式，查询失败提示待验。缺少可信温控、HBM 等增强能力不作为基础安装失败，需在启动后查状态。
- 报告保存为模块目录 compatibility-report.txt，安装界面同步显示。

检测通过仅说明安装上下文中的基础能力满足。光感持续事件、实际写亮度、设备休眠/唤醒及服务上下文 SELinux 权限仍标记待验证；存在传感器不代表能收到数据。探测不会修改亮度、自动亮度模式、HBM、节点权限、PID、学习或配置，也不会同时启动第二个亮度引擎。恢复环境未挂载完整 Android 服务时可能被拒绝，应从已启动系统的模块管理器安装。

## 验证

tests/compatibility.py 执行生产探测头文件的本地 C 模拟：7 个原生能力用例与无写入/截断检查；9 个 shell 环境/协议/失败/超时用例。另有 16 个安装器选择、回滚与现代入口检查，包含探测失败恢复数据且不卸载原版。报告明确不是实机 Android 验收。原 C 主循环仍按 37 场景回放验证，入口探测独立验收。
