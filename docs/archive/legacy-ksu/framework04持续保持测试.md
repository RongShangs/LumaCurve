# 手机 root Agent：持续保持与光感变化验证

framework03 的 21.5 秒测试已确认本机系统通道短时稳定。
本次覆盖更长保持，并观察环境变化时临时输出是否仍稳定；不是新的模块核心。

解压 LumaCurve-framework-probe04.zip，在解压目录执行：

```sh
su
sh ./probe_framework04_android.sh
```

无需安装或重启，自动亮度保持开启。模块原本暂停也可执行，结束后继续保持暂停。
控制约 60 秒，连同哈希及系统 dump 通常约 70～90 秒。
输出中每段每 100ms 一条 SAMPLE：起始 2 秒 → 升亮 5 秒 → 上端保持 20 秒 →
降亮 5 秒 → 下端保持 20 秒 → 返回 5 秒 → 结束保持 3 秒。
目标仍为开始时框架值附近 ±0.01，并受当前 min/max 限制，不试满亮度或 HBM。

如果方便，开始后约 10～20 秒轻遮正面光感几秒再松开，约 35～45 秒改变手机朝向
再回到原位，用来检查环境变化是否会把保持的临时目标覆盖。
不操作滑块、切自动亮度、锁屏、视频或 HDR；这些独立场景将在后续分别验收。
若不做光感动作，也可以回传结果，并说明未做环境变化。

把整个 luma-framework04-时间戳-PID 目录压缩回传，说明是否有突然变暗/变亮。
这次不采集光感事件本身，不能仅凭轨迹证明动作已改变系统传感器输入。
清除读回仍需出现 RESTORE temporary=verified_clear；独立恢复进程的控制期限为 100 秒。
恢复未确认时保持模块暂停，并回传日志处理。

测试只通过系统临时策略发送目标，不写 Settings、模式或 sysfs，不注入 system_server。
框架请求等步长不等于视觉亮度严格均匀；这次继续验证控制权和数值稳定性。
没有更新正式模块、官网或 GitHub。
