# LumaCurve 开发说明

产品版本为 1.0.0 / 10000，配置格式为 12。当前本地修复核心标识为 `20260930-audit-repair01`；本地修复包不会替换已归档的正式包，也不自动推送或发布。

## 生产构建与验证

在工程根目录执行 `python tests/verify_project.py`。入口构建 Java/DEX、运行 C/Java/浏览器/安装器/升级事务回归和语义负向测试，然后构建 ARM64 C 核心并核对 ZIP、源码、DEX 和模块资源。任一步失败都会以非零退出码结束。验证报告为 `build/project-verification.json`，绑定当前源码和测试文件哈希；不代表实机验证。

单独构建：先 `python tools/build_framework_probe.py`，再 `python tools/build_framework_module.py`。默认产物为 `dist/luma_curve-1.0.0-local-audit-repair01.zip`，不包含正式自动更新地址。

对应的独立源码包：`python tools/package_source.py --output dist/LumaCurve-1.0.0-local-audit-repair01-source.zip`。工程无需原 ELF 或反编译工具。构建依赖 Python、JDK、Android SDK/NDK；脚本中的 Windows 工具路径按本机配置。浏览器验证需要 Playwright 和 Edge，生产 WebUI 无 npm 依赖。

历史 sysfs 路线只供参考：`tools/build.py --package` 输出带 `native-reference` 后缀的包；CMake 必须明确指定 `-DLUMA_NATIVE_REFERENCE=ON`。它们不会覆盖框架生产包，不能拿来验收当前生产后端。历史总检查保存在 `tests/verify_native_reference.py`。

## 运行链路

`module/service.sh` 管理启动、配置迁移、暂停和开机日志；`framework_daemon_launcher.sh` 管理单实例和整组退出。C 主循环 `csrc/main_business.c` 处理光感、双侧场景、曲线、学习、温控、目标确认和输出权限；`experimental/framework_output/framework_backend.c` 传递目标、硬保护上限及升亮/降亮速度。

Java broker 调用系统显示框架，结合手动保持、最终安全上限和单调过渡执行输出。安全上限始终优先于手动保持；框架限制仍然有效。RPC 接受不等于面板已到目标，反馈守卫分别检查框架收敛和物理读回。故障后释放控制，30 秒后有限恢复，两次恢复仍失败则等待人工重启。

## 配置事务与诊断

配置、预设、迁移和升级恢复共用 `live.lock`；比较旧文件和替换新文件在同一锁内完成。活着的持锁进程不会因为锁超过 30 秒而被夺锁。嵌套事务借用锁，不释放外层锁。

C 核心严格解析整数/浮点数、检查有限值和范围；失败恢复旧值。成功重载发布 `config_applied_hash`。WebUI 保存、通知重载、回读文件并等待核心确认，超时不会显示“已应用”。它是应用内容确认值，不是安全校验或加密签名。

`core_build`、输出诊断、曲线和偏好状态始终发布，不依赖学习/场景开关。旧学习器的诊断明确命名为 `legacy_learn_block_reason`，渐进式学习使用 `preference_*` 字段。

## HyperOS 4 与系统更新

主屏、背光范围、接口和显示配置在每次启动重新识别。旧实测比例只有在显示身份、最大背光及对应 framework/services 哈希同时匹配时采用；其他固件使用候选比例并持续检查反馈。安装前检查旧临时亮度控制已释放，并等待连续一致的反馈。

归一化 XML 和安装时低区读数不能证明全范围输出正确。未知设备、OTA 后的全范围调节、锁屏/解锁、手动保持和系统限制仍需实测。候选适配不得描述成“所有 HyperOS 4 已验证”。当前框架后端不直接写 HBM 节点，硬件高亮上限由系统管理，阳光增强算法仍有效。

## WebUI 与许可证

`module/webroot` 是状态、设置、日志、关于页面；Root 命令只使用固定模板。更新读取有大小/超时约束的 JSON，绝不执行远程更新脚本；浏览器跨域读取失败时可通过 Root 桥下载同一固定 JSON 地址。公开更新服务需提供 JSON 和合适的 CORS，私密 GitHub 不可作为匿名更新来源。

保持 GPL-3.0、LICENSE、已有源码中的版权声明以及对应源码交付。当前占用应按 C 核心、Java broker 和监管进程一起采样 PSS/CPU；不得沿用旧单核心的低占用数字宣称本次修复降低了耗电。

## 正式 1.0.0 交付与导出

运行统一验证后，以 `python tools/build_framework_module.py --release` 生成正式包，构建号为 `20260930-release-1.0.0`；默认不加参数仍生成隔离的本地审查包。随后运行 `tools/package_source.py` 与 `tools/sync_website.py`，确保安装包、完整源码、官网和更新信息一致。

日志页的兼容概览取自当前核心状态。`export_analysis.sh` 以固定路径和受限任务标识启动后台导出，界面轮询阶段状态；日志导出附带设备状态，分析导出调用 `tools/collect_hyperos4_android.sh` 的同一只读采集流程。两者保存于 `/sdcard/`，附带 SHA-256 文件，不自动上传。主机测试覆盖完整档案、输入不变、失败提示及路径越界拒绝；真实管理器后台导出仍需设备验收。
