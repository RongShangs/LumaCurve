# 完整核心与框架输出联调（候选 01）

这次已将 C 核心接入框架输出，不是再次运行固定升降脚本。
不需要安装模块或重启。完整解压 `LumaCurve-framework-core-test01.zip`，在解压目录 root 终端执行：

```sh
su
sh ./test_framework_core_android.sh
```

正常约 2～3 分钟。脚本会暂时暂停已安装模块，运行独立 C 核心和框架后端。
输出限制在起始框架亮度 ±0.01，目的是核对链路、平滑和系统限幅；不会完整执行你的高亮极端曲线。
正式核心、原配置和学习文件不替换；实验副本暂时关闭学习及 HBM 节点写入。

建议第一轮保持屏幕开启，先静置，再缓慢改变正面照度。后半段可以切换手动亮度约 10 秒后回到自动，以验证放权/接管；不用同时进行熄屏、重启等多个动作。
不要在运行中使用管理器暂停/恢复正式模块，或启动另一个亮度控制程序。

测试结束会验证临时请求已清除，再恢复模块原先运行/暂停状态；用户自行选择的自动/手动模式不会被强行改回。
若清除未确认，脚本保留暂停与证据，并明确输出恢复失败。

请回传整个 `luma-framework-core-test01-时间戳-PID` 输出目录的压缩包，重点文件：

- `core.log`：真实 C 核心与光感/曲线处理。
- `framework.log` / `framework.trace`：目标、限幅、连续请求、系统反馈和背光节点。
- `states.txt` / `final-state.txt`：隔离核心状态，不从正式 WebUI 读取。
- `recovery.txt` / `released-main.txt`：控制权清除结果。

当前没有宣称全机型支持、HBM 接管成功或物理亮度已线性均匀。先由本机实际数据验证，再完善单位标定与正式模块集成。
