# 架构、数据流与协议

## 主循环数据流

启动初始化 → 读取设置/显示与所有权 → 采样前后 ALS/proximity 或 sysfs 回退 → 新鲜度/遮挡/可信变化判断 → 平滑 lux → 曲线 → 学习修正 → 热保护 → 唤醒与低照度边界 → 目标防抖 → 阳光/HBM → 渐变执行器 → 状态输出 → 事件/定时等待。

具体分支顺序仍以 main_business.c 为准：手动、灭屏、无有效样本、只读窗口和退出会提前走共同调度/清理路径。主循环是同一套生产逻辑，不再由旧 main shadow 调用实验 helper。

## 状态机

- 所有权：读取系统亮度进入 wake_readonly；有效 ALS 计数、剩余窗口、延长计数和 chmod 结果共同决定只读/延长/接管。到期边界包含 now == until。
- 防抖：小变化回收候选；较大变化记录方向/候选起点，按明暗及变化方向等待后接纳。保留原微小阈值与分支豁免。
- 热保护：热区扫描缓存 → 可信/可疑类别和温度归一化 → 硬保护进入 → 迟滞保持 → 退出恢复。充电保护及热区缺失也保留。
- 阳光：lux 确认 → 电池/温控/冷却门槛 → active 与 boost → 低 lux、屏幕/模式、传感器/温控/超时等退出 → cooldown。HBM 节点由真实扫描/配置获取。
- 学习：用户调整 → pending 累计 → 延迟与稳定条件 → 11×4 bucket 单元更新 → 持久化。灭屏/重置/无有效调整会取消 pending。权重同时使用照度距离、时段距离、样本年龄和置信度。
- 执行器：目标决定方向/step → 节流/hold → 背光写 → 回读同步/外部接管；失败/短写保留原状态处理，完整故障场景已纳入验收。

## 时间与数值

运行时间/截止使用 clock_gettime 的单调毫秒；NDK 事件 timestamp 为纳秒；持久学习时间为 time() 的 Unix 秒，时段来自 localtime()。温度为摄氏毫度，slider 为 0..255，实际背光范围由 g_max 决定。字段表见 状态字段.md。配置实数是 float；用于日志/文本时提升为 double。显式 fmaf 保留原融合舍入。

## 文件兼容

配置 `/data/local/tmp/ios_brightness.conf`，默认模板 `module/ios_brightness.conf`，config_version=11。新增配置需同时修改 load_config.c 字段表、state.h/state.c 默认值、模块模板和 WebUI，再新增解析/主循环用例。

学习 `/data/local/tmp/ios_brightness_learn`，version=4；单元为 bucket、period、lux、slider、confidence、timestamp 文本记录。解析到临时表，校验通过后提交，拒绝坏版本/异常实数/越界单元。不要直接 dump C struct 代替文本协议。

状态 `/data/local/tmp/ios_brightness_state`，先写 .tmp 再 rename。保留既有 key、单位和英文状态描述，WebUI/控制脚本依赖这些字段。新增状态需在 write_state_file.c 统一添加，再调整 WebUI 和快照对照范围。

PID `/data/local/tmp/ios_brightness.pid`；退出关闭传感器/队列/library，恢复原亮度节点权限，清理 PID，按原逻辑保存学习并记录停止日志。

信号回调是 void(int)，仅赋 volatile 标志；主循环执行重载/重置和清理。真实已注册函数执行已验证；操作系统内核投递链仍待设备。

## 边界与排障

csrc 是维护实现；platform_native.c/native_calls.h 为 Android 边界；module 是脚本与 WebUI；tests 为 oracle 和 mock；reference/experimental/src 为历史参考，默认不链接。字节缓冲仅用于协议/Android ABI，生产不映射原镜像。格式输出的值列表是消息格式化数据，不是 libc/NDK 参数寄存器封送。

无法启动先核对 arm64-v8a、API 26+、module/service.sh 日志及 daemon 路径；无传感器查看 NDK 动态符号和 sysfs 回退路径；不写亮度查看 owner/wake_readonly/governor reason 和 chmod；阳光不进入查看确认计数、电池、可信温度与 cooldown；WebUI 异常查看状态文件及版本。保留现场日志和配置，在可控完整主循环 fixture 中复现后修复。
