# 设置保存误冲突修复

问题：设备上修改设置时反复提示“配置已被其他操作修改，请重新读取”。

原实现通过 `cat` 将配置交给 WebUI，再写成临时文件与磁盘配置执行 `cmp -s`。管理器返回文本时如果删除末尾换行或转换行结束符，比较就会失败；此外，原实现把 `cmp` 命令不可用或文件读取失败也全部报告为修改冲突。未连接用户设备，无法确认其具体触发因素。

本次调整：

- 配置初次读取和保存后的回读使用 Base64 传输，再严格解码 UTF-8。管理器对输出的换行处理不再影响配置内容。
- 保存前在设备上读取当前文件的 Base64 编码，移除编码的换行后通过 shell 内置比较与已读取内容核对，不再依赖 `cmp`。
- 读取或编码处理失败单独报错；真实外部修改仍阻止覆盖，用户需要重新读取。
- 继续保留注释与未知键，临时文件以 0600 权限原子替换，随后请求重载并回读确认。原有比较与替换之间的并发窗口未在本次改动中扩大为跨进程锁实现。

验证：`tests/webui.cjs` 模拟配置输出丢失末尾换行和转成 CRLF，覆盖中文、原文件 CRLF、原文件无末尾换行、真实外部修改、重载失败。另执行界面实际生成的 shell 命令，验证成功写入、冲突拒绝、读取失败不覆盖及临时文件清理。测试 shell 为本地 MSYS Bash，管理器为模拟桥；仍需用户更新模块后复测 Android 实机保存。

本次不修改 C 引擎、亮度策略或版本号，仍为 0.0.1 / 00001。
