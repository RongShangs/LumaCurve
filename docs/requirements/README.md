# 结构化功能需求

`feature-requirements.json`是每项功能需求的唯一手工数据源。运行自检功能与生产兼容目录一一对应；纯界面交互独立登记，不伪装成系统兼容路线。

每项维护稳定ID、名称、默认行为、触发、作用、退出/失败、配置键和依赖能力。系统场景原生说明可引用生产常量，避免复制后漂移。全局约束只引用GLOBAL_RULES.md，不给每项反复复制。

路线、原生ABI、负责人、证据、统一坐标和测试从兼容清单与生产目录读取，不在需求JSON再列一份路线。

修改步骤：改实际实现和对应需求/兼容清单 → `python tools/verify_compatibility.py --write-doc` → 查看`docs/features/`生成差异 → 契约及功能回归。普通验证检查功能覆盖、配置键、实现登记、源码指纹和页面是否同步；这只能发现结构漂移，不能替代对需求含义的审阅或Android真机验证。

版本变化写入`docs/releases/`，当前进展写入`docs/work-status.md`。生成页面不能手改，长期需求不能写进某一版日志后就不再维护。
