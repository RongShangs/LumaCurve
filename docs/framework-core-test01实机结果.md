## 实际发现与候选 02 修正

1. C 防抖分支不仅确认变化，还按每次 4.5% 最大背光分段抬高目标；最终形成旧目标阶梯再叠加框架渐变。候选 02 保留变化确认，但把确认后的完整目标一次交给框架渐变。
2. 启动时 `g_tr_1` 未从实际背光初始化，小变化迟滞把第一目标替换成了 0；轨迹实际先降到约 1300 再升。候选 02 从有效启动背光初始化迟滞参考。
3. 回自动后只有一个真实 on-change 样本，仍为等第二个样本延长并误报 `wake_no_fresh_als`；实际读取有效。候选 02 仅在已确认 on-change 模式、传感器已启用、有真实时间戳和同一个已采集样本的情况下允许安静样本结束观察，不增加样本数、不刷新事件时间。连续/未知模式继续走原确认。
4. 小幅测试窗口一直锚定首次启动 0.0812152；手动切换后系统反馈变成约 0.096，重新接管又被压回 0.0912152。候选 02 在每次取得新会话时从实际反馈重新建立 ±0.01 窗口和渐变起点。
5. 看门狗读取已退出 PID 时出现两条 `/proc/.../cmdline` 缺失提示；未影响恢复。候选 02 将预期的 PID 消失静默处理，同时保留身份核对和失败恢复记录。

以上只改变框架候选路径；默认安装核心仍保持原路。实机失败点被用于构造目标/唤醒测试和三种语义负向测试。
