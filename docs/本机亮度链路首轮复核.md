## 1. 优先处理：daemon 被冻结

`before-processes.txt` 与 `after-processes.txt` 均记录：

```text
root 26964 1 ... do_freezer_trap ... S luma_curve_daemon
```

60 份状态的 `updated_unix=1790684401`（北京时间 20:20:01）不变，
`actuator_write_attempts=27` / `actuator_write_successes=27` 不变，
`sensor_reactive_left_ms=2922`、`dark_settle_left_ms=2922` 等倒计时也全部不变。
实际 brightness 全程 2024；缓存 current_br/target_br=1796，与真实节点已不一致。
两端进程等待位置加上整段状态冻结，指向进程执行被 freezer 停止，远超过普通
状态发布延迟。尚未采集 cgroup.freeze / cgroup.events，需补齐冻结来源。

Android 的 cached-app freezer 使用 cgroup v2 冻结缓存进程；Linux 子进程创建时
继承父进程控制组。启动脚本里的 nohup、后台化及 PPID=1 都不保证迁出原来的
控制组。LumaCurve 的 background 函数目前只处理 cpuset/cpuctl/stune 与优先级，
没有检查 freezer 层级。**热启动继承终端/管理器控制组是待验证假设。**

用户反馈：采集中间挂过一次小窗；brightnesslock.rongshangs.top 未使用、未主动运行。
该应用在 ps 中也处于 do_freezer_trap；进程存在不代表它正在锁亮度，不能把它认定
为干扰源。小窗与冻结的因果关系也不能只凭操作史断言。

当前服务以 PID 存活判断核心是否运行，冻结进程仍有 PID。因此后续需要同时处理
可靠启动的控制组归属、状态新鲜度和界面运行状态。先补证据，再选修复方案。

## 2. 本机系统实际通道与普通亮度上限

只看主屏 physical display=4630946949513469331 / port=147，避免混入背屏。
`before-display.txt` 与 `after-display.txt`：

| 字段 | 主屏值 | 含义 |
| --- | --- | --- |
| BacklightAdapter | useSurfaceControl=true, backlight=null | 系统主屏通过 SurfaceControl 控制 |
| HBM mode | off | 本轮未进入高亮模式 |
| mCurrentMax / hbmTransitionPoint | 0.37486267 | 当前系统归一化上限约 37.49% |
| HBM minimum lux | 4475 | 系统配置的高亮照度条件之一 |
| thermal cap | 1.0，未应用 | 本轮没有系统温控亮度限制证据 |
| current normalized brightness | 0.115736715 | 系统逻辑亮度，不能当作光学实测 |
| RampAnimator.isAnimating | false | 本轮系统动画不在运行 |

SurfaceFlinger 报告主屏 estimated displayBrightnessNits=185.704163，前后不变。
主屏通道上有 SurfaceFlinger、QTI composer、Xiaomi displayfeature 服务；
可以确认系统使用 SurfaceControl，并有相应显示服务，尚未追踪具体驱动调用。

主屏实际选用 `/product/etc/displayconfig/display_id_4630946949513469331.xml`。
dump 中的 backlight/nits 映射为多段线性，最高配置 nit=3500，正常模式/HBM 又有
不同条件限制。模块继承的 nits_max=538.5 不能直接作为这块屏幕真实 nit 标尺。
模块曲线百分比、系统 normalized float、sysfs/max_brightness 百分比、估算 nit
需要明确区分，曲线和状态页后续必须使用一致坐标与单位。

**37.49% 是当前系统通道上限，不能直接认定 raw sysfs 的硬件上限也是 37.49%。**
需要原任务书 C 组小幅写入/读回/系统状态对照才能定性。禁止据此盲目拉满亮度。

## 3. 其他采集限制

- actual_brightness 全程 0，而屏幕 ON、brightness=2024；该字段在本机不能作为
  可用的实际亮度测量，不能据它推断黑屏。
- root 下三项 settings get 均返回 Failed transaction (2147483646)；目前不推断
  此错误码的具体原因。旧状态 settings_read_error=- 也是冻结缓存，不代表当前成功。
- 不能用这份数据推断渐变曲线为线性/跳变，更不能判定原作者模块在所有机型无效。
- test03 上次 124/124 成功且读回一致仍有效；冻结问题不否定持有 FD 的修复。
