# LumaCurve 框架接管实施计划

目标：替代日常自动亮度决策，按视觉上均匀的速度过渡，同时沿用系统显示输出与
硬件限制。以本机 HyperOS 4 / OS4.0.0.41.XBLCNXM / Android 17 / API 37 为首个
明确适配目标。AOSP 是参照，不是 HyperOS 运行时实现的证明。

## 已确定的边界

1. test03 修复 sysfs 自锁；freezer01 修复热重启继承应用冻结控制组。
2. 新日志证明核心在持续写入后，节点被外部改低，但尚未追踪具体写入者。
3. 本机主屏系统链路采用 SurfaceControl；chmod 无法保证完整显示控制权。
4. 普通模式当前上限约 0.37486267；该系统 float 不等于滑块百分比或光学亮度。
5. 固定 538.5 nit 标尺没有本机校准依据，必须从新路径的正式状态输出中移除。
6. 本阶段不改默认引擎，不推送 GitHub，不发行新版。框架读写与 Hook 均待本机验证。

## 阶段 F0：HyperOS 实际接口与稳定控制验证（当前）

交付：独立 app_process / DEX 探测工具，避免 Binder 事务号硬编码。

- 只读：系统实际 DisplayManagerGlobal / IDisplayManager / SurfaceControl 的亮度方法签名，
  display 0 的唯一标识、BrightnessInfo、系统 mode 的读取结果。
- 枚举 /system、/system_ext、/product 的 services、miui、xiaomi、display JAR 中
  brightness/displaypower/backlight/ramp 类，并记录加载错误。加载失败不等于类不存在。
- 记录 services/framework JAR 的版本指纹、display dump、服务列表和配置目录。
- 不加载第三方 Hook，不修改 services.jar，不调用未知的厂商方法。
- 可选受控测试：暂停模块，只切换系统自动决策为手动，在当前 float 附近测试 ±0.02，
  每个目标观察 3 秒，再恢复原请求、mode 与模块运行状态。

F0 完成门槛：本机权限和签名已验证；物理节点与系统报告可对齐；温和目标实际稳定保持。
接口调用成功只是一个条件，不能据此宣布排除覆盖或实现了匀速渐变。
若系统 BrightnessInfo/getBrightness 参数已被小米扩展，先按实机签名适配工具，
不要把反射 NoSuchMethod 当成整条技术路线不成立。

## 阶段 F1：确定单一控制权

优先验证系统框架自动亮度结果的替换入口。保留系统自动亮度开关，LumaCurve
负责普通亮屏自动模式下的候选目标，交给正常 DPC / 亮度限制 / 显示输出链路。
需结合实机 Dex 类列表定位 Xiaomi 扩展或 delegate，而非直接假定某个 AOSP 方法名。

如需 framework Hook / system_server 注入，先建立独立适配原型，按实际固件指纹
绑定签名、显示标识和调用位置；未知固件不启用。KSU 权限不能自动替代该适配层。
必要组件未确定前，不强制用户安装额外框架。

不在这一步替换 HAL/DRM、关闭全系统 freezer 或移除系统温控。HDR、AOD、屏幕关闭、
系统临时亮度覆盖应有明确优先级；阳光模式同步与系统 HBM 资格、时限及保护条件。

门槛：连续稳定环境测试，无无故回落；前后台、锁屏唤醒、滑块操作、开关切换和
引擎退出能正确交还控制权。Hook 心跳断开必须恢复系统决策，不使用过期目标。

## 阶段 F2：拆分已有算法与平台适配

建议接口职责：

| 接口 | 输入/输出 | 约束 |
| --- | --- | --- |
| SensorSnapshot | 前后照度、上报模式、时间、近距、屏幕状态 | 原始与有效输入分开 |
| EngineTarget | 算法目标、场景、学习版本、理由 | 不读写背光节点，不 fork shell |
| DisplayCapabilities | min/max/HBM 档位、亮度映射、固件/显示标识 | 有效范围和绝对硬件范围分开 |
| BrightnessOwner | 系统/模块/临时覆盖/手动/睡眠/回退 | 只能有一个普通自动决策来源 |
| DisplayAdapter | 提交目标、反馈执行值及限制原因 | 不把“调用成功”当作真实输出 |
| StatePublisher | 算法目标、限制后目标、执行值、实际可读值、数据年龄 | 图表和诊断使用同一快照 |

保留现有双侧光感、确认、防抖、可编辑曲线和渐进学习的功能；去除它们对 g_max、
sysfs 写入和系统状态字符串的隐式依赖。先让新适配层影子计算，与旧层对照，
确认单位一致后才接管输出。

## 阶段 F3：统一曲线单位与渐变

- 编辑坐标明确为感知亮度，普通档与阳光档分别标明；不把 raw/max 当通用滑块百分比。
- 从本机 DisplayDeviceConfig 映射到系统 float；有可信标定才显示估算 nit。
- 旧曲线带上 legacy 坐标标记，保留原文件和预设，不默默把旧 raw 比例解释成新坐标。
- 长期学习只微调邻近锚点，默认启用，可关闭，保持用户手工锚点的大范围编辑能力。
- 只保留一个最终渐变时钟：先评估本机 RampAnimator 的坐标和时序；若需替换动画，
  就只替换这一层，不把模块帧写入和系统渐变串联。
- 在感知空间按真实单调时间推进；同向重定向延续当前位置，反向有受控确认，
  不从旧起点重放。系统限制变化必须有单独原因，不伪装成自然照度变化。

状态图显示三条量：算法期望、系统限制后的可执行目标、当前执行值。受限时应
显示“已达到当前限制”，不能仅因暂时 target=current 就报告整条曲线目标已达成。

## 阶段 F4：实机验收与通用化

先验证 0.1 / 0.2 / 0.3 等允许范围内的目标与方向反转，再验证照度场景和阳光档。
记录请求、执行、物理节点、framework reason、限制、时间。无测光设备时不宣称
测得绝对 nit 或严格光学线性，仅记录数值轨迹及用户体感。

已有本地测试继续保留；新增断连回退、版本签名不匹配、多屏隔离、重启配置迁移、
系统临时覆盖和单位转换测试。性能需要新架构重新实测，不能沿用旧版 0.02% CPU 宣称。

完成本机适配后再抽象其他 ROM 后端；不先宣称所有安卓机型均可完全接管。
