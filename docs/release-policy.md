# 发布约定

当前 APK 主线不能使用旧 C/KSU 发布脚本。工作区保留的 `.github/workflows/release.yml` 原先被 Git 忽略，本轮改为手动历史检查并移除发布权限；新 `compatibility.yml` 仅设计为只读维护检查。正式发布时 GitHub 因当前 OAuth 凭据缺少 workflow scope 拒绝新增工作流，因此两份工作流仅保留本地，未纳入发布提交或源码 ZIP，远端 CI 尚未启用；本轮已完成的维护契约与完整回归由本地检查记录提供。当前发布仍按完整 APK 交付流程执行，不能用打标签代替验证。

感谢名单由 `website/thanks.json` 维护，网站和 APP 共用；本地预览脚本由构建、网站同步工具生成；随包离线名单仅在明确需要时另行更新，日常增补只改网站名单。

感谢名单的增删或留言修改不写入版本更新日志、Release 更新说明和官网版本更新摘要。需要展示名单时更新名单本身及 README 的感谢名单区即可。

发布前核对 APK、版本代码、构建标识、源码包、恢复包、网站下载与更新元数据一致。发布说明区分本地测试、固件接口核对与实机验证，不将静态检查表述为实机适配通过。

后续正式发布必须同时更新官网，不能只推 GitHub / LSPosed。官网文案、版本号 / versionCode、APK、对应源码、完整包、SHA-256、update.json 与 update.js 必须与实际发布一致，逐平台下载核对后才标为发布完成。本地打包只准备本地网站和部署包，不上传、不提前变更线上下载或版本元数据。
