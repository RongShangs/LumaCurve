# 生产源码恢复映射

默认 `highlevel` 是完整的普通 C main 和 23 个原业务函数，生产编译单元共 35 个（见 source_lists.py）。原地址仅在参考文件、测试和本文作为追踪线索，不是生产调度方式。

| 主流程区域 | 维护文件与责任 |
|---|---|
| 初始化/启动 | business_startup.c：信号、PID、配置/学习、显示/设置、所有权和初始传感器采样 |
| NDK 建链 | business_sensor_init.c：动态符号、manager/looper/queue、前后 ALS/proximity、失败回退 |
| 所有权/屏幕边沿 | main_business.c：wake_readonly、延长/过期接管、系统亮度观察、休眠/唤醒 |
| 传感器与平滑 | main_business.c + poll_sensors.c/read_lux_fallback.c：有效性、遮挡、可信突暗、EMA |
| 曲线/防抖 | curve_pct_for_lux.c + business_debounce.c：曲线、微小变化、方向、候选和等待 |
| 温控/电池 | business_thermal.c + refresh_battery_state.c：热区扫描、可信分类、归一化、硬保护/迟滞/退出恢复 |
| 学习 | business_learning.c + main_business.c + load_learn.c/save_learn.c：权重、累计/提交/保存/重载 |
| 阳光/HBM | business_sunlight.c + hbm_find_node.c/hbm_scan_bounded.c/highlux_deactivate.c：确认/退出/冷却/温控抑制 |
| 执行器/调度 | main_business.c + trans_update.c/apply_brightness_frame.c：步长、节流、渐变、事件/休眠等待 |
| 状态输出/退出 | write_state_file.c + main_business.c 的 ios_daemon_shutdown：协议、NDK 清理、权限/PID、文件和日志 |
| 外部边界 | platform_native.c、domain_io.h：真实 libc 和 NDK 调用；不链接 dispatch.c/platform.c |

辅助函数全部保留明确的 typed core。`business_api.h` 是业务接口，`functions.h` 声明曲线/过渡/读屏/状态输出等函数以及便捷 api；同文件中的低层包装由 `#ifndef IOS_PRODUCTION` 排除。参考构建仍使用原先的低层 main，便于定位差异。

主循环结构已恢复成 if/循环和少量语义化局部 goto；不存在原地址标签、跨文件跳转、虚拟寄存器主循环。局部 goto 用于共同清理和调度路径。可读性不等于恢复原作者的变量名和注释：这些命名为根据行为重新建立的维护命名。
