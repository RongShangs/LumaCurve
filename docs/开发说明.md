# LumaCurve 开发说明

当前工程只包含生产 C、构建文件、模块资源和本版本测试，不需要原 ELF 或反编译工具才能构建。

## 功能入口

main_business.c 为完整主循环；state.h 为命名状态；business_startup.c / business_sensor_init.c 处理启动和传感器；business_thermal.c / business_sunlight.c 为温控和阳光；curve_pct_for_lux.c / trans_update.c / apply_brightness_frame.c 处理曲线和执行。

module/webroot/index.html 是状态/设置/日志/关于四页布局，styles.css 使用 #fafafa 底色，app.js 是状态/配置/控制逻辑，kernelsu.js 是回调桥。普通浏览器仅预览；引擎控制通过 KernelSU 兼容桥调用白名单控制脚本，外链和日志导出使用独立、固定模板的 Android 命令。

## 身份与协议

module/module.prop 保存 ID、版本、作者和描述。LumaCurve 从 0.0.1 / 00001 开始，当前界面、CMake 项目版本与启动日志也使用 0.0.1；升级版本时一起更新。配置格式仍为 11，学习文件格式仍为 4，这是数据格式版本，不是产品版本。LICENSE 和 NOTICE.md 必须随源码与模块分发。

运行数据与原项目隔离，使用 luma_curve 前缀；不自动导入旧模块配置。修改数据路径时必须同时检查 C 源、启动/控制/卸载/升级脚本和 WebUI。改安装文件列表时同步 module/update-binary 与 module/META-INF/com/google/android/update-binary。

## 本轮 WebUI 行为

顶栏两个下角、底栏两个上角使用 18px CSS 圆角：顶栏圆心纵向向上、底栏圆心纵向向下，左右两侧圆心横向都朝页面中间。没有外伸的 SVG 装饰，不改变栏高和按钮位置；关于页仍隐藏共享顶栏。

hidden 的 cfg-* 输入仅作为待保存值，edit-* 按钮开启原生 dialog。数字参数同时提供滑条和精确输入，开关/文本单独呈现。弹窗确认先校验全部设置，取消不写配置；建议范围取恢复默认值附近的起步区间，没有视为机型校准数据。保存仍走原子替换、旧配置比较、重载和回读。

状态页仅读取引擎现有状态文件，不新建高频传感器任务；一秒轮询受页面可见性与 stateBusy 保护。趋势只记录新的 updated_unix，保留最多一分钟，环境与平滑照度使用共同刻度。前后读数是各路上报值，只有 lux_source 指定的来源代表当前采用的一路；前后年龄为 0 不足以单独证明传感器有效。可信温度只使用 thermal_trusted_temp，缺失时显示无读数。失败时清空指标、趋势与待复制状态，避免继续展示旧数值。

主视图由一张 engine-scene 图形流程取代参数卡片，详细表格通过独立弹窗查看。前后输入支路依据 lux_source/lux_valid 高亮；过滤与样本保持依据过期/突亮/突暗标志；阳光与温控关口分别使用 sunlight_active 与 heat_guard_active；确认关口使用 target_hold_active。输出连接只有在自动模式、屏幕点亮、daemon 控制且允许写入、处于过渡又没有待确认候选时流动。暂停、手动、过期或禁止写入时呈现等待/接管状态。

照度/亮度平面采用 log10(lux+1) 横轴（0–100000 lux）和硬件背光比例纵轴（0–100%）。实心点为 target_br/max_br，空心点为 current_br/max_br，两者放在 smooth 对应位置；浅色轨迹仅来自最近一分钟的真实目标记录。越界值仅在图边界截断，详细读数保留原值。没有绘制假定基础曲线，也不把未知策略的影响归给某一个保护。屏幕图形的颜色仅用于表现背光比例，不控制设备实际亮度。

图形节点仅作展示，移除 role=button、tabindex 和点击处理，图内文字禁止选中；状态页移除标题和复制按钮，原始状态在日志页「设备状态」内复制，详细读数与日志仍可选择文本。连线均置于独立 SVG 空白区，不穿过 HTML 标签；320/390/768 像素检查文字与连线区域无重叠。状态页没有手动刷新与频率标签，可见时持续轮询。主展示栏压缩间距、图表与屏幕高度；320×640、360×720、390×844、412×915 四种视区验证完整主展示栏不被底栏覆盖，状态页本身固定且不可滚动，详细读数改为可内部滚动的原生 dialog，关闭按钮和 Escape 均可返回。展示区取消外框，最大宽度从 520 扩展至 700 像素；ResizeObserver 监听顶栏、预览提示和底栏的高度，避免遮挡。操作按钮有底色，底栏导航保持透明，同组按钮以等宽网格或等分 flex 对齐。日志先展示最近 150 行及刷新/复制/导出，再显示保留策略与清理，设备状态默认折叠。光感路由、保护、待确认与读取失败有专门场景验证。读失败会隐藏图上的目标点、停止连接流动并重置屏幕颜色。普通浏览器示例有独立标识，不对设备执行控制。

外链先通过 cmd package resolve-activity 查询普通 HTTPS 网页的默认入口；如果返回系统选择器或没有有效组件，改用 query-activities 查找可用浏览器。查询只用于本地匹配，不访问示例网站。过滤系统 Resolver/Chooser 和无效组件；用 am start 的 ACTION_VIEW / BROWSABLE 和明确组件打开真实目标网址。移除 MAIN / APP_BROWSER selector，避免设备报 unable to resolve Intent。缺少浏览器或启动失败会提示错误并保留 WebUI。命令依据 [AOSP PackageManagerShellCommand](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/services/core/java/com/android/server/pm/PackageManagerShellCommand.java) 的 resolve-activity / query-activities 接口。浏览器模拟验证包含官网、博客、协议、GitHub、默认浏览器、多浏览器和找不到入口；实际 KSU 设备仍需安装后确认。

日志复制为当前展示的最近 150 行，导出则读取完整当前 .log，用 am get-current-user 取得用户 ID 后写 /storage/emulated/用户ID/Download，生成独立文件名并禁止覆盖；不包含历史轮转日志。所有外链和导出都由用户点击触发。

顶栏为 sticky，背景和底栏用同一 surface 变量。输入数字/文本时隐藏导航；监听 VisualViewport 和窗口变化约束弹窗高度，输入结束后恢复导航。恢复时不改变页面中的配置值。

上游 39 步/37 场景结果是恢复工程的历史验收，没有声称在新模块上重新执行全部原 ELF 差分。本版本单独执行新构建、打包一致性、安装器资源契约、所有脚本逐一语法检查、界面浏览器测试、源码变化检查和独立源码构建。尚无 Android 实机，真实安装/传感器/SELinux/内核信号待验。

## 安装入口与版本更新

安装前会执行只读的 `--check-install` 探测，检查 ARM64 / API 26、实际引擎加载、固定背光节点的数值与打开写权限，以及 NDK 或 sysfs 光感入口。失败会停止安装并回滚已开始的备份流程；旧模块卸载标记只在成功后提交。检测记录保存在模块目录的 compatibility-report.txt。检测不写亮度、不启用传感器，连续事件、实际写入和服务 SELinux 权限仍需重启后实机确认。完整评估见「核心进一步评估与安装检测.md」。

现代 Magisk/KernelSU 会 source customize.sh，因此直接调用安装函数，使用 SKIPUNZIP=1 自行执行检查与解压。原版音量键选择在任何配置备份和旧模块写入之前；安装成功后才设置 disable/remove，按管理器协议在重启时卸载。恢复环境入口共享 install_choice.sh；KernelSU 本身不支持在恢复环境刷模块。

installer.py 在隔离临时目录执行选择、备份、失败回滚和现代 source 入口，模拟音量事件/权限/配置升级，绝不向宿主进程发信号。真实音量键、升级数据恢复和管理器安装仍需 Android 验收。

版本信息分布在 module.prop、CMake、启动日志、WebUI、安装说明和测试预期；未来升版须同步更新，尤其 WebUI 的当前 versionCode。tools/release_metadata.py 根据 module.prop 生成 update.json 并校验标签，package_source.py 自动读取版本命名源码包。发布 workflow 在标签事件下运行，先上传全部附件再公开 Release，最后刷新 main 的更新 JSON；未发布之前该在线地址不可用。目前仅本地 Git，不推送。

安装与更新协议参考：[Magisk 开发文档](https://topjohnwu.github.io/Magisk/guides.html)、[KernelSU 模块指南](https://kernelsu.org/guide/module.html)。

状态叙述按暂停、旧状态、手动、熄屏、亮屏观察、权限、系统控制、温控、样本有效性、候选确认和实际过渡依次判断。同一帧的标题与说明共同解释当前行为；亮屏观察优先于缺少光感提示，屏幕图形同步显示「系统先调节」或「保持亮度」。模式和所有权只在详细读数中显示，不再以左右两个徽章展示。暂停、恢复、重启移到设置页，顶栏继续保留图标、版本和连接状态。

状态、设置和日志使用相同的顶栏高度，删除状态页专有高度覆盖。状态标题与说明已移至手机图形下方，详细读数按钮与标题共同行、左侧排列；按钮保持底色，长时间文本可自然换行。关于页通过 about-page 类隐藏共享顶栏，上方独立展示曲线图标与「流光亮度」标题，移除句号。设置项减少上下内边距、提示行距与分组间距，保留建议范围及编辑功能；引擎控制移至页尾，让参数优先显示。新增验证覆盖顶栏同高、按钮对齐尺寸、关于页布局和实际设置行高度。

本轮核心与室内时域策略说明见 [室内稳定与硬件可靠性优化](室内稳定与硬件可靠性优化.md)。维护单元的基线源码已扩展并固定哈希；37 场景旧配置回放中，后置单独可用场景按明确修正验收，默认开启室内稳定另跑完整主循环。安装与运行端现已采用共享背光发现策略。

当前双光感关系判断、全照度时域确认与 NDK on-change 模式处理见 [iOS 亮度研究与双光感场景自适应](iOS亮度研究与双光感场景自适应.md)。配置键 indoor_stability 保留，设置页名为「场景自适应」。
