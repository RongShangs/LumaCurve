# LumaCurve 本地体验包：HyperOS 4 主屏框架接管

文件：`dist/luma_curve-1.0.0-local-framework-hold01-ui03.zip`。这是正常 KernelSU 模块 ZIP，可从管理器安装并重启使用，不需要运行两分钟的实验脚本。模块 ID `luma_curve`，版本仍为 `1.0.0 / 10000`；当前更改仅在本地 Git 和本地 ZIP，未上传 GitHub、未替换官网包。ZIP 自带 GPL-3.0 许可及对应 C/Java 源码。前几个本地包保留作回退。

若安装前曾通过设置页或命令暂停，引擎会保留暂停状态；这时重启后不会产生 daemon 进程。安装器现在会提示，WebUI 在无状态文件时也会显示「已暂停」。在设置页点「恢复」，或以 root 执行 `sh /data/adb/modules/luma_curve/luma_curvectl.sh resume` 即可启动，无须重启和重新安装。

## 实际行为

- 沿用已有双侧光感、场景、可编辑曲线、缓慢偏好学习、温控及目标确认的 C 主流程。当前运行时配置和预设继续按原格式读取，**原曲线点含义保持为背光代码占最大背光的比例**。
- 主屏输出不再直接写 `/sys/class/backlight/panel0-backlight/brightness` 或给节点上锁。root Java 桥通过已验证的 `DisplayManagerGlobal.setTemporaryBrightness(0,float)` 向 HyperOS 4 请求亮度；只控制物理主屏 `local:4630946949513469331`。
- 旧背光码到框架浮点采用本机 02～04 实测稳定平台中位值约 `17848 背光码 / 框架浮点 1.0`。这是**设备局部工程标定**，不是光学测量。接管前核对实时节点/框架反馈；超出合理偏差则不接管。输出稳定后若物理节点持续偏离，请求自动清除并停止本次接管。
- 遵守系统实时最小/最大亮度。普通档当前系统上限约 `0.37486267`，按上述比例相当于约 6690 背光码。用户曲线要求高于此值时，状态页显示系统实际允许的目标，详细读数保留原始目标、限后目标和反馈；超出普通档的曲线不会被擅自重写。HBM 条件仍由系统决定，本包尚未通过实机高照度验收。
- 亮度由一层感知空间限速器渐变，自动亮度决策通过临时请求压过系统自动策略；切到手动、灭屏、窗口覆盖、核心失联或正常停止会清除临时请求。脚本启动、暂停、恢复、重启和配置编辑仍由原模块命令执行。
- 框架桥稳定时降低读取频率；日志按既有轮转策略维护。无需保留实验用的 100ms 数值轨迹文件。
- 本地修订 02：稳定后以实际物理背光作漂移基线，避免将仅在低亮度测得的比例外推到高亮度后误放权；框架帧租约延长到 3 秒，并记录释放原因。
- 新默认曲线将 0～10 lux 的背光锚点提升至 2%～4.2%。升级时仅将未经编辑的旧默认曲线迁移至新版；用户自定义曲线及预设保持原样。
- 本地修订 03：WebUI 设置页支持配置版本 12；首次亮度帧提交前不再把尚未启动的帧租约误判为过期。修订 02 实机日志证实该误判会导致接管和放权反复循环，核心虽显示运行但未持续输出。
- 本地修订 04：极暗环境下不再用中低亮度校准比值拒绝接管；真实设备回传的 `adjustedBrightness=0.0062366`、主屏背光 `211` 现可通过宽范围校验。框架模式的旧 `chmod` 只作为尝试接管提示，暂时不能接管不会锁死主循环。WebUI 不再把框架条件不满足误称为 root 权限受限。
- 本地修订 05：更新模块简介与关于页，移除关于页的原作者展示；出处仍在源码文档中。GitHub 仓库清空期间不检查不存在的远端更新。
- 本地节能候选 01：模块描述每 20 秒刷新一次（服务巡检仍为约 60 秒）。框架目标、请求和读回相差不超过约两个背光码时按 500 ms 稳态轮询，并避免重复 Binder 写入；超出容差仍按 100 ms 响应。监管脚本继续每秒检查 broker，以保证暂停后快速放权。C 核心自身采样和亮度渐变参数未改。CPU 降幅需要同条件实机复测，Java broker 内存没有宣称已降低。
- 本地手调候选 01：自动模式下检测到系统滑块调整，交还系统约 2.5 秒后读取用户选定的框架亮度，并重新接管且保持该值。只有同一亮屏期间照度发生至少约 2 倍且差值至少 3 lux 的持续变化（两次样本间隔至少 1 秒），才解除保持并恢复自动曲线；锁屏、手动模式及控制租约失效也会放权。状态页用 `framework_user_hold=1` 标明手动保持。
- 长期学习只接受主屏 `user_set` 事件：同一照度区间、同方向至少两次调整（相隔至少 5 秒），最后一次调整后再安静 8 秒，才把最近曲线点最多改动 0.25%。学习后有 60 秒冷却，累计仍受原曲线 ±20% 和相邻点次序约束；设置中可以关闭。手动保持与长期学习分别生效，关闭学习不会取消当次手动保持。
- 本地界面修订 01：日志页只展示本次开机的活动日志，复制和导出使用同一开机范围；活动日志仍可能因大小轮转而截去最早部分。归档默认保留 3 天，旧配置中仍为 7 天的旧默认值会在首次启动时一次性改为 3 天，之后用户在日志页选择的天数会保留。设置页优先说明长期学习，手动曲线锚点与预设收进独立弹窗；详细读数标题固定，关于页新增 QQ 群、打赏备注和感谢名单。
- 本地界面修订 03：设置页把保存、重读和恢复默认值移至引擎控制下；曲线图常显，锚点与预设向下展开。设置和日志页去掉重复的大标题；感谢榜按「昵称：留言」逐行显示。对外适配说明只提 HyperOS 4，模块作者标识统一为酷安@戎Shangs。

## 安装与回退

安装器检查 ARM64、基础系统工具、两份框架 JAR 的 SHA-256，以及主屏只读接口；固件不匹配时拒绝安装。启动时再次核对 JAR，OTA 后固件变化则交还系统，不强行调用未知接口。安装完成后重启，在状态页查看 `output_backend=hyperos4_framework`、`core_build=20260930-framework-hold01` 和 `framework_owned`；详细读数中的 `actuator_write_successes` 是 C→Java 请求接受次数，不是物理写入次数。

如果需要回到先前版本，在 KernelSU 中先暂停此模块，再安装本地保存的旧版模块 ZIP 并重启。原配置、学习数据与预设由已有升级脚本管理；安装 ZIP 中没有执行实验脚本的临时配置覆盖。

## 验收边界

此前候选 01～04 已实测：主屏小幅框架接管、手动放权、回自动接管、最终清除与渐变单调。**本地安装包的完整范围、极端曲线、HBM、长期温控/功耗尚未在手机上跑过**，也没有光学仪器验证“视觉亮度严格线性”。第一版成品先让用户体验真实曲线和正常模块生命周期；后续依据实际体验修正映射及场景细节。
