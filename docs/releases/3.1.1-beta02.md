# HyperLux 3.1.1 Beta 02

本地测试版，版本代码 **31105**，构建 `beta-3.1.1-beta02-assist`。继承 Beta 01 / 31104 的全部改动，以正式 3.1.1 / 31100 为发布基线。本轮不推送 GitHub、LSPosed 或官网，不修改 Beta 01 交付物。

## 相对正式 3.1.1 的累计更新

1. 更新弹窗仅在“关于”页显示，异步检查返回时离开关于页也不跨页弹窗。
2. 新增控制中心亮度条节点映射，提供关闭、仅手动亮度、手动和自动亮度三种选择，默认关闭。拖动与回显双向转换，自动模式继续运行，记忆与保护沿用原配置。未开放的范围不会因映射解锁；实际节点比例仍待设备验证。
3. 优化映射设置弹窗，采用纵向选项卡、明确说明和选中状态；确定后修改，取消保留原设置。
4. 主屏手动亮度弹窗新增临时常亮 / 取消临时常亮，仅作用于当前亮屏会话，锁屏熄屏或停用模块后释放，不永久修改系统熄屏时间。
5. 设置入口统一改名为“暂停自动亮度名单”。
6. 保持 legacy API 82。API 102 实验独立归档，不在当前交付包中；更新系统钩子仍需重启一次。
7. 新增移植系统辅助光感补位适配，先支持已经核对到的 ZTE 第二光感身份；具体条件与边界如下。

## Beta 02 新增：移植系统辅助光感

用户分析包显示：移植系统的主亮度引擎已接入，主光感正常；硬件公布了 `zte.sensor.light_second`，而移植过来的辅助光感策略仍按原厂私有类型查找，未取得辅助传感器。采样开关为 true 不代表注册成功。

当模块当前用户的配置已应用、原系统已经允许辅助光感、主屏的原辅助光感对象为空时，枚举实际传感器，寻找唯一、无需额外权限、非唤醒、按变化上报且单位未额外放大的已确认第二光感。依据传感器语义身份识别，不按机型、系统版本号或固定的私有数字类型猜测。

接入原系统辅助光感位置，继续由原有监听器、采样频率、预热、滤波、融合、手电筒 / 场景和锁屏生命周期处理。不新建独立采样进程或常驻传感器监听，不将主光感复制成辅助读数，不伪造有效值。暗光锁定与功能自检同步识别这种已确认的光感身份。

已有原生辅助光感时保持原选择。未知传感器、虚拟双光感组合、多个候选、其他屏幕、策略关闭、单位不明、接口签名变化时保留原系统路径。停用模块、用户切换或策略对象替换时撤销本次绑定；其他组件替换了光感对象时不覆盖其选择。接入或恢复失败会保留可诊断状态，避免影响基础曲线等独立功能。

分析包运行状态新增 `assist_compatibility`，记录接入状态、传感器名称 / 类型 / 语义身份和异常信息，以便区分已绑定与已经收到有效样本。实际读数依旧使用原系统的有效标志。

## 编号与安装

从本轮起，每次对外交付新的 Beta 包，Beta 序号和 APK versionCode 都递增；本包为 **Beta 02 / 31105**，不会继续用 Beta 01 覆盖新交付。

沿用原包名和签名，覆盖安装保留配置。**覆盖安装后重启一次，系统中的新适配代码才会加载。** 控制中心映射仍需系统界面作用域。

## 验证边界

已新增辅助光感补位与恢复、原生传感器优先、默认状态、用户 / 屏幕隔离、权限与单位约束、候选歧义、注册异常回退、暗光锁定消费等本地主机回归，并静态核对用户实际固件的消费者与传感器清单。

目前没有该努比亚移植设备的 Beta 02 实际运行记录，不能宣称硬件已成功上报、所有移植包均适配或功耗已实测。此前 Beta 01 的接口与操作记录不计为新适配的真机通过证据。
