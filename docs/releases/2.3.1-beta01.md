# HyperLux 2.3.1 Beta 01：主屏节点自动识别

本地测试包，未推送 GitHub、发布 Release 或替换官网正式版。包名和签名不变，可覆盖安装 2.3.0。更新后重启一次，让系统进程加载同版本 Hook。

## 解决的问题

用户的 2.3.0 分析包显示系统 Hook 已接入、设备本地 physical_mapping 曲线已识别，但主屏手动面板提示未找到节点。该功能的 Java 检测和 C 写入均写死 panel0-backlight；这台设备没有采集到标准 backlight 节点。原分析包未包含 LED 类，不能确认它具体使用哪个替代路径，也不能据此认定临时 Root 不支持本应用。

## 修改

- 手动面板自动枚举 `/sys/class/backlight` 和 `/sys/class/leds`。优先选择明确标记主屏的节点；LED 类仅接受已知 LCD/显示背光名称。普通 backlight 类无明确主屏标记时，只有唯一有效候选才允许选择。
- 排除已知副屏、键盘灯、按键灯、通知灯、闪光灯等。多个明确显示节点时拒绝猜测。多个别名指向同一真实文件时合并。
- 检查真实 sysfs 设备路径、亮度和最大值配对、整数范围和当前值。单次枚举数量和读取长度有限制。只读识别，不写亮度测试；识别成功不等于驱动写入已验证。
- 检测结果、写入和读回使用同一个选择。C 写入器重新验证允许的节点类别、真实路径、文件身份和范围；关闭自动亮度前先尝试打开写入句柄，不修改亮度。保持检测、系统租约、锁屏/AOD 退让和恢复自动亮度的行为。
- 权限记录绑定节点路径、真实路径、设备号、inode 和本次启动 ID。恢复时通过已验证文件句柄修改权限，不把旧记录套到别的节点；新启动的旧 sysfs 记录仅丢弃。兼容旧版本仅包含权限数字的 panel0 记录。
- 面板区分未找到节点、多个候选、扫描不完整、节点只读与守护节点不一致。分析包包含完整候选及排除原因，并新增 LED 节点读数。

## 范围

自动亮度继续使用系统亮度机制。节点发现用于主屏手动磁贴，不新增自动模式的节点写入或后台全目录循环搜索。节点最大值是驱动代码范围，不能直接解释为 nit 或保证突破系统可用亮度；有些设备只提供低位数 LED 范围，或不开放可直接写入的文件接口。

## 验证与测试

构建执行生产识别器的主机文件系统测试（主/副屏、MediaTek 常见 LCD LED 名称、普通 LED 排除、别名合并、歧义、缺失文件、数值越界、读取上限）、原生路径及权限记录解析测试，以及现有曲线、记忆、系统租约、守护通信、锁屏退让、固件接口检查和 APK 签名检查。主机测试与静态固件检查不等于该用户设备的实机验证。

请让发生问题的用户覆盖安装本 APK 并重启，打开主屏亮度磁贴。识别出节点后，先小幅拖动，核对节点读回、自动亮度关闭和磁贴激活；再检查锁屏/AOD 不被干扰、解锁恢复、开启系统自动亮度后退让。如仍提示不可用，直接导出本版本分析包即可，无须另外运行节点采集脚本。
