# HyperLux 4.4.0 Beta 02

1. 统一曲线百分比的参照，100%对应本机普通手动亮度上限，改善部分传统曲线设备的显示比例。
2. 继续修复重启后控制中心映射需打开APP的问题，补充独立的Root开机恢复入口。
3. 减少无关操作时的作用域提示，并完善启动恢复诊断。

## 详细更新

累计基线为上一个公开正式版 **4.4.0 / 44000**，本文件包含之后Beta 01—02的改动。当前 **44002 / beta-4.4.0-beta02**；仅本地，不更新公开渠道。

### Beta 02

- 状态页、基础曲线、手动记忆和节点百分比输入共用普通手动亮度标尺。Refactor及系数路线读取原生滑条顶端的逻辑亮度；两种传统物理映射读取原生普通亮度边界，并经本机brightness/backlight/nit链换算。不使用固定机型值，也不把临时温控、当前环境动态限亮当作稳定轴上限。
- 高亮区与普通手动区分开：全设备的编辑、存储和实际输出域继续保留。原有高亮点不重写；高于普通手动上限的旧点仍可点击编辑，以大于100%的数值表达。未能确认手动标尺时保留旧范围，不阻止曲线和记忆工作。
- 新包反馈显示Beta 01的Android后台恢复任务直到打开APP后才执行。增加Root受管service.d入口，复用同一恢复命令和节点所有权检查，不再仅依赖APP后台任务获准启动。
- 保存映射开启时登记受管启动文件，关闭后撤回；未知文件和符号链接不覆盖。开机只有限等待和重试，重新从系统包管理读取当前APK；不依赖固定APK路径，不恢复旧亮度或旧手势，不新增永久APP服务。
- Root开机入口的配置、实际恢复结果及日志单独记录，并在详细兼容路线中区分Android任务与Root入口。目录可写、入口已配置不等于所有Root实现都已验证会执行。
- 原签名、全部已保存设置、旧兼容路线和raw10节点程序保持。覆盖安装后先打开一次APP完成入口登记，再重启加载新版系统钩子及验证开机恢复。

### Beta 01

- 开机解锁后，由Android系统一次性任务为已保存开启的映射重新绑定当前引擎、标定和节点监听。接口未就绪最多四次等待，Root拒绝停止，不回放旧操作。
- 作用域只在修改映射模式、分区上限和返回行为时按需提醒；页面打开、无关保存、重复选中和同一草稿不重复弹窗。
- 数据库未知但当前SystemUI注入已核验时不误报缺失，手动核对和用户确认的重启按钮保留。
- 功能自检与分析包增加启动恢复状态，区分系统注入、配置与Root监听。

完成完整主线主机回归、已有固件静态核对和产物一致性检查。本轮无在线ADB设备，不把脚本模拟执行、目录测试和坐标测试等同真实开机或亮度实测。
