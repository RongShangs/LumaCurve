# HyperLux 2.0.3-test01：参数研究、逻辑审查与测试说明

本文件保留发布前测试版 `test-2.0.3-r1`（20003）的研究记录。该测试阶段未推送、未替换官网。后续整理界面并修复 Settings 导出后发布正式 2.0.3，最终产物和更新内容以 [正式发布说明](2.0.3.md) 为准。

继续采用 Root + LSPosed，在 system_server 的主屏显示线程中调整系统曲线及已核实的参数。没有重新引入背光写入 daemon、Java broker、额外光感采集或常驻定时工作线程。新增高级设置分为五组，共 14 个数值参数，五组默认全部关闭。

## 研究依据及可信范围

使用此前提供的 OS4.0.0.41 与 OS4.0.0.28 两份固件，以及已有显示状态与分析记录。逐项核对实际消费者、字段类型、方法签名、时间单位和保护条件，而非仅凭字段名称添加开关。

两份 `services.jar` SHA-256 相同，`miui-services.jar` 不同；但本次比较的六个类方法体一致：`AutomaticBrightnessController`、`DualSensorPolicy`、`HysteresisLevelsImpl`、`RefactorAutoBrightnessAnimator`、`SunlightController`、`TouchCoverProtectionHelper`。此结论只覆盖这两份输入，不能推广为所有 HyperOS 4 或未来 OTA。固件和反汇编不包含在 APK、源码包中。

关键证据：

- 现有显示记录：主光感 `mAmbientLightHorizonLong=3000`，主亮/暗基础确认各 1000 ms，微小变亮基础确认 5000 ms。
- 两份固件都按 5000 ms 修剪辅助光感历史；修剪会推进最老样本时间，因此不能无限加长基于历史证据的确认期限。
- 变暗期限除基础确认外，还可能包含运动、驾驶相关附加时间。
- `TouchCoverProtectionHelper.mTouchEventDebounce` 是**整数秒**，查询时再乘 1000；不能当作毫秒。
- Refactor 动画的 `mDuration`、`mDurationTime` 是秒，`getDuration()` 转为毫秒并扣除已过去时间。动画在感知亮度坐标上推进。
- 小米手动阳光屏进入/退出基础等待为 5000/2000 ms，历史为 10000 ms；自动 HBM 使用另一套控制器。

AOSP 的 [自动亮度控制器](https://android.googlesource.com/platform/frameworks/base.git/+/master/services/core/java/com/android/server/display/AutomaticBrightnessController.java)与 [高亮度控制器](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/display/HighBrightnessModeController.java)用于理解通用链路。小米定制部分以提供固件的方法体为依据，AOSP 不能证明其实现相同。

## 实际亮度链路

一般路径为：系统接收主/辅助光感 → 独立历史与快慢滤波 → 双侧参考及场景抑制 → 照度越过亮暗阈值并持续确认 → 标准映射或 Refactor 曲线 → 手动锚点与场景修正 → 输出策略、SDR/HDR、HBM、温控等约束 → 系统过渡动画 → 屏幕亮度。

距离、触摸遮挡、辅助重置、反射、运动、驾驶等机制可能延迟或抑制更新。这些步骤存在分支，当前蓝色曲线不等于所有场景最终输出。标准映射与 Refactor 并存，也不能据此推断有两套独立、互相竞争的自动亮度系统。

APP 主/辅助光感来自系统当前滤波和参考状态，**不是芯片原始 RGBC**。同一空间的两侧不必具有相同照度；方向、透光、增益、积分时间、屏幕补偿与驱动处理都可能不同。RGBC 未经这些量归一化，不能仅凭计数接近断定标定差几十倍。本版不擅自乘前置照度，也不拿后置覆盖前置。

## 新增的 14 个参数

每组先打开「自定义」，修改后点击顶部「保存并应用」。接口未兼容时禁用；OTA 后已启用但失去兼容的组仍允许关闭。默认关闭时沿用系统。表内默认值是开启该组后的初始值，不代表每台手机官方默认。

| 组 | 参数 | 范围 | 初始值 | 作用 |
| --- | --- | --- | --- | --- |
| 变化阈值 | 变亮阈值倍率 | 0.5～3× | 1× | 放大/缩小系统变亮照度差 |
| 变化阈值 | 变暗阈值倍率 | 0.5～3× | 1× | 放大/缩小系统变暗照度差 |
| 变化阈值 | 微小变亮阈值倍率 | 0.5～3× | 1× | 不超过正常变亮阈值 |
| 变化阈值 | 最小变亮照度差 | 0～10 lux | 0 | 增加最低变亮变化幅度 |
| 变化阈值 | 最小变暗照度差 | 0～10 lux | 0 | 增加最低变暗变化幅度 |
| 变化阈值 | 自定义阈值照度上限 | 10～2000 lux | 200 | 上限之外保持系统阈值 |
| 辅助确认 | 辅助变亮确认 | 0.5～4 秒 | 1 秒 | 普通变亮独立等待 |
| 辅助确认 | 辅助变暗确认 | 0.5～4 秒 | 2 秒 | 变暗独立等待 |
| 辅助确认 | 辅助微小变亮确认 | 0.5～4 秒 | 3 秒 | 小幅变亮独立等待 |
| 过渡动画 | 变亮时长倍率 | 0.5～3× | 1× | 乘在本次系统感知过渡时长上 |
| 过渡动画 | 变暗时长倍率 | 0.5～3× | 1× | 变暗独立设置 |
| 手动阳光屏 | 阳光屏进入确认 | 1～8 秒 | 5 秒 | 调整进入证据等待 |
| 手动阳光屏 | 阳光屏退出确认 | 0.5～8 秒 | 2 秒 | 调整退出证据等待 |
| 触摸遮挡保护 | 触摸释放等待 | 0～5 秒，整数 | 1 秒 | 手指离开后的附加保护等待 |

阈值、辅助确认、触摸释放调整只在已启用配置、主屏自动亮度、有效照度、屏幕正常点亮、非闲置、非驾驶且确认非 HDR 时介入。阈值还避开 HBM 最低照度以上的分支。用线程作用域及对象身份限定消费者，避免共享阈值对象把改动带给其他屏幕。

动画只调整自动亮度策略的新过渡，避开最近手动调整窗口；保留零时长立即跳转，不重启动画，不改变 nit/逻辑亮度转换。**时长倍率不是物理 nit 或背光代码的线性速度。**已有过渡不会因拖动设置滑块重新开始，仍需保存才提交。

手动阳光屏还要求系统已开启相关光感、屏幕点亮、处于手动亮度且确认非 HDR。不强制启动增强、不提高上限、不改 HBM 预算。自动模式下该组计数不增长是预期。

触摸释放设 0 只取消移开后的附加等待；系统仍判定手指位于遮挡区域时，保护始终保留。游戏场景另有 180 秒触摸关联判据，本次未修改。

建议倍率先试 1.2～1.5×，最低照度差保持 0，再观察。极暗处的大变暗照度差可能要求更明显下降才越过阈值；传感器贴近其低值范围时，不要设远高于环境本身的最低差，也不要一次全部拉满。

## 原有参数的配合与实际边界

保留曲线编辑/预设、记忆强度/连续调节间隔/记忆照度范围、显示层温控放宽/温度阈值/冷却幅度、主亮暗确认、主微小变亮确认、暗光稳定及界面刷新。

- 主自定义亮/暗/微小变亮仍可保存 0.5～10 / 1～15 / 0.5～15 秒目标，**实际新增等待受本机历史窗口限制**。设置底部显示最近采用的基础确认时间。
- 主等待按窗口扣除系统附加时间及 250 ms 调度余量；窗口未知或已占满时保持系统结果，不延长滤波历史。
- 暗光稳定是最短等待，与主/辅助自定义同时开启取较长要求，不缩短系统已有更长等待。
- 例如主窗口 3000 ms、附加时间为 0：暗光稳定要求 3000/4000 ms 时，可增加的基础确认上限为 2750 ms。此为边界计算示例，不是所有设备统一值。
- 主微小变亮基础等待可能本来为 5000 ms，不开启自定义时保留它；不擅自改写所有系统基础等待。
- 更新这些设置但曲线未变化时保留手动锚点；更换曲线、主动清除或停用仍可重建锚点。

## 隐藏机制与尚未开放的部分

亮度分支弹窗新增可取得的触摸遮挡、距离遮挡、夜间唤醒/驾驶、反射、运动、辅助重置、手动阳光屏、HBM 控制器/时间/照度/省电、HDR 图层及杜比条件。详细读数与分析包保留完整字段。

字段不存在表示「未取得」，不是关闭。状态是读取时快照，计数是本次系统进程累计，不代表当前每一帧改写；较晚一次输出记录不能直接归因于较早的计算记录。

| 机制 | 本版处理 | 未开放原因 |
| --- | --- | --- |
| HBM 时间预算与冷却 | 只读展示 | 依赖固件、硬件与使用历史，预算 0 不能单独解释为无限制或完全关闭 |
| 手动最高亮度、扫码增强 | 保留系统 | 动态上限与条件，缺少通用改写证据 |
| 主/辅助增益、积分时间、标定、屏幕补偿 | 保留系统/驱动 | 无归一化与标定证据，照度倍率可能掩盖问题 |
| 光感频率与快慢滤波窗口 | 保留系统 | 同时影响证据有效期、唤醒及功耗，不能只加时长滑块 |
| 反射、AON、驾驶、运动、游戏距离保护 | 观测，保留判定 | 依赖多传感器及异步服务，并非每台均启用 |
| 夜间唤醒、AOD、口袋恢复 | 观测，保留交接 | 正常点亮、唤醒和息屏显示条件不同 |
| HDR、杜比、应用指定/临时亮度 | 保留输出策略 | 曲线不是这些路径唯一决定因素 |
| Thermal HAL、内核与驱动温控 | 保留系统 | 当前可调项只针对已验证的显示层限亮入口 |

没有凭字段存在就开放“关闭所有场景保护”“无限阳光屏”等选项。

## 发现、修正与优化

1. **时间窗口**：避免自定义期限超过证据而不断向后移动；修正暗光稳定越窗时原本整段退回基础时间的问题，允许在窗口内增加部分等待。
2. **阈值边界**：系统扫描用严格小于。新倍率把正照度的变暗阈值压到零时保留极小正阈值，让真实零照度仍能越过；不改传感器输入。
3. **介入条件**：核对屏幕、自动亮度、照度有效性、HDR、闲置与驾驶；条件未知时保持系统。动画另核对输出策略和最近手动操作。
4. **事务与恢复**：Root 提交和显示线程双重校验高级类型/范围及兼容，先验证再改曲线。停用、错误回退、用户切换清除高级改写；触摸原方法抛错也恢复临时字段。
5. **缓存**：应用/停用重新计算主/辅助阈值缓存；动画仅在仍等于本应用改写值时恢复，不覆盖后续系统更新。
6. **启动重试**：控制器未就绪导致接入失败时最多三次，按 1/2 秒安排重试，避免单次早期失败永久失去接入，不无限轮询重启。
7. **反射复用**：按类/字段缓存，减少重复查询，不增额外进程或周期工作线程。
8. **导出预算**：原有单项超时和大小/数量边界外，增加 180 秒总体采集预算；记录跳过/截断并校验 ZIP。极端阻塞 I/O 和校验不等于严格 180 秒总墙钟上限，外层仍有超时保护。
9. **解释与翻译**：显示条件、计数、最近确认时间和状态过期；界面触摸状态探测不计入控制改写。新增中英双语，修正长短词条重叠。

当前手动偏好是小米 Refactor 锚点记忆调整，非本应用持久化的无限长期训练，不能保证锚点跨重启保存。当前曲线为三个可编辑基准点与固定最高端，非旧 KSU 的 14 点曲线。

尚无直接证据证明既往侧躺变暗又变亮全部出自一个原因；这些参数用于分别验证确认、阈值、触摸等原因，不能一次全开后宣称已解决。没有新增实机性能数据，不能因“不加进程”宣称零占用或零耗电。

## 本地验证

本次本地构建通过以下结果，并记录在合集 `build-info.json`：

- 868 项主机逻辑：参数边界、阈值/时间窗口、曲线/记忆/恢复及翻译。
- 26 项采集与名单：真实 JSON、文件/命令限制、超时、总体预算与 ZIP 清单。
- 115 项可选 Hook 回调模型：默认关闭、主屏作用域、共享对象、HDR/手动/驾驶/闲置跳过、动画恢复、触摸异常恢复和辅助独立确认。
- 78 项新增两份固件消费者、单位及方法体检查；原有曲线/温控/传感器/记忆检查通过。
- APK 编译、签名、对齐及归档一致性，沿用现有签名支持覆盖安装。

这些是本地逻辑、模型和固件静态验证，**不是 Android 实机或 ART Hook 运行验证**。设备效果、布局和资源增量需本轮实测。

## 建议测试顺序

1. 覆盖安装，LSPosed 保持「系统框架」作用域，重启一次。确认版本 `2.0.3-test01`，详细读数构建 `test-2.0.3-r1`。安装 APK 不会自动替换已运行的旧 system_server Hook。
2. 先保持新增五组关闭，保留个人曲线与旧设置。观察暗处静止、视频、锁屏/解锁和双侧遮挡/松开，排查更新回归。
3. 每次只试一组。小波动先试阈值 1.2～1.5×；短暂遮挡试主/辅助确认；改变过渡速度再试时长倍率。核对计数和实际确认时间。
4. 同一照明下试触摸遮挡区域后移开、背面向下放桌面再拿起、侧躺刷视频。发生异常记时间、动作、HDR 状态，立即导出分析包。
5. 测试暗到亮、亮到暗的明显变化，再测试持续暗光，不能只观察保持不动而漏掉无法变暗。
6. 手动滑块应立即响应，不受新增动画延迟；随后检查手动记忆、锁屏与明显环境变化后的交接。
7. HDR 进入/退出、AOD、连续锁屏和能实际触发的运动/驾驶场景中，检查高级参数是否交回系统。类存在不等于场景已启用。
8. 手动阳光屏只在系统设置开启且真实条件达到时测试；自动模式中该组不应增长计数。
9. 关闭新增组并保存，再「停用并恢复」，确认系统恢复。OTA 后重新检查兼容并保存，不沿用旧 fingerprint。

分析包保存至内部存储根目录，包含高级配置、计数、场景快照与有界计算/输出历史，不自动上传。

## 产物与恢复

`HyperLux-2.0.3-test01.apk`、对应 `-source.zip`、APK/源码/恢复工具合集 `HyperLux-2.0.3-test01.zip`。合集是普通 ZIP，**不是 KSU 刷入模块**。

恢复脚本和辅助 jar 解压到同一目录后，在该目录执行相对路径命令：

```sh
su
sh ./restore_refactor_hook_android.sh
```

也可 APP 停用或取消 LSPosed 模块并重启。无需替换 framework/services.jar。测试完成后再决定是否发布，当前正式下载保持 2.0.2。
