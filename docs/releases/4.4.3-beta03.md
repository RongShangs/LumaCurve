# HyperLux 4.4.3 Beta 03

1. 改善控制中心节点映射和主屏亮度磁贴的启动兼容，处理可信私有文件权限残留导致的启动失败。
2. 完善节点程序升级恢复和错误诊断，保留已保存设置与原有兼容。
3. 累计包含小米12S Pro状态及日志修复、Redmi K60 HyperOS 1旧接口适配。

## 详细更新

累计基线为上一个已公开正式版 **4.4.3 /44300**；本版 **4.4.3-beta03 /44303** 仅本地交付，不发布。

### Beta 03

- K90 Pro Max分析包显示节点识别、曲线和Root读写正常，但磁贴与映射共用的原生程序在私有锁检查退出；本次快照的映射实际模式为关闭，分区设置尚未成功应用。
- 在验证Root、可信父目录、真实路径、所有者和打开对象后，规范本模块私有目录及锁权限；锁始终保留同一文件对象，拒绝符号链接、硬链接、非Root所有者及正在占用的锁，不强行解除其他会话。
- 候选程序先完成原生恢复再原子替换，避免旧程序的同一检查问题阻止升级；失败保留原文件，清理本次临时文件，原权限恢复记录继续严格核验。
- 分开报告原生身份、目录、锁占用和权限失败，避免元数据错误显示errno=0 Success；导出分析包补充只读目录与锁文件元数据，不增加持续采样。
- 原生载荷更新为raw11，保留已有就绪协议、节点发现、真实上限及全部旧兼容路线。包内未提供原锁元数据，不能据此断言具体Root工具故障；该机实际恢复仍待安装验证。

### Beta 02

- 分析包显示物理曲线已经连接，但完整状态发布反复缺少自动亮度字段，导致APP取不到状态及运行日志；这与没有注入或反复连接曲线不同。
- 新增原生AutomaticBrightnessStrategy/2的有效自动模式读取。保留原owner字段优先，只在字段缺失且主屏、DPC、策略和ABC所有权及签名完整时采用；不使用用户设置缓存代替实时状态，不绕过错误接口。
- 物理和Simple后端在适配器中收束模式，Refactor原路线不变。模式读取错误独立保留，曲线与日志继续发布，不伪造手动模式。
- APP等待运行状态时改为页内提示，自动刷新不再连续Toast；实际不兼容和缺注入提示保留。功能自检可查看所选模式接口及失败原因。
- 保留原配置、原生程序与全部旧兼容，不增加常驻进程或采样。主机及所附固件静态检查通过后打包；尚无该机安装本版后的实际结果。

### Beta 01

- 分析包显示 Android 14 /API34，LSPosed 已注入；曲线初始化失败于不存在的 `getMode()`，并非按 HyperOS 版本号禁止使用。
- 在物理曲线适配器中新增普通／休眠双映射对象 ABI。完整缺失模式编号及映射表时，核验实际 `isForIdleMode()`、普通及休眠对象、当前对象与主屏归属，收束到现有物理 nit 曲线、配置和记忆契约。
- 原模式编号／映射表路径继续优先；任一现代接口标记存在而结构残缺、类型错误或调用失败时，不借旧路径绕过校验。不增加机型白名单、不修改保存的配置语义。
- 保留本机完整曲线、应用修正、短期模型及原生亮度转换。只调整普通映射；系统切入休眠映射时不向其写入曲线或回放普通手动记忆，退出后按真实归属恢复。
- 运行快照及功能自检补充实际采用的映射上下文；新路径没有单独输出程序、额外光感采样或新增常驻进程。
- 主机回归和所附私有固件接口核对分别验证；尚无该 K60 安装本版后的设备结果，不将接口匹配等同于全部功能或物理亮度实测。户外、传感器、温控、过渡、节点等能力仍各自检测。
