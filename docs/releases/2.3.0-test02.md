# HyperLux 2.3.0-test02：主屏完整节点调节

本地测试版，尚未推送或发布正式版。设置分类和可选暗光定时锁定沿用 test01；本版将主屏手动面板改为 bright 项目使用的直接节点接管路线。

## 使用

覆盖安装并重启一次，进入设置保存并应用。添加控制中心「主屏亮度」磁贴，点击只展示独立弹窗，原 APP 的状态、设置、日志和关于不会加载。APP 设置中也可打开同一弹窗。

弹窗显示实际节点值、目标值、节点上限；竖向滑条映射 10 到主屏 max_brightness，支持整数输入。拖动或输入后关闭自动亮度，直接写节点；不按显示框架的普通滑条上限裁切。节点值不是 nit，读回值正确也不等于实际达到了某个 nit，驱动仍有最终限制。高亮会增加发热与耗电。

关闭弹窗继续保持用户选择，Root 查询进程结束，只保留主屏 C 守护及系统端的接管资格检查。重新开启系统自动亮度、锁屏或停用引擎时，撤销接管资格，守护退出并恢复原始权限。锁屏时只释放主屏节点，不强制开启用户选择关闭的自动亮度。反复打开与拖动更新目标，不重复启动多个守护。

## 实现边界

只操作 panel0-backlight 的 brightness 与 max_brightness，绝不操作 panel1。缺少明确主屏节点时不猜测其他背光节点。旧亮度模块占用节点、写入失败或读回不符时报告异常，放弃本次接管。

C 守护在 Root 私有目录运行，独占文件锁，控制 socket 检查对端 UID。先保存原始权限、打开写入 FD，再移除写权限位；后续复用 FD，不每帧重开，不复制过去的自锁死局。正常每 4 秒读节点，被覆盖才补写。无息屏唤醒或常亮功能，无额外唤醒锁；启动时尝试移出 APP 冻结分组，已知冻结根节点无法迁移时不接管。

模式切换由现有系统 Hook 观察，资格租约由 system_server 原子更新，C 守护读取时验证所有者、会话、期限和系统进程存活。自动亮度开启或锁屏后撤销租约，文件变化通知唤醒守护释放节点；无法注册通知时回退为 250ms 检查。系统端每 2 秒续约，8 秒失联自动释放。续约不用 system_server 连接 su socket，避免依赖这条 SELinux 跨域权限。守护失效由健康状态触发退让，不无限保留接管标记。

仅主屏节点接管需要 C 守护；暗光定时锁定的传感器监听仍在 system_server 中。新增路径的功耗与兼容性尚需真实设备测试，不沿用旧版本性能数字。

## 验证顺序

1. 未使用手动面板时，原有曲线、记忆、暗光稳定和暗光定时锁定保持正常。
2. 从磁贴打开，确认只弹出浮动面板。低、中、高分别拖动，确认目标值与实际节点值匹配；测试输入整数。
3. 连续拖动、迅速换方向、重复打开弹窗，确认最终选择生效，只有一个 C 守护。
4. 关闭弹窗，等待 30 秒确认节点保持；观察 APP/Root 查询进程结束，C 守护仍在。
5. 从控制中心开启自动亮度，确认节点恢复可写，守护退出，系统亮度重新接管；旧拖动请求不能再次关闭自动。
6. 接管中锁屏、解锁，确认释放节点，用户手动模式保留；需要重新滑动才再次接管。
7. 停用引擎、恢复自动按钮与恢复脚本分别测试，确认不残留 0444 锁定。
8. 检查浅色、深色和横屏弹窗。出现问题导出分析包，附节点目标、实际值及复现步骤。

本地验证包括生产控制器服务替身、原生租约/会话/范围与协议格式、既有回归测试、ARM64 编译、APK 签名及源码一致性检查。未连接 Android 设备，本版不能宣称通过实机背光、SELinux 或冻结机制验证。

停止工具：完整包解压后，Root 终端运行 sh ./restore_refactor_hook_android.sh。如果守护曾被 SIGKILL，恢复工具会使用私有权限记录释放节点。

息屏与 AOD：同时监听息屏广播和主屏显示状态；DOZE/OFF 或失去交互立即清除接管许可，原生守护监听许可文件变化后释放节点。零背光不再被守护重新顶亮。重新亮屏不自动恢复节点接管，必须再次手动滑动。
