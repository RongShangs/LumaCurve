# HyperLux 2.3.1-beta03：暗光修复测试版

本地测试版，不推送 GitHub，不创建 Release，不替换官网正式包。可覆盖安装，更新后需重启手机，让 Android 系统进程加载新版 Hook。

## 暗光定时锁定

旧实现虽然注册了光感监听，但把不同 SensorManager 产生的 Sensor 对象按实例相等匹配，可能丢掉有效回调，导致暗光计时一直不开始。

现在使用系统亮度控制器实际持有的 SensorManager，并按传感器类型和硬件 handle 匹配。管理器、传感器或照度放大系数变更时，释放旧监听并重新计时。分析包增加主辅回调数量、未匹配回调数量和读数年龄；未收到有效光感时显示“等待光感读数”。

仍需主辅光感及系统确认照度符合进入条件，连续达到设定分钟数才锁定。环境持续超过退出阈值后恢复自动，锁屏时退出。无效输入不会触发锁定。

## 暗光小幅变亮

旧阈值 Hook 调用仅查找公开方法的反射接口，而实际固件的 HBM 数据方法受保护，异常被静默忽略，导致暗光变化阈值看似开启却没有生效。

现在读取实际 HBM 数据字段，恢复暗光阈值对正常升亮和小幅升亮分支的作用，保留 HBM/HDR 和非适用场景的边界。接口异常会进入日志和详细状态。

辅助光感新鲜、有效且覆盖至少一秒的零值历史，可以参与有限时长的主光感升亮确认；无效、过期、明显环境变化、确认时间结束仍放行。没有改写光感值，也不把所有暗光变化一律冻结。

## 输出路径

beta02 新增的 MediaTek 框架输出通道已撤回。该用户确认手动面板无效来自临时 Root 对 sysfs 写入的限制，现有证据不足以归因于显示链路。此次保留 beta01 的主屏节点自动识别和原有直接写入方式；不能绕过 Root 环境对节点写入的限制。

## 验证与使用

已覆盖同硬件不同 Sensor 实例、错误 handle、SensorManager 更换、连续暗光计时、锁定后的环境退出、锁屏退让、受保护 HBM 接口、正常/小幅阈值、有效零值与无效/过期辅助证据等回归场景，并核对用户固件中的字段和接口。主机模型与固件静态检查不能代替实机体验确认。

安装后重启，保留原设置。在满足设定暗光条件的环境中保持亮屏，查看暗光计时是否递减，到时是否关闭自动亮度并保持。再验证环境明显变亮及锁屏退出。暗光阈值开启时，分析包应显示 `low_light_threshold_adjustments` 增加，且 `threshold_error` 为空。若仍有小幅升亮，请导出此版本分析包，保留发生时间和当时环境。
