# HyperLux 2.0.4-test01：自动选择设备曲线后端

开发阶段研究记录：当时仅作本地测试，正式版为 2.0.3。该实现现已整理为正式 2.0.4，安装与版本信息以 [正式更新说明](2.0.4.md) 为准。

部分 HyperOS 4 固件使用传统物理亮度映射，而没有启用 RefactorNitController。此前 LSPosed 已注入，也可能因没有 Refactor 对象而被错误提示为未接入。

现在按实际控制器和 AutomaticBrightnessController 的运行开关选择后端，不按机型、JAR 哈希或资源基础值选择。支持既有 Refactor、MiuiPhysicalBrightnessMappingStrategy 与 AOSP PhysicalMappingStrategy；接口类型或主屏身份不符合时保留系统行为并报告原因。这不是所有 HyperOS 4 固件均已兼容的承诺。

## 默认基准与编辑

- 从当前主屏实际本地配置读取完整 lux / nit 数组和标定边界，不套另一台手机的曲线。
- 新基准默认 100%；草稿和已保存配置绑定固件、后端与完整基准标识，避免跨机制误用。
- Refactor 保留原编辑方式，单位为系统逻辑 nit。传统映射使用物理 nit；手动输入的 0..1 框架亮度单独转换，不与 nit 混算。
- 传统曲线全部节点保留。四个编辑手柄选在起点、最接近 30 / 600 lux 的原节点和末端；末端固定。手柄之间按原曲线相对高度重塑，100% 精确保留原数组和平台区，不压缩成四条直线。
- 状态页采样系统 spline；设置预览展示完整重塑曲线。保留应用分类修正、短期模型超时/照度范围、色彩采样元数据。
- 由系统重建 spline 与短期模型，继续处理光感、场景、动画、HDR、HBM 和输出保护。手动记忆仍是系统短期记忆，不增加独立长期学习。
- 普通系统重复配置不会抹掉自定义基准；真正的系统/云端配置更换会交回系统并重新读取基准。旧配置需重新应用。
- 停用恢复接入前配置；编辑失败回滚配置、spline、分类映射与记忆。用户切换交回系统；编辑普通曲线不清除闲置模式模型。

## 状态与限制

Root、LSPosed 注入、曲线连接分开显示。状态核对构建、固件、system_server PID 与启动时间，避免上次开机缓存。分析包增加 injection.json、完整基准、后端和坐标。

原有高级选项仍逐项检查。没有 Refactor 动画对象的传统路径不会开放其动画倍率。不同系统接口变化仍可能需要适配。

已核对提供的传统映射固件实际调用链。生产适配器/Hook 合成回调模型覆盖密集曲线、中性设置、编辑、恢复、回滚、元数据、坐标、记忆、重复配置与基准更换，同时执行原 Refactor 和高级选项回归。这不等于 Android/ART 或实机验证，暂未取得安装后的结果。

## 实机测试

1. 覆盖安装 APK，LSPosed 启用 HyperLux、作用域保持系统框架，然后重启。
2. 日志页应分别显示 Root、LSPosed 和曲线状态。传统设备应出现「传统系统曲线 · 设备本地基准」。
3. 所有节点 100%、高级选项关闭，保存并应用，先确认与原自动亮度一致。
4. 固定环境下小幅调低一个中段点并保存；再点停用，核对原基准恢复。
5. 检查滑块与锁屏解锁。异常时导出分析包发回；包含设备固件，请私下传送。

恢复：LSPosed 禁用 HyperLux 并重启；或使用合集恢复脚本，不依赖 APP 已安装。
