# HyperLux 2.3.2-beta01：主屏节点权限检查

版本代码 **23201**，构建 **beta-2.3.2-permission01**。基于 2.3.1 的本地测试包，沿用包名与签名；官网和 GitHub 正式版保持 2.3.1。

## 诊断结论

用户提供的 2026-10-07 19:11 分析包显示：APP 与 Hook 均为 2.3.1，OS4.0，系统曲线后端 physical_mapping；主屏节点为 `/sys/class/backlight/panel0-backlight/brightness`，规范路径位于 `/sys/devices/`，上限 16383，读回 951。节点模式为 0444，Root 采集进程在 ksu 域。主屏守护未连接，包中未包含守护启动日志、权限恢复记录或健康文件。

旧 Java 状态检查仅凭节点没有写权限位就标记 `node_not_writable`，面板随即禁用操作。没有实际尝试打开，因此不能据此认定 Root 无权限或 SELinux 拒绝，也不能认定节点权限是守护崩溃遗留。原生启动和首次接管路径也存在相同的模式位预判。

## 修复

- Java 改用 `O_WRONLY | O_CLOEXEC | O_NOFOLLOW` 实际打开节点，核对打开的文件身份和规范路径后立即关闭。检查不使用截断标志，不写亮度、不改权限、不启动守护、不切换自动亮度。
- 原生启动和首次接管同样以实际打开结果为准，并核对设备、inode 和规范路径。保留同一开机、同一节点绑定的权限记录；原权限为 0444 时，也按原值保存和恢复。
- 原生身份更新为 `raw07-openprobe`，避免旧守护被误认为已具备新权限检查逻辑。
- 若系统实际拒绝打开，诊断包含 `write_probe`、`write_error`、`write_errno` 和 `node_mode`；面板继续显示已取得的节点读回与上限，错误显示 errno。
- 自动亮度、手动会话、屏幕状态、租约、输出隔离、权限恢复及失败回滚规则沿用现有需求。未改用户记忆、暗光或其他配置。

## 验证

新增 `tests/refactor_panel_access.py` 使用实际 Java 状态方法、原生 open/acquire/release 方法及系统调用替身，覆盖 0444/0644/0664 可打开、EPERM/EACCES/EROFS 拒绝、身份变化、打开后检查失败的关闭、守护占用、旧守护拒绝、权限保存和恢复、记录同步失败及 chmod 失败。Java 78 项、原生 52 项；恢复旧 Java 判断的负对照在首个 0444 样例复现错误。

执行完整构建，包括 Java / ARM64 C 编译、既有主机回归、已有私有固件静态核对、签名、对齐和最终 APK 原生资产检查。最终结果以构建日志和合集 `build-info.json` 为准。

没有连接手机验证。打开成功也不能保证驱动接受具体亮度写入；该阶段仍按原逻辑验证读回，失败则回滚。本包修复已确认的预判缺陷，实机可用性需反馈。

## 测试方式

覆盖安装 `HyperLux-2.3.2-beta01.apk` 后重启。打开主屏亮度磁贴，确认读回和上限正常；打开面板不应关闭系统自动亮度。小幅滑动后确认实际亮度改变，再点“恢复自动”。若仍不可用，导出新版分析包，可看到实际打开或写入错误；无需手动放宽整个 sysfs 的权限。

完整 ZIP 包含 APK、源码与恢复工具，不是 KSU 模块。恢复工具或 LSPosed 取消启用并重启仍可使用。
