# HyperLux 2.1.2-test01（本地测试版）

本次增加跟随系统的深色模式，以及系统手动偏好锚点的持久化。不发布 GitHub Release，不更新官网的正式下载。

## 深色模式

四个主页面、设置子页、弹窗、输入框、曲线和状态流程图跟随系统深浅模式。状态栏、导航栏与原生开关也同步切换；二维码图片保留原色。切换主题造成 Activity 重建时，通过实例状态保留尚未应用的设置和当前设置子页，并在设备基准一致时恢复草稿。

## 手动记忆

- “跨重启保留手动记忆”默认开启，可单独关闭。
- 保留期限为最近一次保存起 1～90 天，默认 30 天。
- 持久化节点上限可设为自动或手动限制，界面读取本机能力。当前 Refactor 容器最多容纳 7 个总锚点（包含 4 个基础节点；手动调整也可能修改基础位置）；传统物理映射只支持恢复一个手动偏好点。这不是将基础曲线扩展为 7 点。
- 保存实际被系统接受的手动节点，按系统手动顺序保留最近节点；每次拖动结束后合并约 1.5 秒再写入，记录有大小上限。
- 恢复使用系统原有 `updateLogicalCurve` 或 `setScreenBrightnessByUser(lux, brightness)`，保留系统插值、动画和输出链路。传统后端同时恢复其短期模型。恢复不重复计算一次学习，也不增加手动事件计数。
- 记录绑定固件指纹、设备完整曲线、当前编辑基准和用户身份；修改基础曲线、系统更新、用户切换后不套用旧记录。普通确认时间、温控等设置变化不改变曲线身份。
- 启动与熄屏/自动亮度交接后，只有自动亮度、主屏普通映射、亮屏且身份一致时才恢复。系统因较大环境变化清除的短期记忆不在同一场景被反复插回。
- 新的手动选择优先于存档；无法识别的接口、过期或损坏记录不影响系统继续调节。关闭持久化保留存档，停止自动保存与恢复。
- 清除入口同时删除实时与已保存的记忆，并单独记录清除请求已处理，避免重启后重复执行旧清除请求。分析包新增 `manual-memory.json`。
- 配置导入导出包含这些选项，但不包含设备私有记忆数据；从旧配置导入时缺少的新选项使用默认值，节点上限按本机能力调整。

## 为什么暂不扩为 8 个基础节点

当前已提供的 Refactor 固件中，锚点数组、插入溢出判断与数组复制写死为 7，默认重建写死为 4；默认插值还依赖三个亮度字段。只把 UI 改为 8 点或扩充数组都无法让系统完整使用新增基础节点，还会挤占手动记忆。因此本轮保留 4 个编辑节点，不替换系统曲线算法。传统映射仍保留原设备的完整密集节点。

## 实机验证

覆盖安装 APK 后重启手机以加载新 Hook，保持 LSPosed 的系统框架作用域。

1. 保存并应用，在固定光照下手动拖动控制中心亮度条，松手约 2 秒后查看“手动记忆已保存”和节点数量。
2. 锁屏后解锁，再重启一次，查看记忆恢复状态和恢复次数。若系统仍保有新的实时手动点，存档不会覆盖它。
3. 调小持久化节点上限，继续在不同照度下调节，确认保存/恢复数量不超过设定值及本机能力。
4. 清除手动记忆，重启后确认不会恢复已清除的节点；重新手动调节、保存，再重启，确认旧清除请求不会再次清除新记忆。
5. 切换持久化开关、改变基础曲线或明显改变环境照度，确认不会反复恢复旧亮度。系统仍有自己的场景判断和短期记忆规则。
6. 在任一设置子页修改但不保存，切换系统深浅模式，确认页面和草稿仍在，并检查曲线、弹窗与输入框颜色。

主机测试与已提供固件的静态分析不替代上述实机测试。本地包内 `build-info.json` 包含构建时的验证结果。
