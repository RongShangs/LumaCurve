# HyperLux 2.0.4-test02：传统曲线用户身份修复

开发阶段修复记录：测试包构建 `test-2.0.4-user02`，版本代码 `20004`，当时仅本地测试。用户确认修复有效后，已并入正式 `release-2.0.4-r2`；安装以 [正式更新说明](2.0.4.md) 为准。

## 现场结论

提供的 K90PM 分析包运行 `test-2.0.4-traditional01`。LSPosed 注入、传统物理映射与完整本机曲线均已连接，状态中 `user_serial=-1`、`consumed=0`，配置未启用。保存请求被用户身份检查拒绝，尚未进入系统曲线重建。此报错不能证明曲线或温控修改本身失败。

## 修复

- 不再在 `system_server` 加载早期只查询一次并永久保留未知用户。传统曲线启动、配置读取及前台刷新时重新核对前台用户，并转换为系统显示回调使用的用户序列号。
- 保存前等待 Hook 刷新身份与状态，仍要求前台为主用户且曲线归属主用户；未知身份给出尚未就绪提示，保留多用户隔离。
- 未知身份不再能与未知配置用户判为匹配。用户切换后更新归属并发布状态，诊断补充身份是否就绪及来源。

不会新增光感订阅或逐帧查询用户服务，也不更改默认曲线、编辑幅度和系统亮度控制。

## 测试方法

1. 覆盖安装 `HyperLux-2.0.4-test02.apk`，LSPosed 保持系统框架作用域，**重启一次**以加载新 Hook。
2. 主用户进入日志页，详细读数应显示 `build=test-2.0.4-user02`、`user_serial=0`、`user_identity_ready=true`。
3. 系统默认曲线、所有编辑点 100%，点击保存并应用，状态应进入已应用；再小幅改变一处并保存，观察输出，最后停用恢复。
4. 如果仍失败，导出新分析包核对身份来源与完整错误。此前没有提交成功的曲线需要重新保存；不要求清除 APP 数据或重新开关自动亮度。

本地模型和固件核对不等于实机验证。完整 ZIP 为 APK、源码与恢复工具合集，不是 KSU 模块。
