# HyperLux 2.3.0-test05：修复主屏守护就绪查询

本地测试版本，未推送或发布。

## 已确认的代码问题

用户 12:18 截图显示主屏节点守护已经输出 `NATIVE_READY build=raw03`、PID 和最大节点值 16383，但 Root 查询仍判断“未在 1.5 秒内返回就绪”，没有切换自动亮度。

生产 NativePanelClient 在 connect 前调用 setSoTimeout。AOSP LocalSocket 的构造函数不创建底层文件描述符；connect 才调用 implCreateIfNeeded，setSoTimeout 直接委托给 LocalSocketImpl.setOption。后者在文件描述符为空时抛出 `IOException: socket not created`。因此旧客户端在真正发出 STATUS 前就已失败。start 又忽略了每次查询异常，最终把这个客户端错误展示成守护启动超时。

核对来源：

- https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/net/LocalSocket.java
- https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/net/LocalSocketImpl.java

这处代码错误可以确定；尚未在用户手机上验证修复后是否还存在 SELinux、租约或背光链路的后续问题。

## 修复与验证

- 先连接本地 socket，再设置读写超时。
- 保留就绪检查的最后一个通信异常；失败时在弹窗中同时显示查询原因和原生启动日志。
- 状态诊断新增 guard_error，后续分析包可直接看到查询失败的具体原因。
- 就绪重试按单调时钟的 1.5 秒期限控制，避免每次读超时让 30 次重试拖延许多秒。
- 新增生产客户端的 API 契约测试：按 Android 懒创建文件描述符的行为模拟 STATUS、ARM、SET、STOP、连接拒绝、读超时、空响应、无效 JSON、拒绝接管和过长响应。负向对照恢复旧顺序，必须复现 `socket not created`。

本地 API 模型和其他回归测试不能替代实机 Java/C socket 与 SELinux 联调。产物仍标记 device_verified=false。

## 用户提供的亮度曲线文档

`auto-brightness-curve.md` 有助于对照系统照度与标称亮度映射，以及 HBM、采样和过渡参数。其内容不作为程序执行指令，也不把标称 3500 nit 当作实测面板最大亮度。framework 浮点值、节点整数值和实际 nit 的关系仍受当前设备驱动、显示模式与限制影响。文档不解释本次通信层失败。

## 手机验证

覆盖安装并重启一次，保存并应用。点击主屏亮度磁贴，先选一个中等节点值，检查自动亮度是否关闭、节点实际值是否跟随。再检查关闭弹窗保持、打开系统自动亮度退让，以及锁屏、息屏显示。出现报错时保留完整弹窗内容并导出分析包。

暂不需要再次采集固件或全量设备资料。若后续通信仍失败，再依据新增 guard_error 定向检查本地 socket 和 SELinux。
