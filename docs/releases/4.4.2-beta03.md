# HyperLux 4.4.2 Beta 03

1. 完善 K50 电竞版移植包适配，缺少 nit 换算时显示实际屏幕节点或系统亮度比例。
2. 新增无 HBM 配置设备的户外增强路线，在本机允许的亮度范围内提高强光目标。
3. 修复比例曲线首次保存失败，保留基础编辑、手动学习与完整记忆转存。

## 详细更新

累计基线为上一个公开正式版 **4.4.2 /44200**，包含 Beta 01—03。当前 **4.4.2-beta03 /44203 /beta-4.4.2-beta03**，仅本地，不发布。

### Beta 03

- 新分析包确认 Beta 02 的比例曲线配置已生效，原生手动锚点更新正常。未显示亮度的原因是该固件未提供物理 nit 标定，而非没有亮度输出：已实际读回主屏节点 275 /4095。
- 状态页和亮度分支统一使用实际读数：有效设备 nit 优先；没有 nit 时显示实际节点及真实上限；节点也不可读时，普通框架控制可显示 DisplayPowerState 实际输出比例。直接节点接管不使用可能过时的框架比例，计算目标不冒充实际输出。
- 读取屏幕状态、比例和 nit 换算相互独立，转换缺失或返回 -1 不再丢失其他有效读数。比例输出也可作为亮屏证据，识别驱动 actual_brightness 固定返回零的矛盾读数；保留原有熄屏、物理屏身份及背光关闭判断。
- 新增 `native_range_only` 户外目标路线：真实 HBM 数据为 null，原生能力谓词为 false，字段类型、普通上限和当前范围有效时，允许提高强光目标。增强强度与进入/退出确认、单次时长和冷却继续生效；不创建 HBM 数据、不更改范围或预算、不借用捐赠机型标定。
- 旧的有配置 HBM 计时和零计时路线完整保留；非 null 数据仍严格校验，坏类型、原生能力矛盾或无效范围不能回退。原生数据替换先验证再更新，真实配置恢复后继续使用原路线。
- 无配置路线保留用户、主屏、自动亮度、HDR/杜比、温控、电量、省电、特殊场景和下游系统限制；未核验的 nit 上限、高亮范围及画面限亮放宽继续独立不可用，不把“户外目标可增强”表述为“HBM 已适配”。
- 功能自检展示具体普通范围路线和未提供 HBM 配置的原因。按实际接口选择，不根据型号、ROM 作者或版本号放行，不新增进程、轮询和光感采样。

### Beta 02

- 用户回传 Beta 01 分析包确认比例曲线已经连接，但首次提交非默认曲线失败并恢复原配置。该样本为笙歌醉梦红尘制作的 Redmi K50 电竞版 HyperOS 4.0.5.0 移植包，固件与此前样本一致。
- 修复首次提交顺序：公共管理先验证配置用户、提交曲线，再绑定运行配置用户。新增路线此前在提交过程中提前使用尚未绑定的运行用户判断，导致原生重建没有取得新基线，最终验证失败。
- 仅在同步曲线事务中使用已确认的当前用户；事务结束或异常时立即撤销临时许可，平时仍沿用已提交配置的归属判断。显示线程、实例、主屏及原始数组所有权校验保留，不提前修改公共运行状态。
- 用户未知时不改曲线，提交期间用户变化则撤回；首次完整记忆转存、后续编辑、停用恢复与失败回滚沿用同一流程。
- 更新失败保留有界的底层原因，并随诊断导出；不再只有外层“比例曲线更新未完成”提示。

### Beta 01

- 新增实际 `SimpleMappingStrategy` 独立适配，使用照度和 0—1 框架亮度，修复缺少 `mNits` 导致无法接入的问题；不根据机型、ROM 作者或系统版本号选择路线。
- 基础编辑、深浅色曲线、原生手动学习及记忆转基础复用统一管理。原数组不改，曲线重建与学习前读取使用同一完整基线；转存读取实际样条节点，不缩成四点或拟合回原节点。
- 使用独立 `framework_brightness` 契约，普通手动上限仍作为 100% 标尺；没有物理标定时不将比例值冒充 nit。传感器、节点、户外及 Root 等能力继续分别检测。
- 保留全部 Refactor、系数、传统物理映射与端点裁剪路线、用户原设置及系统保护，不新增进程、巡检或传感器采样。

## 验证范围

Beta 02 的实际配置应用和原生学习已有本次用户分析包确认。Beta 03 完成生产代码主机回归、实际节点报告回放、同一私有固件的原生 HBM 空配置判断及 Simple 108 节点核对，旧兼容、保存设置、原签名和既有交付保持。

Beta 03 尚无本设备 Android/ART 安装后的实际户外效果、长测、物理测光或功耗结论。没有 nit 标定的设备仍不显示估算 nit；显示节点数值或明确标注系统比例。
