# HyperLux 2.0.3 · 正式版

版本代码 **20003**，构建 **release-2.0.3-r1**。适配 HyperOS 4，需要 Root 与 LSPosed。保持「系统框架 / Android 系统」作用域，可覆盖同签名旧版本，**更新后重启一次**。

## 界面整理

- **状态页边距统一**：当前曲线卡片内，曲线/输出/HDR 分支入口的下边距由 6dp 增加到 12dp，与左右一致。同步调整图表可用高度，避免入口挤压或覆盖曲线；仍是一页完整流程，无外层滚动。
- **设置按控制逻辑排序**：顶部保留保存与停用，依次为「亮度与偏好」「环境变化与过渡」「场景与保护」「运行状态与界面」。曲线和记忆相邻；阈值 → 主确认 → 辅助确认 → 暗光稳定 → 动画连续排列；触摸保护、手动阳光屏和温控集中在后面；生效计数与界面刷新置底。高级参数按需展开，主确认与暗光稳定为独立卡片。
- 新分组、参数和提示继续支持中英双语，跟随系统。

## 新增 14 个可调数值参数

五组独立开关，**默认均关闭**，升级不擅自开启。接口不兼容时禁用对应选项，关闭后保留系统行为。

| 组 | 参数与范围 |
| --- | --- |
| 变化阈值 | 普通变亮、变暗、微小变亮倍率各 0.5～3×；最小亮/暗照度差各 0～10 lux；适用照度上限 10～2000 lux |
| 辅助光感确认 | 辅助变亮、变暗、微小变亮确认各 0.5～4 秒 |
| 过渡动画 | 自动亮度新过渡的亮/暗时长倍率各 0.5～3× |
| 手动模式阳光屏 | 进入确认 1～8 秒、退出确认 0.5～8 秒 |
| 触摸遮挡保护 | 手指移开后等待 0～5 秒，整数秒；手指仍在检测区域时保留保护 |

倍率越大，阈值越不敏感、动画时长越长，建议先小幅调整。动画保留系统感知亮度坐标，不是物理 nit 或背光代码的线性速度。手动阳光屏确认不是自动 HBM 冷却时间，不强制增强，也不修改 HBM 预算。

阈值、辅助确认和触摸调整核对主屏、自动亮度、有效照度、屏幕、HDR、闲置和驾驶条件。动画另避开最近手动操作并核对输出策略。保留曲线编辑、预设、系统手动记忆、显示层温控与原有响应设置。

## 修正与可观测性

- **期限匹配历史窗口**：按实际历史窗口、系统附加等待和调度余量限制新增主确认时间。暗光稳定越窗时允许在窗口内增加部分等待，保留系统已有更长策略。显示最近实际采用的主基础确认时间及窗口限制次数。
- **变暗阈值边界**：新倍率导致正照度下暗阈值归零时保留极小正值，让真实零照度能越过严格小于判据，不改传感器输入。
- **参数与恢复**：新增类型/范围和兼容条件双重校验；更新不相关设置保留手动锚点。停用、错误回退与用户切换撤销高级改写并刷新缓存；触摸查询异常也恢复临时字段。
- **接入与效率**：控制器未就绪时最多三次接入尝试，避免一次早期失败永久失去连接；复用反射缓存，不增加亮度输出进程或额外光感订阅。
- **亮度分支**：增加触摸、距离、夜间唤醒/驾驶、反射、运动、辅助重置、手动阳光屏、HBM 时间/照度/省电及 HDR/杜比条件。缺失字段表示未取得，计数是本次系统进程累计。
- **Settings 导出**：修复 `settings get system` 的 `Failed transaction` 导致三项亮度设置没有读数。复用已有 SettingsProvider 直接读取主用户 0，保留原始值，新增 `settings/system.json`；零值、未设置、读取错误与预算跳过分别记录，单项失败不阻止其他项。此修正不修改任何系统设置，仍需实机重新导出确认。
- **分析包**：增加 180 秒总体采集预算，记录跳过、超时和截断，保留 ZIP 校验及八步进度。仍保存到内部存储根目录，不自动上传。

## 验证与升级

通过 **868 项主机逻辑、49 项名单/采集、115 项可选 Hook 回调模型、78 项新增固件静态检查**，以及原有消费链核对、编译、签名、对齐和归档校验。固件检查覆盖提供的两份 HyperOS 4 资料，不等于所有固件或 ART Hook 实机验证；布局与新增参数仍欢迎反馈，不承诺消除所有亮度起伏。

`HyperLux-2.0.3.apk` 沿用包名、图标及签名，版本代码与 2.0.3-test01 相同，支持同签名覆盖。测试版允许提示同版本正式 Release；正式版不反复提示自身。
