# HyperLux 4.6.0-beta03

本地测试版，累计基线为4.6.0正式版，包含 Beta01、Beta02 与本次工作目录修复。

## 简略更新

- Beta03：修复首选 Root 工作目录不可信时主屏原生守护无法启动的问题；原生程序、锁文件、权限恢复记录、日志与户外节点守护统一跟随同一个已核验目录。
- Beta03：保留原有父目录/属主/权限/真实路径校验，不通过放宽权限或删除检查来放行；两个目录都不可用时明确失败，不迁移用户设置。
- Beta02：应用窗口亮度保持交接；Beta01：缺失流式距离输入的无效等待修复。

## 详细更新

分析包显示 Root 授权与节点读取均正常，失败发生在 `NativePanelRoot.install()` 的 `RootWorkspace.requireNative()`：原生守护只接受 `/data/adb/luma_curve_refactor_test`，该目录的父目录 `/data/adb` 在一次属性变化后不再满足「root 所有且组/其他不可写」，于是手动面板失败，其余 Root 功能已回退到 `/data/local/.hyperlux-root-0` 而未受影响。同一设备 2026-11-01、11-03 的分析包中该目录可通过校验，最后一次成功守护为 raw11，说明是设备侧目录属性变化，不是曲线或节点接口问题。

本次把目录选择收敛到 `RootWorkspace`：`requireNative()` 依次核验首选与备用目录，返回通过同一 `secure()` 的路径；`NativePanelRoot` 以该路径安装程序、写日志并作为 `--workspace=` 传给原生程序；原生 `private_directory(path)` 复核父目录属主与权限、真实路径、目录属主及打开对象，并把 `main-panel.lock`、`main-panel-permissions`、`outdoor-node-health.json`、户外节点锁和日志全部派生自同一路径。STATUS 响应新增 `workspace`，Java 要求运行中的守护与本次选择一致；无 `workspace` 字段的旧守护仍按同节点兼容复用，旧版本程序用 `--version` 握手识别后按旧固定目录恢复，不猜测新参数。

未放宽任何一项检查：父目录仍须为 root 所有且组/其他不可写；候选目录仍须非链接、属主为 root、规范路径一致，并由原生以 `O_NOFOLLOW` 打开后复核 dev/inode。新增的只有「同一套规则下允许第二个目录」和「路径由 Java 传入后原生独立复验」。

回归覆盖首选目录可用、父目录拒绝后备用目录可用、两个目录都失败、备用目录父目录被改写/属主错误/别名、非法 `--workspace` 名称、守护异常退出后的恢复、旧版固定目录残留恢复，以及原生安装器的临时文件、恢复失败回滚和同一载荷快速路径。真机尚未回访；实际 HyperOS/KernelSU 目录属性与主屏接管效果仍需新包验证。
