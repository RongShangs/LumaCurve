# HyperLux 2.3.0-test01 测试说明

本版仅本地构建，尚未推送 GitHub、发布 Release 或更新官网。包名与签名沿用正式版，版本代码 23000。

## 设置整理

设置首页按「亮度与偏好」「响应与保护」「运行与诊断」分组，保留独立子页面。普通暗光稳定、暗光小变化阈值、辅助参考闸门和新增暗光定时锁定集中到「暗光稳定与锁定」。主屏手动亮度与户外增强分开：前者是用户明确操作的手动选择，后者仍是自动亮度策略。主要开关与预设优先展示，细节参数保持默认折叠。

## 暗光定时锁定

默认关闭。默认参数是进入 5 lux、持续 5 分钟、退出 30 lux、退出确认 5 秒：

- 进入照度可设 1～30 lux，等待时间 1～30 分钟。
- 退出照度可设 5～500 lux，且至少高于进入照度 5 lux；退出确认 1～30 秒。
- 本机存在辅助光感时，需要主辅双方持续处于进入照度以内，原生自动亮度输入也必须已完成有效采样。任意一侧持续达到退出照度即可恢复自动亮度。只有主光感的设备使用主光感。
- 独立读取系统实际选用的传感器，沿用其 FOV 倍率；不改变原生融合滤波输入。ON_CHANGE 传感器在持续订阅期间不把「没有新变化」误判为失效；连续传感器检查事件新鲜度。
- 进入时只设定一次当前实际亮度，不循环写值。锁定后以低频监听保持照度判断，无唤醒锁，熄屏即撤销监听。
- 锁屏、进入不适用场景、传感器失效、关闭功能或停用引擎，退出本功能持有的锁定并恢复自动亮度。
- 用户重新开启自动亮度，立即结束锁定；重新进入暗光后须重新等待完整分钟数。用户主动关闭自动亮度时不启动倒计时。锁定时用户另选亮度，则退让并保留用户手动模式。
- 系统进程重启后，读取本功能的接管记录，仅恢复暗光锁定曾关闭的自动亮度。主屏手动面板记录不触发自动恢复。

这里的「锁定」停止环境光引起的自动调节，仍尊重系统温控、HDR、应用指定亮度和驱动约束，不保证所有场景物理亮度绝对不变。

## 主屏手动亮度与磁贴

「主屏手动亮度」子页面可打开面板，也可请求添加控制中心磁贴；管理器没有显示添加请求时，在控制中心编辑磁贴列表，选择 HyperLux 的「主屏亮度」。

- 仅控制 display 0 主屏，不操作副屏，不改写背光节点权限。
- 使用系统显示框架允许的浮点亮度范围，滑条完整映射当前允许的最小值与最大值；支持直接输入同坐标亮度值，保留足够小的步长。
- 拖动或应用数值时关闭自动亮度；关闭面板后保留该手动选择。
- 用户开启系统自动亮度时，结束面板写入会话并丢弃旧请求；此后要再次主动操作面板才会重新进入手动模式。
- 模式接管只存在于显式面板会话，应用退到后台时关闭面板；没有额外常驻写入进程。
- 动态范围以本机当前报告为准；100% 是当时允许的上限，温控、HBM 预算、HDR 和驱动仍可能限制实际输出。此功能不保证绕过系统或硬件限制。

## 安装与实机检查

1. 覆盖安装测试 APK，确认 LSPosed「系统框架 / Android 系统」作用域，然后重启一次。进入应用，检查 Root、Hook 连接及当前构建，再保存并应用。
2. 新功能未开启时，先确认原有自动亮度和配置保持正常。
3. 打开「主屏手动亮度」面板，测试低、中、高亮度、直接输入值。调节应转为手动，开启系统自动亮度后面板立即退让；关闭面板应保留用户的手动选择。
4. 添加「主屏亮度」磁贴，检查可直接打开同一面板。打开面板并退到后台，确认不会残留写入会话。
5. 暗光锁定先将等待设为 1 分钟，保持主辅都低于进入值。状态页应从监听、倒计时进入「暗光保持」，系统自动亮度关闭。注意应用指定亮度或温控仍可改变输出。
6. 保持光线短暂变化后返回暗处，不能误恢复；任一侧持续亮过退出值并达到确认秒数后，应恢复自动亮度。
7. 暗光保持中锁屏再解锁，应恢复自动亮度并重新计时。另测用户原本手动模式：暗处等待、锁屏再解锁，都不应被本功能改成自动。
8. 暗光保持中主动开启自动亮度、修改手动亮度、关闭功能或停用引擎，检查各自退让行为。异常时导出分析包，附复现步骤。

建议确认短时测试后，将等待恢复为适合自己的分钟数。界面中的独立监听照度和原生融合照度用途不同，导出的状态会保留两者以便定位。

## 本地验证范围

直接编译生产控制器和生产模式策略，配合主机 Android 服务替身验证状态机、计时、双侧输入、旧请求、模式优先级、锁屏恢复、接口失效与系统范围限制；同时执行已有曲线、记忆、诊断、配置迁移、传统后端、户外和固件检查。APK 校验签名及对齐。以上均不能替代真实 Android/ART 服务与长期体验验证。

新增能力复用 system_server 内的现有 LSPosed Hook，不需要新增 C 常驻进程。没有额外唤醒锁，但开启暗光锁定后的传感器监听和事件处理并非零成本，需要后续实测。

恢复：应用内「停用并恢复」，或解压完整包，在 Root 终端运行 `sh ./restore_refactor_hook_android.sh`。禁用 LSPosed 后直接重启同样停止 Hook；如暗光接管记录仍存在，可用恢复工具恢复原自动模式。
