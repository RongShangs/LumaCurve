# HyperLux 4.5.0-beta19

本地测试版，基于Beta18，未公开发布。

## 本版简略更新

- 新增“隔离挂起小窗亮度”独立开关，默认关闭：正常视频小窗保留临时亮度，最小浮窗或贴边挂起时交回系统判断。
- 修复应用独立亮度从小窗重新最大化后不重新进入的问题，无需关闭应用再从桌面打开。
- 修复模块恢复自动亮度的延迟通知被误判为用户主动操作；保留用户控制中心调整优先。

## 自4.5.0正式版以来的累计简略更新

- Beta01：增加放宽画面限亮后的可选高亮上限曲线。
- Beta02—03：重做高亮设置与拖动曲线，增加短时主动激发测试。
- Beta10：恢复Beta03独立曲线布局，合并曲线研究另存弃用分支。
- Beta11—12：增加物理nit目标曲线，四点拖动、图例和恢复默认；保留旧配置及路线。
- Beta13—15：完善测试参数和图形范围，拆出详情页，统一整块点击反馈。
- Beta16—18：重排高亮增强主页及详情，统一触发门槛、最高亮度限制名称，完善状态参数。

## 本版详细更新

应用临时亮度隔离页新增“隔离挂起小窗亮度”，与原来的窗口亮度同步隔离分开，旧配置不自动开启。按实际窗口门禁和原生最小/贴边状态筛除窗口亮度候选，不按焦点或窗口面积猜测；正常小窗、其他有效窗口及系统原有拒绝规则保留。模式变化、启停时触发一次合并窗口重评估，不记忆或重放临时亮度，不直接修改窗口属性或系统亮度。

应用独立亮度增加任务窗口模式事件：小窗退出，全屏最大化后重新按名单判断；完整模式接口缺失时保留原有焦点路线。模块自己的模式写入通知单独识别，避免退出接管时的延迟回调将应用误加入“用户主动恢复自动亮度”的豁免名单。用户真正开启自动亮度和原控制中心操作仍优先。

保留原名单、分组、记忆、曲线、原签名及节点恢复。相关主机、固件和负向检查已执行；具体机型的小窗手势、动画及实际亮度效果仍待真机回访。此前详情见对应Beta文件。
