# HyperLux 2.1.1-test01

本地修复测试版，构建标识 `20261004-status-test01`，尚未推送或替换正式 2.1.0。

用户分析包记录了 SettingsProvider 拒绝状态字符串超过 32768 的错误。实时状态最后成功更新于约 03:00，10:46 保存时 Hook 实际处理新设置，但确认仍读取旧状态，六秒后应用发起回退。

修复：

- 将实时状态和运行记录、计算追踪、输出追踪、户外限制追踪及完整曲线数组分开存储，按长度拆分。每个值限制在 30000 字符及 UTF-8 字节以内。
- 分片带快照标识，完整发布后才写主状态。并发读取时不拼接不同快照的数据；缺失记录有明确标记。保留既有历史容量，不通过清空记录绕过限制。
- 保存、停用及清除记忆使用独立确认字段，仍核验构建、进程身份、固件与提交标识，不依赖完整诊断状态能否写入。
- 等待确认期间发送有限的刷新请求；显示线程只重读未处理配置，重复通知不重建手动锚点。
- 保存失败后核对此前配置是否恢复；失败原因使用完整弹窗展示，可直接导出分析包。分析包附带确认信息与最近提交失败原因。

验证包含超长状态拒绝及拆分后完整往返、多字节字符和 JSON 转义、并发/缺失分片、旧快照、独立确认、错误确认和恢复/停用确认。测试使用主机服务替身，未连接实机。

安装：覆盖安装 APK，确认 LSPosed 仍勾选系统框架，重启一次以加载新 Hook。随后修改一个设置并保存，确认提示成功、状态持续刷新，必要时导出分析包。
