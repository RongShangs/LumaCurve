# HyperLux 4.3.3 Beta 07

累计基线：上一个已公开正式版 **4.3.3 / 43300**。本包 **4.3.3-beta07 / 43307**，包含 Beta 01—07，按版本分段。仅本地打包，不发布。

## 简要更新

1. 修复部分设备分区亮度条在普通区间调节后，稍后显示位置偏低的问题。
2. 新增“应用亮度隔离”，减少应用临时调亮对系统亮度偏好和手动记忆的干扰；入口位于“暂停自动亮度名单”上方，默认关闭。
3. 基础曲线节点统一按0—100%显示和输入，与曲线纵轴一致；深色模式、最低点和拖动提示同步调整。
4. 修复部分设备使用分区节点控制时，普通区间内手动调亮、绿色记忆曲线提前到顶的问题。
5. 修复进入场景设置时误弹系统界面作用域提醒。
6. 放开基础曲线编辑范围，按设备实际亮度上下限调整，相邻节点按需联动；深色模式同样适用。
7. 修复更新弹窗底部按钮显示不完整，改善短屏、横屏和大字体布局。
8. 关于页代码贡献新增简约，提供作者主页及参考项目链接。

## 4.3.0 详细更新（保留大版本内容）

以下为4.3.0发布时的记录；4.3.1对主题记忆、最高点编辑及亮度显示的改进见末尾追加部分。


相较上一公开正式版 **4.2.0 / 42000（release-4.2.0）**，累计合入 Beta 01—09 的最终功能和修复，以下按当前实际行为整理。

### 控制中心完整节点控制

- 在“主屏手动亮度”页面提供独立的控制中心映射设置，可选择关闭、完整节点控制或分区节点控制，默认关闭；旧版隐藏比例映射及已保存选择保留，不在覆盖更新时自动改成节点写入。
- 完整模式下，滑条按当前主屏真实背光节点比例显示，拉满对应设备读取到的 max_brightness。不同设备使用自己的上限，不写死16383、4095或其他节点值。
- 手动拖动后关闭自动亮度、放开暗光锁定并保持节点，不参与手动记忆；重新打开自动亮度结束保持。锁屏暂停、解锁恢复，物理屏或控制权变化按原处理。
- 与主屏亮度面板共用原生保持程序、租约和异常恢复，不另建一套节点写入服务；只在明确启用且接口、节点权限及监听连接均可用时接入。Root暂缺只影响对应路径，不重置其他设置。

### 分区节点控制与操作示意

- 滑条下方75%为普通区间，上方25%为增强区间。普通上限读取原机HBM过渡点，或经验证的普通亮度上限，再按本机标定换算；75%只是显示比例，不是硬件节点比例。
- 普通区间沿用系统调节，自动亮度开启时继续参与手动记忆。首次向上拖到普通上限时，当前滑块同步停在边界；松手后3秒内快速再次上滑，才进入增强区。
- 增强区按普通节点上界至用户设置的最高节点均匀分配。最高节点默认使用设备真实上限，也可通过滑条或数值输入调整；此值只约束手动增强目标，不限制系统自动阳光屏。
- 进入增强区后关闭自动亮度、放开暗光锁定并使用共用节点保持，不学习高节点值。返回普通区间时可选择“恢复自动亮度”或“继续保持手动”，默认恢复自动亮度。
- 自动阳光屏可正常将滑块显示在增强区，不需要二次确认，也不会仅因显示位置而关闭自动亮度。若系统输出超过用户所选上界，滑块显示到顶，不反过来压低系统输出。
- 已处于自动增强区时，从该处开始的新拖动在当前实际高亮再次核验后直接接管，避免先跳回75%。旧反馈、当前已退出高亮、HDR、严重温控或熄屏等情况不凭旧显示放行。
- 设置内提供首笔封顶、松手、快速再次上滑、返回及自动高亮的动画。手指为主题内固定色实心圆，动画不显示计时数字；离页、隐藏或暂停时停止。所有编辑仍由顶部“保存并应用”提交。

### 控制中心换算兼容与使用范围

- 保留原全区间可反解路线；追加经实际标定表、原生双向换算及端点行为核对的有效域路线，改善正常最低亮度平台被误判为不兼容的问题。Refactor逻辑换算独立核验，未知中间平台或错误标定仍拒绝。
- SystemUI输入与反馈分开处理，原软件坐标路线保留，用户手势才请求节点接管。请求核验当前用户、配置、系统进程、物理屏、实际上限及自动亮度开关代次，拒绝过期排队操作。
- 需要Root节点写入权限及LSPosed“系统界面”作用域。安装或更新后重启，再打开一次APP连接节点控制。原“系统框架 / Android 系统”作用域继续保留。
- 功能以设备实际自检为准。未知动态折叠监听布局暂不强行启用新控制中心节点路径，原有折叠屏手动面板与其他兼容功能保留。节点值、系统换算nit和屏幕实测亮度不是同一概念。

### 深色模式独立基础曲线

- 在亮度曲线设置中新增独立开关，默认关闭。启用后可分别编辑普通基础曲线与深色模式基础曲线，状态页按正在使用的曲线显示名称和跳转。
- 首次启用从普通基础草稿起步，之后两条曲线独立保存；关闭开关仍保留深色曲线。同设备配置导入导出保留双曲线，设备基准不一致时保留本机数据。
- 每次实际切换深浅色模式会清除当前、已保存和待恢复的手动记忆，包括永久保持的记忆，避免旧主题偏好被带入新主题。设置处保留提示，两条基础曲线不被清除。
- 将绿色曲线保存为基础曲线时，只修改当前主题对应的那一条；转存期间主题变化时拒绝旧图写入。复用系统主题事件，不新增主题轮询或传感器采样。

### 恢复系统默认

- 设置首页“停用并恢复”改为“恢复系统默认”。确认后撤销基础曲线、暗光锁定、户外增强、温控调整和应用暂停等亮度定制，并清除手动记忆。
- 等待引擎确认后再清理本地亮度草稿，未确认不假报成功。自定义预设、界面偏好、桌面图标状态及教程记录保留；不重新启动此前停用的其他亮度模块。

### 部分平板的传统亮度曲线
